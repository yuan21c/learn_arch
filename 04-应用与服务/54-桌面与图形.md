# 第 54 章 桌面与图形

前六章都在命令行里。这一章讲图形栈：从内核的显示驱动到窗口系统，再到桌面环境。**全部内容标注 `环境：VM`**——WSL 没有可用的本地图形栈（WSLg 是 Windows 侧的窗口转发，不是 Arch 的桌面），显卡直通与性能表现也只有在真机上才有意义。

> 本章目标：能说清「内核 DRM/KMS → 显示服务器 → 窗口管理器/桌面环境」的三层结构；能区分 X11 与 Wayland 的架构差异与各自的兼容性问题；能在虚拟机里装好一个最小图形环境并排障（黑屏、无信号、登录循环）；知道显卡驱动的三种选择（开源、专有、混合显卡）以及虚拟机里该用哪一类。
> 对应 Wiki：[Xorg](https://wiki.archlinux.org/title/Xorg)、[Wayland](https://wiki.archlinux.org/title/Wayland)、[Desktop environment](https://wiki.archlinux.org/title/Desktop_environment)

## 图形栈的三层

```text
应用 → 工具包（GTK/Qt）→ 显示服务器（X11 或 Wayland）→ 合成器 → 内核 DRM/KMS → 显卡驱动 → 显示输出
```

三个概念必须先分清：

- **DRM/KMS**：内核里的显示子系统，负责设置分辨率、模式、扫描输出；驱动（`i915`、`amdgpu`、`nouveau`、`virtio-gpu`）都挂在这里。
- **显示服务器**：X11 是一套独立服务（`Xorg`），应用通过 X 协议连它；Wayland 是协议，合成器（`sway`、`KWin`、`GNOME Shell`）同时充当服务器。
- **桌面环境**：窗口管理 + 面板 + 设置 + 文件管理器 + 一套应用（GNOME、KDE Plasma、Xfce）。

理解这三层，才能判断「黑屏」是哪一层的问题：内核日志有输出说明 DRM 起来了；能看到登录界面说明显示服务器起来了；登录后回到登录界面，通常是桌面环境的会话或驱动问题。

## X11 与 Wayland

| 维度 | X11 | Wayland |
| --- | --- | --- |
| 架构 | 独立服务 + 客户端 | 合成器即服务器，协议直连 |
| 输入与显示 | 全局抓取容易（也意味着不安全） | 按窗口隔离，抓屏需授权 |
| 混成与撕裂 | 需合成器（如 `picom`） | 合成是协议的一部分 |
| 兼容性 | 几乎所有老程序 | XWayland 兜底，个别程序仍异常 |
| 多屏/缩放 | 配置繁琐 | 按输出独立缩放，体验更好 |
| 远程/串流 | 成熟（`x11vnc` 等） | 方案较新，支持参差 |

结论：新装环境优先 Wayland；需要特定老软件、远程桌面或输入法兼容性时，X11 仍是稳妥选择。两者在 Arch 上可以共存（登录界面里选会话），不必二选一装系统。

## 最小图形环境（VM）

先只装 Xorg 与一个轻量窗口管理器，把链路跑通，再上桌面环境（环境：VM）：

```bash
sudo pacman -S xorg-server xorg-xinit xterm
sudo pacman -S xf86-video-vmware      # 或 xf86-video-qxl / virtio-gpu 用 modesetting
startx
```

`xorg-xinit` 提供 `startx`，它读 `~/.xinitrc`；没有这个文件时用系统默认的 `xinitrc`（启动一个 `xterm`）。虚拟机里通常不需要专有驱动：`modesetting` 驱动配合 `virtio-gpu`/`qxl` 即可，性能足够跑桌面、不足跑 3D 游戏。

确认驱动走的是哪条路：

```bash
lspci -k | grep -A3 -E 'VGA|3D'     # 看设备与内核在用哪个驱动
sudo journalctl -b -k | grep -Ei 'drm|kms'
glxinfo | grep 'OpenGL renderer'    # 需要 mesa-utils
```

看到 `llvmpipe` 说明在用**软件渲染**——能跑，但慢；看到 `virgl` 或真实 GPU 名字才算硬件加速。

## 桌面环境与显示管理器

- **桌面环境**：`gnome`、`plasma-meta`（KDE）、`xfce4`。功能与资源占用递减。
- **显示管理器（DM）**：登录界面与图形会话启动器，`gdm`（GNOME）、`sddm`（KDE/通用）、`lightdm`（轻量）。也可以不用 DM，用 `startx` 或 `exec dbus-run-session -- gnome-session` 手动启动。

```bash
sudo systemctl enable --now gdm     # 装好后重启进入图形登录
```

`enable` 一个 DM 后，系统默认从 `graphical.target` 启动。想回到纯命令行（排障时常用）：`systemctl isolate multi-user.target`，或从引导菜单里加 `systemd.unit=multi-user.target`（第 16、41 章）。

虚拟机里的推荐路径：先用 `startx` + 轻量 WM 验证链路，再装桌面环境；不要一上来就装完整 GNOME——一旦黑屏，你很难判断是驱动、DM 还是会话的问题。

## 显卡驱动：三种选择

| 场景 | 驱动 | 说明 |
| --- | --- | --- |
| Intel 核显 | `mesa`（内置 `i915`/`xe`） | 免配置，Wayland 支持好 |
| AMD | `mesa` + `vulkan-radeon` | 开源栈成熟 |
| NVIDIA | `nvidia`（专有）或 `nouveau`（开源） | 专有性能好、与 Wayland 的历史包袱多；`nvidia-dkms` 配合 `linux-headers` |
| 虚拟机 | `mesa` + `modesetting`/`virtio-gpu` | 不要装厂商专有驱动 |

混合显卡（笔记本双显卡）用 `optimus` 方案或 `prime-run` 按程序切换；这是真机话题，虚拟机里不涉及。

## 黑屏与登录循环的排查

| 现象 | 先查 |
| --- | --- |
| 引导后完全黑屏、无光标 | 内核参数加 `nomodeset` 试进；看 `journalctl -b -k` 的 DRM 报错 |
| 有登录界面，登录后黑屏回登录 | 会话配置/桌面环境依赖缺失；换 `startx` 手工启动看终端报错 |
| 分辨率不对、只有低分辨率 | 驱动未加载（在用 `llvmpipe`）；检查 `lspci -k` 与 `journalctl -k` |
| 花屏、随机闪烁 | 驱动/固件问题；虚拟机换显示设备（qxl/virtio/vmware）对比 |
| 鼠标键盘无响应 | 输入驱动与 `/dev/input` 权限；Wayland 下看合成器日志 |

X11 的日志在 `/var/log/Xorg.0.log`（或 `~/.local/share/xorg/`），Wayland 各合成器的日志进 journal。**先看日志再改配置**，图形问题最忌凭猜测反复重启。

## 小结

- 三层结构：DRM/KMS（内核）→ 显示服务器/合成器 → 桌面环境；判断故障先定位层。
- X11 独立服务、兼容性好；Wayland 合成器即服务器、隔离与缩放更好；两者可共存。
- 虚拟机里用 `mesa` + `modesetting`/`virtio-gpu`，看到 `llvmpipe` 就是软件渲染。
- 先 `startx` + 轻量 WM 验证链路，再装桌面环境与 DM。
- 驱动按硬件选：Intel/AMD 用 `mesa`，NVIDIA 专有或 `nouveau`，虚拟机不用专有驱动。
- 黑屏先 `nomodeset` + 看 `journalctl -k`/`Xorg.0.log`，不要盲改配置。

## 练习

1. 三层辨认（环境：VM）：装好最小 X 环境后，分别用 `journalctl -b -k | grep -i drm`、`ps aux | grep -E 'Xorg|wayland'`、`echo $XDG_SESSION_TYPE` 找出三层各自的证据。
2. X11 与 Wayland（环境：VM）：装一个 Wayland 合成器（如 `sway`）与 Xorg，在登录界面切换会话各进一次，记录 `echo $XDG_SESSION_TYPE` 与常用程序的表现差异。
3. 渲染路径（环境：VM）：`glxinfo | grep 'OpenGL renderer'`，判断是软件还是硬件渲染；再切换到另一种虚拟显示设备，对比结果。
4. 无 DM 启动（环境：VM）：不启用任何 DM，用 `startx` + `~/.xinitrc` 启动一个 WM，验证 `graphical.target` 与手工启动的差别。
5. 黑屏排查（环境：VM）：故意把 `~/.xinitrc` 写错一行，重现「启动后立刻回命令行」，从终端输出与 `Xorg.0.log` 找出错误行。
6. 驱动核对（环境：VM）：`lspci -k | grep -A3 VGA` 与 `lsmod | grep -E 'virtio|qxl|vmwgfx|i915|amdgpu'`，说明当前虚拟机用的是哪条驱动路径。
