这一章是「桌面日常」的合并章：音频、打印、电源、输入法、蓝牙。它们在 Wiki 上各有一整套页面，但使用频率不高、彼此又常一起出现（装了桌面就会遇到），所以按**精讲 + 索引**处理：给出能跑通的最小配置和排障入口，细节交给 Wiki。

## 音频：PipeWire

PipeWire 是当前桌面环境普遍采用的 Arch 音频栈，兼容 PulseAudio 与 JACK 的客户端；**最小系统不会自带**，要手动安装（环境：VM/真机桌面；WSL 无本地音频设备）：

```bash
sudo pacman -S pipewire pipewire-pulse pipewire-alsa wireplumber
systemctl --user enable --now pipewire pipewire-pulse wireplumber
wpctl status
```

三个组件分工：`pipewire` 是服务本体，`pipewire-pulse` 提供 PulseAudio 兼容接口（老程序照常能用），`wireplumber` 是会话/策略管理器（决定设备优先级、路由）。**它们是用户级服务**（`--user`），不是系统级。

排障入口：`pavucontrol`（图形路由面板）看每个应用的声音路由；`wpctl status` 看设备与默认节点；没有声音时先确认「设备被识别」（`aplay -l`，来自 `alsa-utils`）再确认「默认输出节点正确」。

视频播放与硬件解码：`ffmpeg` 提供基础编解码，`gst-plugins-*` 供 GStreamer 应用使用；VA-API 硬件解码按显卡选 `intel-media-driver`、`libva-mesa-driver`，用 `vainfo` 验证。

## 打印：CUPS

（环境：VM/真机，需要实际或虚拟打印机）

```bash
sudo pacman -S cups
sudo systemctl enable --now cups.socket
```

注意是 **`cups.socket`** 而不是 `cups.service`：CUPS 用 socket 激活，只在有打印请求时才启动服务，省资源。管理界面在 `http://localhost:631`，命令行等价：

```bash
lpstat -p -d                       # 打印机列表与默认打印机
lpadmin -p myprinter -E -v ipp://打印机地址/ipp/print -m everywhere
lp -d myprinter /etc/hostname      # 打印一个测试文件
```

`-m everywhere` 走 **IPP Everywhere（无驱动打印）**：现代网络打印机都支持，不需要装厂商驱动。老打印机才需要 `foomatic`/厂商 PPD——这也是「Linux 打印难」这一旧印象的主要来源，新设备基本没有了。

常见故障：`lpstat` 里打印机状态 `disabled`（用 `cupsenable` 恢复）；任务卡住（`cancel -a`）；找不到设备（先用 `ippfind` 或打印机 IP 的 Web 界面确认可达）。

## 电源：挂起、休眠与合盖

三种状态差别很大：

| 状态                | 内存             | 磁盘 | 恢复速度 | 前提                                   |
| ------------------- | ---------------- | ---- | -------- | -------------------------------------- |
| 挂起（suspend，S3） | 保持供电         | 不写 | 秒级     | 驱动支持                               |
| 休眠（hibernate）   | 写入 swap 后断电 | 需要 | 十秒级   | **swap ≥ 内存**，且内核参数指定 resume |
| 混合睡眠            | 两者都做         | 需要 | 秒级     | 同休眠                                 |

```bash
systemctl suspend
systemctl hibernate        # 没配好 swap 会直接失败
```

休眠的三个细节别漏：initramfs 用 systemd hook 时自带 resume 机制，busybox hook 才必须显式加 `resume=`；**swapfile 还需要 `resume_offset=`**（`filefrag -v` 查偏移，第 17 章）；UEFI 机器上 systemd 可能通过 `HibernateLocation` 自动定位，改了 swap 布局要同步。另外 `linux-hardened` 内核不支持休眠。

合盖、电源键的行为由 **logind** 决定，配置在 `/etc/systemd/logind.conf`：

```text
HandleLidSwitch=suspend
HandleLidSwitchExternalPower=suspend
HandleLidSwitchDocked=ignore
```

改完 `systemctl restart systemd-logind`（会短暂影响会话）。笔记本上还有一个二选一：`power-profiles-daemon`（桌面环境集成、切换性能/平衡/省电）或 `tlp`（细粒度、偏命令行）——**不要同时装**，两者会互相覆盖策略。

## 输入法：Fcitx5

（环境：VM/真机桌面）

```bash
sudo pacman -S fcitx5 fcitx5-chinese-addons fcitx5-gtk fcitx5-qt
```

环境变量是 X11 下的关键（写在 `~/.config/environment.d/fcitx.conf`，登录时由 systemd 读取）：

```text
GTK_IM_MODULE=fcitx
QT_IM_MODULE=fcitx
XMODIFIERS=@im=fcitx
```

自动启动：在桌面环境的「自启动」里加 `fcitx5 -d`，或建一个用户级 unit（第 46 章）。图形配置工具是 `fcitx5-configtool`。Wayland 下按合成器分三种情况：GNOME 需要装输入法扩展；KDE 在系统设置里启用；走 XWayland 的老程序仍依赖上面三个 IM 变量——**遇到「候选框不跟随光标」先查该合成器的 Wiki 小节**。

排障顺序：`fcitx5-diagnose`（官方诊断脚本，会把环境变量、进程、DBus 状态一次列清）→ 检查环境变量是否在**会话内**生效（`echo $GTK_IM_MODULE`）→ 检查是否只有一个输入法框架在跑（IBus 与 Fcitx 冲突是常见原因）。

## 蓝牙

```bash
sudo pacman -S bluez bluez-utils
sudo systemctl enable --now bluetooth
bluetoothctl
```

交互式流程：`power on` → `agent on` → `default-agent` → `scan on` → `pair <MAC>` → `trust <MAC>` → `connect <MAC>`。设备被 `rfkill` 阻断时先 `rfkill list` 看清类型：**Soft blocked** 可用 `rfkill unblock bluetooth` 解除；**Hard blocked** 是物理开关/BIOS 关着，软件解不动，去查机身开关。

## 小结

- 音频：PipeWire + `pipewire-pulse` + `wireplumber`，三个都是**用户级**服务；`wpctl`/`pavucontrol` 是排障入口。
- 打印：启用 `cups.socket`（不是 `cups.service`），现代打印机用 `-m everywhere` 无驱动添加。
- 电源：挂起只保内存、休眠要 swap ≥ 内存；合盖策略在 `logind.conf`；`power-profiles-daemon` 与 `tlp` 二选一。
- 输入法：Fcitx5 + 三个环境变量（X11）；Wayland 依赖合成器的 `text-input` 支持；`fcitx5-diagnose` 先跑。
- 蓝牙：`bluez` + `bluetoothctl` 六步配对；`rfkill` 解阻断。
- 长尾主题只留索引，按需去 Wiki。

## 练习

1. 音频链路（环境：VM/真机）：装好 PipeWire 后 `wpctl status` 与 `aplay -l` 各看一次，播放一个 wav 文件；用 `pavucontrol` 把某应用切到另一个输出设备，说明「默认节点」与「应用路由」的区别。
2. 无驱动打印（环境：VM/真机）：用 `lpadmin -m everywhere` 添加一台 IPP 打印机（可先用 `ippfind` 找），`lpstat -p -d` 确认，打印一个文本文件；再故意 `cupsdisable` 一台打印机，观察任务卡住并恢复。
3. 挂起实测（环境：VM）：`systemctl suspend` 后恢复，检查 `journalctl -b | grep -i suspend` 的记录；再试 `systemctl hibernate`，说明为什么在 swap 不足时会失败。
4. 合盖策略（环境：真机笔记本）：读 `logind.conf` 的默认值，改成「接电源时 ignore、用电池时 suspend」，重启 logind 后验证。
5. 输入法（环境：VM/真机）：配好 Fcitx5 与环境变量，`fcitx5-diagnose` 保存输出，指出其中哪几项说明配置正确；在 X11 与 Wayland 会话下各测一次切换。
6. 蓝牙（环境：真机）：用 `bluetoothctl` 完成一次配对与连接，`rfkill list` 前后对比；断开后 `trust` 的作用是什么？
