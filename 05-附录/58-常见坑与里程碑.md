# 第 58 章 常见坑与里程碑

本章把全书反复强调的错误集中成一张对照表，再用按篇与主题分组的里程碑清单帮你判断学习进度。坑不是靠记住避免的，而是靠固定习惯避免；里程碑也不是装饰，每一项都应该能用命令或输出证明。

> 本章目标：能识别全书各篇的高频错误，并按篇与主题分组的清单自查是否真正走完了学习路径。
> 对应 Wiki：[System maintenance](https://wiki.archlinux.org/title/System_maintenance)｜[Installation guide](https://wiki.archlinux.org/title/Installation_guide)

## 58.1 常见坑

| 错误做法                               | 后果                                                                         | 正确做法                                                                                                                                       |
| -------------------------------------- | ---------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 执行 `pacman -Sy 包名`                 | 只同步数据库不升级系统，形成部分升级，库版本不匹配，程序随机崩溃             | 只用 `pacman -Syu` 完整升级，安装前先升级系统                                                                                                  |
| 长期以 root 登录操作                   | 权限模型失效，一条错误命令即可破坏系统，日志中的操作者也失去区分度           | 日常用普通用户，必要时 `sudo`，配置 `wheel` 组                                                                                                 |
| 一上手就装 AUR 助手                    | 跳过 PKGBUILD 与 makepkg，构建失败时无法排障，也无法判断脚本风险             | 先手动 `git clone` + `makepkg -si` 安装几个包，再考虑助手                                                                                      |
| 升级前不看 Arch News                   | 需要手动干预的更新被忽略，升级后服务或引导直接失败                           | 升级前浏览 [Arch News](https://archlinux.org/news/)，按提示操作                                                                                |
| 用 `--overwrite` 掩盖文件冲突          | 冲突被压下但根因仍在，后续升级冲突更多，文件归属混乱                         | 先查 `pacman -Qo` 找出文件归属，解决包冲突再升级                                                                                               |
| 随意添加第三方仓库                     | 包版本与官方仓库冲突，依赖解析被破坏，安全边界扩大                           | 只保留官方仓库；确需第三方时固定优先级并记录来源                                                                                               |
| 大改前不备份                           | WSL 导出成本极低却不用，出错后只能重装，数据无法恢复                         | 改动 pacman 配置、批量删包、折腾 AUR 前先 `wsl --export`                                                                                       |
| 把 WSL 行为当成 Arch 通用行为          | 微软内核、自动挂载、自动生成的 DNS 被误认为 Arch 设计，迁移到真机后判断错误  | 区分 WSL 特例与 Arch 通用机制，排障时先确认环境                                                                                                |
| 手动往 `/usr` 放文件                   | 包管理器不接管这些文件，升级或重装包时被覆盖或残留                           | 配置放 `/etc`，数据放 `/var` 或 `/home`，自建程序放 `/opt` 或 `/usr/local`                                                                     |
| 变量为空值时删错路径                   | `rm -rf $DIR/` 与 `rm -rf "$DIR"/` 在 `DIR` 为空时都指向 `/`，可能删到根目录 | 空值防护：用 `rm -rf -- "${DIR:?DIR is empty}/"`，或先判断 `[ -n "$DIR" ]`、为空则 `exit 1`；加引号不解决空值问题，`set -u` 只拦未定义不拦空值 |
| 直接 `kill -9` 停服务                  | 跳过清理，临时文件残留、锁不释放，下次启动可能失败                           | 先 `kill -TERM`（或 `systemctl stop`），等它自己收尾                                                                                           |
| 改完 fstab 不测试就重启                | 一行写错导致开机进 emergency mode，甚至无法进入系统                          | 改完先 `mount -a`，并保留 `.bak` 与一个可用的救援入口                                                                                          |
| 照抄过期博客或视频命令                 | 参数已变化、包已改名、仓库已迁移，命令失败甚至破坏系统                       | 以 Wiki 当前页面和 `man` 为准，执行前核对参数含义                                                                                              |
| 安装时忘记挂载 ESP 就装引导器          | `grub-install` 写入失败或固件找不到引导项，重启直接进固件界面                | 先 `findmnt /mnt/boot` 确认 ESP，再安装引导器                                                                                                  |
| 重复执行 `genfstab` 或分区前不确认设备 | fstab 出现重复条目导致 emergency mode；`mkfs` 写错磁盘直接丢数据             | fstab 只生成一次并人工检查；分区前用 `lsblk` 核对设备与容量                                                                                    |

这些坑有共同结构：跳过确认、跳过备份、跳过日志。把这三步固定成习惯，比记住具体命令更有效。

## 58.2 里程碑清单

### 第一篇 Linux 基础

- [ ] 能用 `find` + `grep` + 管道完成一次文件盘点
- [ ] 能解释 rwx、`umask`、SUID/SGID/Sticky 与 ACL 各自解决什么问题
- [ ] 能创建用户、加入组，并用 `sudo` 完成一次受控提权
- [ ] 能说清 `/etc`、`/usr`、`/var`、`/home` 的分工，以及 `PATH` 是怎么来的

### 第二篇 Linux 进阶

- [ ] 能读懂 `ps`/`top` 输出并定位一个吃 CPU 或卡在 I/O 的进程
- [ ] 能写出带 `set -euo pipefail` 与 `trap` 的脚本并解释每条的作用
- [ ] 能在虚拟机里完成分区 → 格式化 → 挂载 → 写 fstab 的完整流程
- [ ] 能按「链路 → 路由 → 连通 → 名称 → 端口 → 应用」六层排查网络故障
- [ ] `pvs`/`vgs`/`lvs` 能读出卷组与逻辑卷布局，`btrfs filesystem usage` 与 `zramctl` 输出正常

### 第三篇之一：定位与环境

- [ ] 能说出 Arch 与 Ubuntu/Fedora 在包管理、发布模型上的核心差异
- [ ] 能解释 WSL 版 Arch 缺少哪些能力，以及为什么安装要放到虚拟机
- [ ] 能独立完成一次系统更新，且不会触发部分升级
- [ ] 能读懂 `/etc/os-release`、`systemctl is-system-running` 的输出

### 第三篇之二：包管理

- [ ] 熟练使用 `-Qe`、`-Qm`、`-Qdt`、`-Qo`、`-Ql`、`-F`
- [ ] 能区分显式安装与依赖安装，并会用 `-D --asdeps/--asexplicit` 调整
- [ ] 能从 `/var/cache/pacman/pkg` 回滚一个包并恢复
- [ ] 能独立处理一次密钥环或签名错误
- [ ] 能解释 `-Rns` 与 `-Rs` 的差别，并在删除前检查依赖

### 第三篇之三：系统

- [ ] 能编写 service 与 timer，并用 `list-timers` 验证
- [ ] 能用 `systemctl status` 与 `journalctl -u` 定位 failed unit
- [ ] 能读懂 `systemd-analyze blame` 的输出并判断是否有异常

### 第三篇之四：构建

- [ ] 能写出包含 `pkgname`、`pkgver`、`source`、`sha256sums` 的 PKGBUILD
- [ ] 能不用助手从 AUR 安装一个包，并全程读过 PKGBUILD
- [ ] 能读懂 `makepkg` 的常见报错并定位到具体行
- [ ] 能用 `namcap` 检查 PKGBUILD 与构建产物
- [ ] 知道 AUR 与官方仓库的区别，以及构建脚本的风险边界

### 第三篇之五：维护

- [ ] 升级前会主动查看 Arch News
- [ ] 能独立处理密钥环、依赖损坏、磁盘空间不足三类问题
- [ ] 有稳定的备份与恢复流程，并实际演练过
- [ ] 能写出一份包含时间线、根因、修复步骤的故障复盘
- [ ] 能解释 pacnew 的处理原则，并实际合并过一次

### 第三篇之六：安装

- [ ] 能在虚拟机中独立完成一次 UEFI 安装并重启进入系统
- [ ] 能解释分区、`pacstrap`、`genfstab`、`arch-chroot` 各自的作用
- [ ] 能分别用 GRUB 与 systemd-boot 安装一次引导器
- [ ] 能解释 initramfs 的作用，并在需要时重新生成
- [ ] 知道如何用 Live ISO 挂载后 chroot 救援

### 第四篇 应用与服务

- [ ] `nginx -t` 输出 test is successful，`curl` 拿到的是自己的站点而不是默认页
- [ ] `sudo sshd -T` 能列出实际生效配置，防火墙放行端口与 `port` 一致
- [ ] `sudo mariadb -e 'SELECT 1'` 与 `sudo -u postgres psql -c 'SELECT 1'` 均返回结果，且备份实际恢复验证过一次
- [ ] `docker compose version` 可用，`docker ps` 里有正在跑的容器
- [ ] `sudo certbot renew --dry-run` 通过，`systemctl list-timers | grep -i certbot` 能看到下一次触发
- [ ] `apachectl configtest` 输出 Syntax OK 或 `caddy validate` 通过，`curl` 拿到的是自己的站点
- [ ] `sudo aa-status` 输出已加载 profile 数（或明确说明未启用）
- [ ] `wpctl status` 能列出音频节点（桌面环境）

### 附录

- [ ] 能用第 56 章速查表定位任意一条常用命令的出处
- [ ] 能用第 57 章索引为任一主题找到 Wiki 入口
- [ ] 动手前默认走「确认 → 备份 → 看日志」三步（58.1 节）

## 58.3 完成本书之后

| 方向       | 下一步                                                                                      | 入口                                                                                                   |
| ---------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 真机安装   | 先确认硬件兼容性、备份数据、准备 Live U 盘，再按第 43-45 章流程走一遍                       | [Installation guide](https://wiki.archlinux.org/title/Installation_guide)                              |
| 桌面环境   | 先选 Wayland 或 Xorg，再选桌面环境与显示管理器，最后处理显卡驱动                            | [Desktop environment](https://wiki.archlinux.org/title/Desktop_environment)                            |
| 内核       | 从 `lsmod`、`modprobe`、`mkinitcpio` 的 `MODULES` 入手，再考虑自编译内核                    | [Kernel](https://wiki.archlinux.org/title/Kernel)                                                      |
| 容器       | 先理解镜像、命名空间与 cgroups，再选 Docker 或 Podman（第 52 章）；`systemd-nspawn` 见 Wiki | [Docker](https://wiki.archlinux.org/title/Docker)、[Podman](https://wiki.archlinux.org/title/Podman)   |
| 磁盘与快照 | 在虚拟机中练 LUKS 与 btrfs 子卷，确认能救援后再上真机                                       | [Dm-crypt](https://wiki.archlinux.org/title/Dm-crypt)、[Btrfs](https://wiki.archlinux.org/title/Btrfs) |
| 参与社区   | 从提交 Wiki 修正、维护 AUR 包、报告 bug 开始                                                | [Getting involved](https://wiki.archlinux.org/title/Getting_involved)                                  |

参与社区不等于写代码。修正一处过期的 Wiki 命令、给 AUR 包补充构建依赖、在论坛复现并描述一个 bug，都是有效贡献。发言前先搜索是否已有讨论，提问时附上命令、完整报错和环境信息。

真机前的最后检查：

- [ ] 重要数据已备份到另一块磁盘
- [ ] 确认无线网卡、显卡、指纹等硬件有可用驱动
- [ ] 能在虚拟机中独立完成安装与救援
- [ ] 知道如何关闭 Secure Boot，或按第 42 章的流程签名引导器
- [ ] 准备好可用的 Live U 盘和第二台查资料的设备

## 小结

- 高频错误集中在三件事：跳过确认、跳过备份、跳过日志。
- 部分升级、滥用 `--overwrite`、长期 root 是破坏性最强的三类习惯。
- 安装阶段的坑多来自挂载点与设备标识，执行前必须验证。
- 里程碑的每一项都应有命令或输出作为证据，而不是「看过」。
- 完成本书只意味着能维护单机 Arch，桌面、内核、加密、容器仍需按 Wiki 深入。
- 下一步优先真机安装与桌面环境，但都要先在虚拟机中演练。

## 练习

1. 从常见坑表中选出你曾犯过的三条，写出当时的现象与正确做法（环境：阅读题）。
2. 用 `pacman -Qdt`、`pacman -Qm`、`pacman -Qe` 各生成一份清单，找出可清理项（环境：WSL；预期：三份清单非空或可解释为空）。
3. fstab 事故演练（环境：VM）：前置三步——快照、`cp /etc/fstab /etc/fstab.bak`、备好 Live ISO；再制造一次 fstab 重复条目进入 emergency mode，记录报错（预期：emergency 提示或挂载失败），用 `mount -o remount,rw /` 后从 `.bak` 恢复或用 Live ISO 修复，重启验证。

    > **危险**：本练习故意破坏启动配置，属不可逆操作；未完成上述前置三步不要开始。

4. 写一份自己的升级前检查清单，包含 News、备份、待升级包、日志四项（环境：阅读题）。
5. 对照里程碑清单，标出未完成项并给出验证命令（环境：阅读题）。
6. 从「完成本书之后」中选一个方向，列出开始前需要读的三个 Wiki 小节（环境：阅读题）。
