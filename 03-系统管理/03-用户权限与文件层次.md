# 03 用户、权限与文件层次

Arch 默认只给一个 root 账户，普通用户、sudo 权限和目录归属都要自己建立。权限问题很少表现为「命令报错」，更多是服务读不到配置、文件被别的用户覆盖、升级后配置消失。本章把用户、权限位和 FHS 放在一起讲，因为它们决定「东西该放哪、谁能动」。

> 本章目标：理解 UID/GID 与账户文件，能正确设置权限和属主，按 FHS 放置文件，并知道哪些路径不应手动修改。
> 对应 Wiki：[Users and groups](https://wiki.archlinux.org/title/Users_and_groups)、[File permissions and attributes](https://wiki.archlinux.org/title/File_permissions_and_attributes)

## UID 与 GID

Linux 用数字标识用户和组，名字只是 `/etc` 里的映射。

| 范围        | 用途           |
| ----------- | -------------- |
| UID 0       | root           |
| UID 1–999   | 系统账户与服务 |
| UID 1000 起 | 普通用户       |

```bash
id
# uid=1000(arch) gid=1000(arch) groups=1000(arch),998(wheel)
getent passwd arch
# arch:x:1000:1000::/home/arch:/bin/bash
```

`id` 同时显示主组和附加组。判断 sudo 是否可用，先看 `wheel` 是否在 `groups` 里。

## 账户文件

| 文件          | 内容                                 | 权限         |
| ------------- | ------------------------------------ | ------------ |
| `/etc/passwd` | 用户名、UID、GID、家目录、登录 shell | 所有人可读   |
| `/etc/shadow` | 密码哈希与账户有效期                 | 仅 root 可读 |
| `/etc/group`  | 组名、GID、成员列表                  | 所有人可读   |

`passwd` 中的 `x` 表示哈希在 `shadow`。`shadow` 字段依次是用户名、哈希、最后修改天数、最小/最大有效期、警告期、失效期。不要手写哈希，用 `passwd` 修改。

```bash
sudo useradd -m -G wheel -s /bin/bash arch
sudo passwd arch
```

`-m` 创建家目录，`-G` 设置附加组，`-s` 指定 shell。追加附加组用 `usermod -aG wheel arch`，`-a` 不能省。组变更在下次登录时生效。sudo 通过 `/etc/sudoers` 的 `%wheel ALL=(ALL:ALL) ALL` 授权，`sudo -v` 可验证凭据；完整流程见 [用户权限与 sudo](../01-环境准备/02-用户权限与-sudo.md)。

## chmod、chown 与 umask

| 八进制 | 权限  | 含义      |
| ------ | ----- | --------- |
| 0      | `---` | 无        |
| 4      | `r--` | 读        |
| 5      | `r-x` | 读 + 执行 |
| 6      | `rw-` | 读 + 写   |
| 7      | `rwx` | 全部      |

```bash
chmod u+x run.sh          # 属主加执行
chmod 644 notes.txt       # rw-r--r--
```

目录的 `r` 允许列出内容，`x` 允许进入和访问其中的文件；只有 `r` 没有 `x` 时，能看到名字但进不去。给目录设权限时不要只盯着 `w`。

`umask` 决定新文件的默认权限：把基准权限按位去掉 umask 中的位，就是实际权限。

```bash
umask
# 0022
touch newfile.txt && mkdir newdir
stat -c '%a %n' newfile.txt newdir
# 644 newfile.txt；755 newdir（两行输出）
```

文件基准是 666，目录基准是 777；`umask 022` 得到 644 与 755。`umask 027` 得到 640 与 750，适合不想让其他人读的场景。umask 只影响新建文件。

```bash
sudo chown arch:arch file.txt
sudo chown -R arch: /srv/app
```

省略组时只改属主。递归修改前先确认路径：

> **危险**：`chown -R` 和 `chmod -R` 会作用于整个目录树，路径写错可能破坏系统或让服务无法启动。执行前用 `pwd` 和 `ls` 确认目标，不要在 `/`、`/usr`、`/etc` 上随手递归。

## 特殊权限位

| 位     | 八进制 | 作用                             | 典型位置          |
| ------ | ------ | -------------------------------- | ----------------- |
| 粘滞位 | 1000   | 仅文件属主、目录属主或 root 可删 | `/tmp`            |
| setgid | 2000   | 新建文件继承目录的组             | 共享目录          |
| setuid | 4000   | 以文件属主身份执行               | `/usr/bin/passwd` |

```bash
sudo mkdir -p /srv/shared
sudo chgrp wheel /srv/shared
sudo chmod 2775 /srv/shared
ls -ld /tmp /srv/shared
# drwxrwxrwt ... /tmp；drwxrwsr-x ... /srv/shared
```

setgid 目录适合团队共享：把 `wheel` 换成实际的团队组后，新建文件会自动继承该组。setuid 是高风险特性，不要给自写程序添加。

## 文件层次 FHS

| 路径    | 放什么                       | 谁管理       |
| ------- | ---------------------------- | ------------ |
| `/etc`  | 系统与软件配置               | 管理员       |
| `/usr`  | 发行版提供的程序、库、文档   | 包管理器     |
| `/var`  | 可变数据：日志、缓存、数据库 | 服务与管理员 |
| `/opt`  | 自包含的第三方软件           | 管理员       |
| `/srv`  | 服务提供的数据               | 服务         |
| `/tmp`  | 临时文件，重启可能清空       | 任何人       |
| `/run`  | 运行时状态，重启清空         | 系统         |
| `/home` | 用户数据                     | 用户         |

## 包所有权

```bash
pacman -Qo /usr/bin/bash
# /usr/bin/bash is owned by bash 5.3.3-1
pacman -Qo /etc/ssh/sshd_config
# /etc/ssh/sshd_config is owned by openssh 10.2p1-1
```

- 不要手动往 `/usr` 放文件。`pacman -Qkk` 会把它报成 altered，重装或升级包时可能被覆盖。
- 软件包自带的配置在 `/etc`，可以修改；升级时 pacman 保留你的版本并生成 `.pacnew`，用 `pacdiff` 合并。
- 服务数据放 `/var/lib/服务名`，用户数据放 `/home`；自己编译的软件放 `/usr/local`，或打包后用 pacman 管理。

## ACL

传统权限只能表达「属主/组/其他人」，ACL 可以给单个用户额外授权。

```bash
setfacl -m u:arch:rw shared.txt
getfacl shared.txt
# user::rw-
# user:arch:rw-
# group::r--
# other::r--
```

`ls -l` 权限末尾出现 `+` 表示存在 ACL；`getfacl` 还会输出 `mask` 行，限制命名条目的最大权限。撤销用 `setfacl -x u:arch shared.txt`，清除全部用 `setfacl -b shared.txt`。ext4、xfs、btrfs 默认支持 ACL；WSL 的 `/mnt/c` 由 Windows 模拟权限，ACL 行为不可靠。

## 小结

- UID 0 是 root，普通用户通常从 1000 起，系统账户在低位区间。
- `/etc/passwd` 存账户，`/etc/shadow` 存密码哈希，`/etc/group` 存组成员。
- chmod 用八进制或符号设置权限，umask 决定新建文件的默认值。
- 粘滞位保护 `/tmp`，setgid 目录让新文件继承组，setuid 不要随便用。
- FHS 的分工：`/usr` 程序、`/etc` 配置、`/var` 可变数据、`/home` 用户数据。
- 包拥有的文件不要手改；本地软件放 `/usr/local` 或 `/opt`。

## 练习

1. 用 `id` 和 `getent passwd` 查看当前用户，说明每个字段的含义。
2. 创建测试文件，分别用 `chmod 600`、`640`、`664` 设置权限，用 `ls -l` 验证。
3. 设置 `umask 027`，新建文件与目录，记录实际权限，再恢复原值。
4. 创建 `/srv/shared`，设置 `2775` 和组 `devs`，验证新文件自动继承组。
