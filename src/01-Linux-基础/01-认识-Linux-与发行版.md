# 第 1 章 认识 Linux 与发行版

很多人把「Linux」当成一个操作系统的名字，把 Ubuntu、Fedora、Arch 当成「三种不同的 Linux」。要真正读懂后面章节的每一个概念，先把三个层次分清楚：内核、发行版、桌面。它们各管一件事，本章从这里开始。

> 本章目标：说清内核、用户空间、发行版与桌面各负责什么；能对比主流发行版的关键差异；理解为什么本书从 Arch 入手、而学的命令却是通用的。
> 对应 Wiki：[Arch compared to other distributions](https://wiki.archlinux.org/title/Arch_compared_to_other_distributions)

## 内核与用户空间

严格意义上的 Linux 只是**内核**：由 Linus Torvalds 团队维护的那段程序，负责进程调度、内存管理、文件系统、设备驱动与安全边界。日常说的「Linux 系统」，其实是内核加上用户空间的组合。

- 内核向上提供统一抽象：程序看到的是文件、目录、进程和网络连接，不必直接理解硬件。
- 用户空间是内核之外的一切：shell、命令行工具、图形桌面、库文件、你自己的程序。
- 程序不能直接访问硬件，只能向内核发起「系统调用」（读文件、申请内存、建立网络连接）。这个边界在第 12 章会再次展开。

把一台机器从下往上看，层次是这样的：

```text
硬件（CPU、内存、磁盘、网卡）
 ↑ 中断 / 驱动（I/O、时钟）
内核（Linux：调度、内存、文件系统、驱动）
 ↑ 系统调用
用户空间（shell、coreutils、库、桌面、应用程序）
```

你后面所有章节的操作，都发生在最上面那一层；内核层是第二篇与第三篇部分内容的主角。

```bash
# 任何发行版都有的两个查询命令
uname -r # 只输出内核版本号
cat /etc/os-release # 发行版自我标识
```

`uname -r` 描述内核版本；发行版内核包的 release 字符串通常带厂商/发行版标识，但同一个内核也可以运行在不同发行版上，发行版的差别都在用户空间。`/etc/os-release` 是发行版用来给自己贴标签的文件，脚本判断系统类型时读的就是它。本书验证环境的实跑结果如下（**输出以你机器为准，本书验证环境见 README** §验证环境）：

```text
$ uname -r
7.2.11-arch1-1
$ grep PRETTY_NAME /etc/os-release # grep 与管道的完整用法见第 4 章
PRETTY_NAME="Arch Linux"
```

内核版本里的 `arch1` 字样说明它来自 Arch 的内核包；发行版标识才是你练习时面对的用户空间。

## 发行版负责把零件组装成系统

发行版（distribution）= 内核 + 精选的用户空间软件 + 包管理器 + 默认配置 + 安装与维护方式。没有发行版，你面对的将是几百个各自编译的源码包；有了发行版，装机变成一次选择题。差异集中在这几个维度：

| 维度 | 发行版在决定什么 | 例子 |
| -------- | ---------------------------- | -------------------------- |
| 软件交付 | 用什么包管理器、软件版本多新 | APT、DNF、pacman、zypper |
| 发布节奏 | 固定周期大版本，还是滚动更新 | Ubuntu LTS 固定；Arch 滚动 |
| 默认配置 | 预装什么、替用户选好什么 | 桌面环境、驱动、开机服务 |
| 支持模式 | 社区维护还是商业公司支持 | Debian 社区；RHEL 商业 |

包管理器只是表层差异：安装、卸载、依赖解析大同小异；升级语义受发布模式影响（固定发行版与滚动发行版差别明显，见第 29、52 章）。第 29 章讲这些通用概念，第三篇再把它们落到 Arch 的 pacman 上。

## 主流发行版一览

| 家族 | 代表发行版 | 包管理 | 发布模式 | 定位一句话 |
| ----------- | ------------------- | ------------ | ---------------------------- | ---------------------------------- |
| Debian 系 | Debian、Ubuntu | APT | 固定周期 + LTS | 生态大，默认配置完整 |
| Red Hat 系 | Fedora、RHEL、Rocky | DNF | Fedora 半年、RHEL 固定 | 企业标准，新特性试验田 |
| Arch 系 | Arch、Manjaro | pacman | 滚动更新 | 极简基础系统，用户自己组装 |
| SUSE 系 | openSUSE、SLES | zypper | Leap 固定、Tumbleweed 滚动 | 自带管理工具链 |
| 其他/源码系 | Alpine、Gentoo | apk、portage | Alpine 固定周期、Gentoo 滚动 | Alpine 偏容器镜像；Gentoo 源码编译 |

这张表只描述定位，不评价优劣。选择的实质是：接受多少默认值、要多新的软件、需要社区还是商业支持。无论选谁，本书第一、二篇讲的命令与概念都通用——发行版差异是「默认值」的差异，不是「底层原理」的差异。

发行版之间还有亲缘关系：Ubuntu 衍生自 Debian，共享 APT 与 deb 包格式；Rocky、AlmaLinux 承接了 CentOS 留下的 RHEL 生态；Manjaro 基于 Arch 但加了默认配置。看懂「上游—下游」，很多软件兼容性问题就有了答案：下游继承上游的软件仓库，再叠加自己的打包与配置选择。

## 桌面环境与显示服务器（精讲）

Linux 桌面完全是用户空间的一层，内核并不知道你用的是 GNOME 还是 KDE：

- 桌面环境（DE）：GNOME、KDE Plasma、Xfce 等，是窗口管理、面板、文件管理器、设置工具的整套组合。
- 显示服务器：X11 与 Wayland 两代协议，负责程序把画面画到屏幕、把键鼠输入递回去。
- 显示管理器：登录界面，验证身份后启动桌面会话。

在纯命令行的服务器或最小安装里，这一层不存在；图形程序可以逐个安装并在有显示服务时运行，但那不是完整桌面会话。`echo $XDG_CURRENT_DESKTOP` 在图形会话中输出桌面名，在纯命令行里通常为空。图形相关的完整实践放在第五篇「桌面、多媒体与应用生态」，且建议在虚拟机里做。

## 为什么从 Arch 入手

- 组件透明：最小系统之上每加一个组件都由你决定，理解「Linux 由什么组成」的最佳样本。
- 无隐藏默认：发行版替你做的决定越少，你越能看见决定本身。
- 文档密度高：Arch Wiki 覆盖的大多是通用 Linux 主题，换一份发行版后依然适用。
- 滚动更新让你提前遇到真实的维护问题：升级、备份、读懂变更公告——这些与发行版无关，是所有 Linux 系统的日常。

本书的分工由此确定：第一、二篇只讲通用原理（命令、文件、权限、进程、网络、启动），第三篇才进入 Arch 专属工具。你现在学的每一条命令，在 Ubuntu、Fedora 上同样能用。

也要看清代价：Arch 不预装桌面、不替你做配置决定，滚动更新意味着你要自己跟踪升级。它适合想弄懂系统的人，不适合想要「装完即用」的人——这不是缺点，是定位。

## 术语小表

| 术语 | 含义 |
| -------------- | ------------------------------------------------- |
| 内核（kernel） | 管理硬件与系统资源的核心程序，即 Linux 本身 |
| 用户空间 | 内核之外的全部程序与库 |
| 系统调用 | 程序向内核提出请求的受控入口 |
| 发行版 | 内核 + 用户空间软件 + 包管理器 + 默认配置的组合 |
| 包管理器 | 安装、升级、卸载软件包的工具，如 APT、DNF、pacman |
| 桌面环境 | 窗口管理、面板、文件管理器等整套图形界面 |
| 显示服务器 | 承担画屏与输入转发的协议层，X11 或 Wayland |
| 滚动更新 | 无大版本、持续小步升级的发布模式 |

## 发行版选择的取舍与常见误判

选择发行版，实质上是在三个轴上取位置：**软件新旧**、**默认值多少**、**支持来源**。没有哪个位置绝对更好，只有与你使用场景是否匹配。

| 取舍 | 偏一端 | 偏另一端 | 主要代价 |
| --- | --- | --- | --- |
| 发布模式 | 固定周期 / LTS：变化可预期 | 滚动更新：软件新、问题也新 | 固定版软件旧；滚动版需要持续维护 |
| 默认配置 | 开箱即用：预装桌面与驱动 | 最小系统：自己组装 | 默认越多越难看清组成；最小系统上手慢 |
| 支持来源 | 商业支持：SLA 与认证 | 社区支持：文档与社区响应 | 商业支持有成本；社区支持靠自助 |
| 软件来源 | 官方仓库：一致、可审计 | 第三方仓库 / AUR：覆盖长尾 | 第三方源可能冲突、滞后或无人维护 |

**常见误判**（每一条都能在真实机器上验证）：

1. 把 `uname -r` 的输出当成发行版版本。它只是内核版本；**固定版本**发行版（Debian、Fedora 等）的版本看 `/etc/os-release` 的 `VERSION_ID`，而 Arch 是滚动发行版，`/etc/os-release` 里**没有** `VERSION_ID`，只有 `BUILD_ID=rolling`。判断 Arch 当前状态用 `PRETTY_NAME`、`BUILD_ID` 与 `uname -r`/`pacman -Q linux`；`/etc/arch-release` 文件存在本身也是判据。
2. 跨发行版照抄包管理命令。`apt install`、`dnf install`、`pacman -S` 解决的是同一件事，但包名、仓库与升级语义不同。
3. 在滚动发行版上「攒着不升级」，一次性跨几个月升级。滚动版的风险随间隔增大，正确做法是小步、常升级、先读公告（见第 52 章）。
4. 在一个发行版里混装另一发行版的包管理器或第三方二进制包。短期能跑，长期会出现文件所有权冲突；排查入口是「哪些文件不属于本发行版的包」。
5. 以为桌面环境属于内核或「Linux 自带」。最小安装没有桌面，桌面完全是用户空间的一组可选组件（见第五篇）。

**验证与回滚**：

```bash
# 一次确认「内核 / 发行版 / 包归属」三件事
uname -r
grep -E '^(NAME|VERSION_ID|BUILD_ID|PRETTY_NAME)=' /etc/os-release # Arch 没有 VERSION_ID，只有 BUILD_ID=rolling
ls /etc/arch-release # 存在（通常为空文件）即表明是 Arch
command -v apt dnf pacman zypper 2>/dev/null   # 只打印存在的包管理器
```

改动系统前的通用回滚点：虚拟机快照优先；物理机至少备份 `/etc` 与包清单（`pacman -Qqe > pkglist.txt`，其他发行版用对应查询命令）。如果已经混装出问题，先列出「不属于当前发行版的包」，再逐个卸载或重装，不要直接删文件。

**取舍边界**：如果你需要稳定可预期的服务器环境，固定发行版更合适；如果你要把「系统由什么组成」学清楚，最小系统 + 滚动更新更合适。本书选择 Arch 是为了后者，不代表它适合所有人。

## 小结

- Linux 严格指内核；日常所指的「Linux」是内核 + 用户空间工具组成的发行版。
- 发行版的差异在包管理器、发布节奏、默认配置、支持模式四个维度，底层原理相同。
- 桌面是用户空间最上层的一层，与内核无关；最小系统默认没有桌面。
- Arch 的价值在于把系统组成摆到明面；本书篇一、篇二讲通用知识，篇三才讲 Arch 专属内容。

## 练习

1. 运行 `uname -r` 和 `cat /etc/os-release`，写下内核版本与发行版标识，确认两者描述的是不同层次。
2. 运行 `ls /usr/bin | wc -l` 统计系统命令数量（管道与 `wc` 的细节见第 4 章），挑出三个你没用过的，先猜用途再用 `--help` 验证。
3. 在图形会话里运行 `echo $XDG_CURRENT_DESKTOP`；如果没有图形会话，记录它的空值并说明原因。
4. 打开参考中的「Arch compared to other distributions」，任选一个发行版，摘录它与 Arch 的三条差异并归类到本章的四个维度。
