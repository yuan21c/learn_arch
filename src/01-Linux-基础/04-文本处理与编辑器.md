# 第 4 章 文本处理与编辑器

Linux 把一切组织成文本：配置、日志、账号、源码。真正的效率来自把小工具串成流水线——一条命令只做一件事，管道把它们接起来。本章按数据的流向讲重定向与管道，再逐个拆开最常用的文本工具，最后落回编辑器 `vim`，让你既能筛选数据也能修改文件。

> 本章目标：理解标准输入、标准输出、标准错误与重定向/管道的组合；能组合 `cat/head/tail/wc/sort/uniq/cut/tr` 处理文本；会用 `grep` 按模式过滤并读懂它的退出码；能用 `sed/awk` 完成简单替换与取列；掌握 `vim` 的模式切换与最小编辑闭环。
> 对应 Wiki：[Grep](https://wiki.archlinux.org/title/Grep)、[Vim](https://wiki.archlinux.org/title/Vim)

## 标准流与重定向

每个程序出生时带着三个文件描述符：`0` 标准输入（读）、`1` 标准输出（写结果）、`2` 标准错误（写报错）。重定向就是把这些流改道到文件：

| 写法 | 作用 |
| ------ | ------------------------------------------------- |
| `>` | 把 stdout 写入文件（**覆盖**） |
| `>>` | 把 stdout 追加到文件末尾 |
| `<` | 从文件读入作为 stdin |
| `2>` | 只把 stderr 写入文件 |
| `2>&1` | 把 stderr 并入当前 stdout，一起被管道或重定向接走 |

> **危险**：`>` 会先把目标文件**清空**再写入，且不进回收站。追加只能用 `>>`；动配置文件前先 `cp file file.bak`，`> ~/.bashrc` 这类操作永远不要敲。

顺序敏感：`>file 2>&1` 把 stderr 一起写进文件；`2>&1 >file` 则 stderr 仍去屏幕——重定向从左到右依次生效，写反了行为完全不同。

管道 `|` 把左边的 stdout 接到右边的 stdin，数据单向流动，可以串联多级。错误信息默认不进管道，这正是 `2>&1` 存在的理由。实跑一组（/tmp 演练）：

```bash
mkdir -p /tmp/text-lab && cd /tmp/text-lab && printf 'a 1\nb 2\nc 3\na 1\n' > data.txt # 布场：4 行、含两次 a 1
sort data.txt | uniq -c # 排序后统计重复
ls nofile-xyz 2>err.log # 报错进文件，屏幕保持干净
head -1 err.log # ls: cannot access 'nofile-xyz': ...
wc -l < data.txt # 输入重定向：结果只有数字，没有文件名
```

## 查看与计数：cat、head、tail、wc

- `cat`（concatenate，连接/拼接）属于 GNU coreutils，Unix 第 1 版即有，原本用于拼接多个文件并输出，现也常用来查看小文件。`cat -n 文件` 连续输出并标行号；`cat a.txt b.txt` 拼接多个文件。但 `cat` 不做筛选：小文件查看/拼接直接用 `cat`，看大文件用 `less`，要筛选就把文件直接交给 `grep`（不必 `cat file | grep`）。选项来源：`-n` = number（行号）。
- `head`（head，开头）属于 GNU coreutils，Unix 第 1 版即有，取文件开头若干行。选项来源：`-n` = number，默认 10 行。
- `tail`（tail，尾巴）属于 GNU coreutils，Unix 第 1 版即有，取文件结尾若干行；`-f` = follow（跟随）用于盯日志。选项来源：`-n` = number，默认 10 行；`-f` = follow，持续跟踪新增内容，是盯日志的标准姿势。
- `wc`（word count，字数统计）属于 GNU coreutils，Unix 第 1 版即有，统计行/词/字节。选项来源：`-l` = lines（行数）、`-w` = words（词数）、`-c` = bytes（字节数）；从管道或 `<` 进来时它只输出数字。

```bash
seq 1 5 | tail -2 # 4 5
wc -l < data.txt # 4
```

```bash
seq 1 5 | tail -2 # 4 5
wc -l < data.txt # 4
```

## 排序与整理：sort、uniq、cut、tr

`sort`（sort，排序）属于 GNU coreutils，Unix 第 1 版即有，默认比较是**文本序**（字符串比较），这有一个著名陷阱——按字符串排，`10` 排在 `9` 前面；数字必须给 `-n`（实跑）：

选项来源：`-n` = numeric（数字序）、`-r` = reverse（倒序）、`-k` = key（按第几列）、`-u` = unique（去重）。

```bash
printf '9\n10\n1\n' | sort # 1 10 9
printf '9\n10\n1\n' | sort -n # 1 9 10
```

其余三个各管一段：

| 命令 | 来源 | 职责 | 常用形式 |
| ------ | ---- | --------------- | ------------------------------------------------- |
| `sort` | sort（排序） | 排序 | `-n` 数字、`-r` 倒序、`-k2` 按第 2 列、`-u` 去重 |
| `uniq` | unique（唯一/去重） | 相邻去重 | `-c` count（计数）、`-d` duplicated（只留重复行，先 `sort` 再 `uniq`） |
| `cut` | cut（切割） | 按列切分 | `-d` delimiter（分隔符，如 `-d,`）、`-f` fields（字段，如 `-f2`） |
| `tr` | translate（翻译/替换） | 字符级翻译/删除 | `tr 'a-z' 'A-Z'`、`tr -d '\r'` 清 CRLF 换行 |

记忆：sort = 排序，把文本按字母或数字重排；uniq = unique，去重，但**只合并相邻重复行**，必须先 `sort` 再 `uniq`；cut = cut，像剪刀一样按列“切开”文本；tr = translate，字符级“翻译”，把一个字符换成另一个，或用 `-d` delete 删除字符。

`tr` 不接文件名，只从 stdin 读，所以永远出现在管道里。

## grep 过滤文本

`grep`（g/re/p，全局正则表达式打印）返回所有匹配行，是文本流水线里出现频率最高的过滤器。它的名字来自 ed 编辑器里的命令 `g/re/p`：在整个文件（g，global）中按正则表达式（re，regular expression）匹配并打印（p，print）匹配行，后来独立成命令。属于 GNU grep。

选项来源如下表：

| 选项 | 来源 | 作用 |
| ---- | ---- | ---- |
| `-i` | ignore case（忽略大小写） | 忽略大小写 |
| `-n` | number（行号） | 标出行号 |
| `-v` | invert（反选） | 反选，输出**不**匹配的行 |
| `-c` | count（计数） | 只输出匹配行数 |
| `-r` | recursive（递归） | 递归搜索目录 |
| `-E` | extended regex（扩展正则） | 扩展正则（`|`、`+`、`()` 不用反斜杠） |

记忆：grep = g/re/p，记忆口诀“全局正则打印”；-i = ignore case，-v = invert（反选），-c = count（计数匹配行数）。

退出码是 grep 的隐藏价值：`0` 有匹配、`1` 无匹配、`2` 出错；上一条命令的退出码保存在 `$?` 里（`echo $?` 查看）。脚本据此分支，实跑验证：

```bash
grep -c 'a 1' data.txt # 2
grep zzz data.txt # 无输出
echo $? # 1
```

锚点与通配在正则里：`^error` 行首、`end$` 行尾、`.` 匹配任意单字符；配合 `-E 'error|warn'` 可一次匹配多个词。

## sed 与 awk 入门

`sed`（stream editor，流编辑器）是逐行流编辑器，属于 GNU sed，Unix 第 1 版即有早期原型。最常用的形态是替换：`sed 's/旧/新/' 文件`（默认每行只换第一处，加 `g` 换全行）；`2s/…/…/` 限定第 2 行；`sed -n '2p' file` 只打印第 2 行（`-n` 关掉默认输出，由 `p` 显式打印）。选项来源：`-n` 抑制默认输出、`p` = print（显式打印）、`-i` = in-place（就地修改）、`s` = substitute（替换）、`g` = global（全局替换）。替换结果先输出到屏幕确认，无误再落地。

记忆：sed = stream editor，流式编辑器；s = substitute 替换；g = global 全局替换；-n = 抑制默认输出，配合 p 显式打印。

> **危险**：`sed -i` 直接改写原文件。确认无误才用；建议 `sed -i.bak 's/旧/新/' 文件` 顺手留一份 `.bak` 备份。（`-i` = in-place，就地修改，`.bak` 是备份后缀）

`awk`（Aho、Weinberger、Kernighan 三位作者姓氏首字母缩写）按字段处理，1977 年由 Bell Labs 三人开发，默认以空白为分隔符切出 `$1`、`$2`…，`$0` 是整行，`-F:` 可改分隔符——读 `/etc/passwd` 全靠它（实跑）。选项来源：`-F` = field separator（字段分隔符）；`$0` 整行，`$1`、`$2`… 第几列。

记忆：awk = 三位作者姓氏缩写（Aho + Weinberger + Kernighan）；$0 = 整行，$1 = 第 1 列，$2 = 第 2 列。

```bash
sed 's/a/AA/' data.txt | head -2 # 替换送到管道
awk '{print $1, $2*2}' data.txt # 取第 1 列，第 2 列翻倍
awk -F: '{print $1}' /etc/passwd | head -3
```

`awk` 的完整形态是 `模式 {动作}`：`/ERROR/ {print $1}` 只打印含 ERROR 行的第一列。到这里，「从日志里抓出错误、按字段统计、导出成表」的组合已经齐了。

## vim 核心操作

`vim`（Vi IMproved，改进版 Vi）是 vi 的改进版，作者 Bram Moolenaar，1991 年首次发布；其前身 vi 由 Bill Joy 于 1976 年开发。多数服务器与桌面发行版自带 `vim`，但 distroless 或 busybox 这类精简镜像里可能没有（实跑 `vim --version`：本机为 Vi IMproved 9.2）。它难在**模式**，而最小闭环只有几步：

- 打开：`vim 文件`；进入插入：`i`（insert，光标前）或 `a`（append，光标后）；`Esc` 回到正常模式——不确定自己在哪个模式，就按一次 `Esc`。
- 保存退出：正常模式下 `:wq`（write + quit，保存退出）；放弃修改退出 `:q!`（quit 强制退出）；`:w` 只保存。
- 移动与编辑：`h j k l` 上下左右，`gg`/`G` 到文件首尾，`dd` 删整行，`p` 粘贴，`u` 撤销，`Ctrl-r` 重做。
- 辅助：`:set number` 显示行号；`:help 主题` 查内置帮助；`vimtutor` 是自带的交互教程，分课节推进，可随时退出。

记忆：vim = Vi Improved，vi 的改进版；i = insert 插入；a = append 追加；Esc 回正常模式；:wq = write + quit；:q! = quit 强制退出。

先把「插入 → `Esc` → `:wq`」和「`dd` → `u`」两组肌肉记忆练出来，其余按需查。

## 常见失败与验证

| 失败模式 | 原因 | 验证与回滚 |
| --- | --- | --- |
| `>` 把原文件清空 | 重定向在命令执行前就截断目标 | 先输出到临时文件，检查后再 `mv`；或 `>>` 追加 |
| `sed -i` 改错无备份 | 就地修改不保留原文件 | 用 `sed -i.bak`，或先 `sed ... 文件 \| diff -u 文件 -` |
| `grep` 没结果但文件明明有 | 大小写、二进制文件、编码 | `grep -i`、`grep -a`、`file 文件`；先 `grep -F` 排除正则元字符 |
| `sort`/`uniq` 结果不对 | `uniq` 只合并相邻重复行 | 先 `sort` 再 `uniq`；用 `sort -u` 等价替代 |
| `awk`/`cut` 字段错位 | 分隔符不一致、连续空格 | `awk -F'\t'`、`cut -d' ' -f...` 前先用 `cat -A` 看真实分隔 |

**回滚与验证**：任何就地编辑（`sed -i`、`vim` 保存）前先确认文件在版本控制或备份中；没有就 `cp -a 文件 文件.bak`。验证时先用 `diff -u` 看差异，再决定是否保留。`vim` 的 `:q!` 是放弃修改的兜底；不熟悉时不要用 `:wq` 盲存。

**取舍**：`grep`/`sed`/`awk` 适合一行流与批量；复杂逻辑应写成脚本或改用 `python`。`cut` 只按固定分隔符，`awk` 能处理空白与条件，`tr` 只能字符级替换——选错工具会让命令越写越长。

## 小结

- stdout 与 stderr 是两条流：`>` 覆盖、`>>` 追加、`2>` 分流、`|` 串联；`>` 会清空文件。
- `head/tail/cat/wc` 负责取段与计数；`tail -f` 跟踪日志。
- `sort` 默认文本序（`10` 在 `9` 前），数字要 `-n`；`uniq` 只合并相邻行；`cut` 取列、`tr` 换字符。
- `grep` 的选项覆盖日常过滤，退出码 0/1/2 让它可以当条件用。
- `sed` 管替换、`awk` 管字段；`-i` 落地前先确认，`.bak` 是好习惯。
- `vim` 的关键是模式：`i` 进入、`Esc` 返回、`:wq` 保存退出、`dd/u` 可逆。

## 练习

1. 造数据并走一遍流：

 ```bash
 mkdir -p /tmp/text-lab && cd /tmp/text-lab

 head -5 n.txt; tail -n 3 n.txt; wc -l < n.txt
 ```

2. 用 `printf '9\n10\n1\n' | sort` 与 `sort -n` 复现文本序陷阱，再用 `sort -rn` 做倒序数字排序。
3. 生成含重复行的文件：`printf 'b 2\na 1\nc 3\na 1\n' > d.txt`，然后 `sort d.txt | uniq -c` 统计，`cut -d' ' -f1 d.txt | sort | uniq -c` 统计各字符出现次数。
4. 对同一文件分别执行 `grep a d.txt; echo $?` 与 `grep zzz d.txt; echo $?`，记录两次退出码并解释；再用 `grep -E 'a 1|b 2'` 一次模式匹配三行（两种行型：`a 1` 两行、`b 2` 一行）。
5. 用 `sed -n '2p' d.txt` 取第 2 行、`sed 's/a/AA/' d.txt` 先看替换结果（不加 `-i`）；用 `awk -F: '{print $1}' /etc/passwd | head -5` 列出账号名。
