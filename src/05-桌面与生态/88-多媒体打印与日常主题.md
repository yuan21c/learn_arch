# 第 88 章 桌面日常总览：音频、打印、电源、输入法与蓝牙

这一章是「桌面日常」的合并章：音频、打印、电源、输入法、蓝牙。它们在 Wiki 上各有一整套页面，但使用频率不高、彼此又常一起出现（装了桌面就会遇到），所以按**精讲 + 索引**处理：给出能跑通的最小配置和排障入口，细节交给 Wiki。

> 本章目标：能用 PipeWire 跑起声音并知道它与 PulseAudio 的关系；能用 CUPS 添加一台无驱动打印机并验证；理解挂起/休眠的前提与 logind 的合盖策略；能在 X11 与 Wayland 下分别配好 Fcitx5 输入法；会用 `bluetoothctl` 完成一次配对。长尾应用（浏览器、办公、视频播放）只给索引，不展开。
> 对应 Wiki：[PipeWire](https://wiki.archlinux.org/title/PipeWire)、[CUPS](https://wiki.archlinux.org/title/CUPS)、[Power management](https://wiki.archlinux.org/title/Power_management)、[Fcitx5](https://wiki.archlinux.org/title/Fcitx5)、[Bluetooth](https://wiki.archlinux.org/title/Bluetooth)

## 音频：PipeWire

PipeWire 是当前桌面环境普遍采用的 Arch 音频栈，兼容 PulseAudio 与 JACK 的客户端；**最小系统不会自带**，要手动安装（桌面）：

```bash
sudo pacman -S pipewire pipewire-pulse pipewire-alsa wireplumber
systemctl --user enable --now pipewire pipewire-pulse wireplumber
wpctl status
```

三个组件分工：`pipewire` 是服务本体，`pipewire-pulse` 提供 PulseAudio 兼容接口（老程序照常能用），`wireplumber` 是会话/策略管理器（决定设备优先级、路由）。**它们是用户级服务**（`--user`），不是系统级。

排障入口：`pavucontrol`（图形路由面板）看每个应用的声音路由；`wpctl status` 看设备与默认节点；没有声音时先确认「设备被识别」（`aplay -l`，来自 `alsa-utils`）再确认「默认输出节点正确」。

视频播放与硬件解码：`ffmpeg` 提供基础编解码，`gst-plugins-*` 供 GStreamer 应用使用；VA-API 硬件解码按显卡选：Intel 用 `intel-media-driver`，AMD 的由 `mesa` 提供（旧的独立包名已并入 mesa），用 `vainfo` 验证。

## 打印：CUPS

（需要实际或虚拟打印机）

```bash
sudo pacman -S cups
sudo systemctl enable --now cups.socket
```

推荐启用 **`cups.socket`**（socket 激活，只在有打印请求时才启动服务，省资源）；直接 `enable --now cups.service` 也可以，服务会常驻并监听 631 端口与本地 `/run/cups/cups.sock`，但空闲时也占内存。管理界面在 `http://localhost:631`，命令行等价：

```bash
lpstat -p -d # 打印机列表与默认打印机
sudo lpadmin -p myprinter -E -v ipp://打印机地址/ipp/print -m everywhere # 通常需 root 或 CUPS SystemGroup 成员
lp -d myprinter /etc/hostname # 打印一个测试文件
```

`-m everywhere` 走 **IPP Everywhere（无驱动打印）**：现代网络打印机都支持，不需要装厂商驱动。老打印机才需要 `foomatic`/厂商 PPD——这也是「Linux 打印难」这一旧印象的主要来源，新设备基本没有了。

常见故障：`lpstat` 里打印机状态 `disabled`（用 `cupsenable` 恢复）；任务卡住（`cancel -a`）；找不到设备（先用 `ippfind` 或打印机 IP 的 Web 界面确认可达）。

## 电源：挂起、休眠与合盖

三种状态差别很大：

| 状态 | 内存 | 磁盘 | 恢复速度 | 前提 |
| ------------------- | ---------------- | ---- | -------- | -------------------------------------- |
| 挂起（suspend，S3） | 保持供电 | 不写 | 秒级 | 驱动支持 |
| 休眠（hibernate） | 写入 swap 后断电 | 需要 | 十秒级 | **swap ≥ 内存**，且内核参数指定 resume |
| 混合睡眠 | 两者都做 | 需要 | 秒级 | 同休眠 |

```bash
systemctl suspend
systemctl hibernate # 没配好 swap 会直接失败
```

休眠有三个细节别漏：**两种 initramfs 都要写 `resume=`**——systemd hook 由 initramfs 里的 systemd 据此恢复，busybox hook 还要在 `HOOKS` 里加 `resume`（示例：`HOOKS=(base udev autodetect modconf block resume filesystems keyboard fsck)`，顺序以 Wiki 为准）。**swapfile 还需要 `resume_offset=`**，按文件系统取偏移——ext4 用 `filefrag -v`，btrfs 用 `btrfs inspect-internal map-swapfile -r`；UEFI 机器上 systemd 可能通过 `HibernateLocation` 自动定位，改了 swap 布局要同步。另外 `linux-hardened` 内核不支持休眠。

```bash
# 查询 swapfile 的 resume_offset（按文件系统分支）
sudo filefrag -v /swapfile # ext4：取 first_extent 的 physical_offset
sudo btrfs inspect-internal map-swapfile -r /swapfile # btrfs：直接输出偏移
```

把 `resume=<swap 所在分区的 UUID>` 与 `resume_offset=<上面的偏移>` 一起写进内核命令行（GRUB 的 `GRUB_CMDLINE_LINUX_DEFAULT` 或 systemd-boot 的 entry），再重建引导配置。

合盖、电源键的行为由 **logind** 决定，配置在 `/etc/systemd/logind.conf`：

```text
HandleLidSwitch=suspend
HandleLidSwitchExternalPower=suspend
HandleLidSwitchDocked=ignore
```

改完 `systemctl restart systemd-logind`（会短暂影响会话）。笔记本上还有一个二选一：`power-profiles-daemon`（桌面环境集成、切换性能/平衡/省电）或 `tlp`（细粒度、偏命令行）——**不要同时装**，两者会互相覆盖策略。

## 输入法：Fcitx5

（桌面）

```bash
sudo pacman -S fcitx5 fcitx5-chinese-addons fcitx5-gtk fcitx5-qt fcitx5-configtool
```

环境变量是 X11 下的关键，必须在**会话启动时**注入：写 `~/.xprofile`（display manager 启动的 X11 会话）或 `~/.xinitrc`（`startx`）。`environment.d` 只对 systemd 用户服务生效，图形会话未必读取，不要把 X11 变量放那里：

```text
GTK_IM_MODULE=fcitx
QT_IM_MODULE=fcitx
XMODIFIERS=@im=fcitx
```

自动启动：在桌面环境的「自启动」里加 `fcitx5 -d`，或建一个用户级 unit（第 63 章）。图形配置工具是 `fcitx5-configtool`（已在上面的安装清单里）。Wayland 下按合成器分三种情况：GNOME 需要装输入法扩展；KDE 在系统设置里启用；走 XWayland 的老程序仍依赖上面三个 IM 变量——**遇到「候选框不跟随光标」先查该合成器的 Wiki 小节**。

排障顺序：`fcitx5-diagnose`（官方诊断脚本，会把环境变量、进程、DBus 状态一次列清）→ 检查环境变量是否在**会话内**生效（`echo $GTK_IM_MODULE`）→ 检查是否只有一个输入法框架在跑（IBus 与 Fcitx 冲突是常见原因）。

## 蓝牙

```bash
sudo pacman -S bluez bluez-utils
sudo systemctl enable --now bluetooth
bluetoothctl
```

交互式流程：`power on` → `agent on` → `default-agent` → `scan on` → `pair <MAC>` → `trust <MAC>` → `connect <MAC>`。设备被 `rfkill` 阻断时先 `rfkill list` 看清类型：**Soft blocked** 可用 `rfkill unblock bluetooth` 解除；**Hard blocked** 是物理开关/BIOS 关着，软件解不动，去查机身开关。

## 失败模式

| 现象 | 根因 | 处置 |
| ------------------------------ | ------------------------------------------ | ------------------------------------------------------ |
| `wpctl` 报 `Could not connect to PipeWire` | 用户级服务没启动，或没在图形会话内 | `systemctl --user enable --now pipewire pipewire-pulse wireplumber` |
| 有设备但没声音 | 默认输出节点错/静音/路由到错误设备 | `wpctl status` 看默认节点，`pavucontrol` 按应用改路由 |
| 播放卡顿、爆音 | 采样率不匹配或会话管理器未接管 | 查 `pw-metadata -n settings`，确认 `wireplumber` 在跑 |
| `lpstat` 显示打印机 `disabled` | 队列被暂停或出错 | `cupsenable <打印机>`，再看 `lpstat -p` |
| 打印任务永远卡住 | 队列停在错误状态/后端不可达 | `cancel -a <打印机>`，检查 `http://localhost:631` 的错误日志 |
| `systemctl hibernate` 直接失败 | swap 小于内存或没配 `resume=` | 按正文检查 swap 与 initramfs 的 `resume`/`resume_offset` |
| 合盖不睡眠 | `logind.conf` 被改或别的电源服务接管 | 备份后恢复 `HandleLidSwitch`，`systemctl restart systemd-logind` |
| 输入法候选框不跟随光标 | Wayland 合成器 `text-input` 支持不足 | 按合成器 Wiki 处理；XWayland 程序另测 |
| 打字触发两边候选框 | IBus 与 Fcitx5 同时在跑 | 只保留一个框架，删另一个的自启项 |
| 蓝牙设备搜不到 | `rfkill` 软/硬阻断 | `rfkill list`；软阻断 `unblock`，硬阻断查物理开关 |

## 验证与回滚

日常主题的验证都遵循「服务状态 → 设备识别 → 实际功能」三步：

```bash
systemctl --user is-active pipewire pipewire-pulse wireplumber
wpctl status | head -20
aplay -l 2>/dev/null | head -8
lpstat -p -d 2>/dev/null
cat /sys/power/state
echo "$GTK_IM_MODULE $QT_IM_MODULE $XMODIFIERS"
rfkill list 2>/dev/null | head -8
```

服务 `active` 只说明进程在跑；`wpctl status` 里有设备与默认节点、`aplay -l` 能看到声卡、`lpstat` 能看到队列，才算链路通。电源状态用 `cat /sys/power/state` 确认 `mem`/`disk` 是否可用；输入法看三个变量是否在**会话内**有值。

回滚：

```bash
systemctl --user disable --now pipewire pipewire-pulse wireplumber
rm ~/.config/autostart/fcitx5.desktop
sudo cp /etc/systemd/logind.conf.bak /etc/systemd/logind.conf
sudo systemctl restart systemd-logind
lpadmin -x myprinter # 删除打印队列
```

停用用户级音频服务会同时影响所有桌面应用，操作前先确认不是远程会话；`logind.conf` 改错会导致合盖/电源键行为异常，**改前必须备份**。

## 取舍边界

- **PipeWire vs PulseAudio vs 裸 ALSA**：桌面统一用 PipeWire；需要 JACK 级低延迟见第 89 章；裸 ALSA 只适合无会话管理器的极简环境。
- **`cups.socket` vs `cups.service`**：socket 激活省资源，适合偶尔打印；常驻服务启动更快，适合打印频繁的场景。
- **挂起 vs 休眠**：挂起快、依赖供电；休眠省电、依赖 swap 与 `resume` 配置。笔记本合盖用挂起，长期离机才考虑休眠。
- **`power-profiles-daemon` vs `tlp`**：前者与桌面集成、切换简单；后者细粒度但需自己调参。二者只能选一个。
- **Fcitx5 vs IBus**：Fcitx5 生态与中文输入更完整；IBus 与 GNOME 集成更直接。选一个，不要在同一个会话里跑两个。
- **蓝牙 vs USB/2.4G**：蓝牙方便但受射频与协议限制；对延迟敏感的设备优先有线或专用接收器。

## 小结

- 音频：PipeWire + `pipewire-pulse` + `wireplumber`，三个都是**用户级**服务；`wpctl`/`pavucontrol` 是排障入口。
- 打印：推荐启用 `cups.socket` 激活（`cups.service` 亦可），现代打印机用 `-m everywhere` 无驱动添加。
- 电源：挂起只保内存、休眠要 swap ≥ 内存；合盖策略在 `logind.conf`；`power-profiles-daemon` 与 `tlp` 二选一。
- 输入法：Fcitx5 + 三个环境变量（X11）；Wayland 依赖合成器的 `text-input` 支持；`fcitx5-diagnose` 先跑。
- 蓝牙：`bluez` + `bluetoothctl` 六步配对；`rfkill` 解阻断。
- 长尾主题只留索引，按需去 Wiki。

## 练习

1. 音频链路：装好 PipeWire 后 `wpctl status` 与 `aplay -l` 各看一次，播放一个 wav 文件；用 `pavucontrol` 把某应用切到另一个输出设备，说明「默认节点」与「应用路由」的区别。
2. 无驱动打印：用 `lpadmin -m everywhere` 添加一台 IPP 打印机（可先用 `ippfind` 找），`lpstat -p -d` 确认，打印一个文本文件；再故意 `cupsdisable` 一台打印机，观察任务卡住并恢复。
3. 挂起实测：`systemctl suspend` 后恢复，检查 `journalctl -b | grep -i suspend` 的记录；再试 `systemctl hibernate`，说明为什么在 swap 不足时会失败。
4. 合盖策略（需要真机）：读 `logind.conf` 的默认值，改成「接电源时 ignore、用电池时 suspend」，重启 logind 后验证。
5. 输入法：配好 Fcitx5 与环境变量，`fcitx5-diagnose` 保存输出，指出其中哪几项说明配置正确；在 X11 与 Wayland 会话下各测一次切换。
6. 蓝牙（需要真机）：用 `bluetoothctl` 完成一次配对与连接，`rfkill list` 前后对比；断开后 `trust` 的作用是什么？
