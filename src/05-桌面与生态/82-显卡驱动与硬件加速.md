# 第 82 章 显卡驱动与硬件加速

第 81 章把图形栈分成「内核 → 显示服务器 → 桌面」三层；这一章钻进最底下那层：**内核显示驱动与用户态加速库**。同一块 GPU 要工作，需要内核模块、Mesa（OpenGL/Vulkan）、固件、以及按用途选择的 VA-API / CUDA / ROCm，缺一层就退化成软件渲染。

> 本章目标：能画出「内核模块 → Mesa → Vulkan ICD / VA-API → 应用」的驱动链条；能按 Intel、AMD、NVIDIA 三类硬件说出该装哪些包、有哪些专属内核参数；知道虚拟机里 3D 加速走的是 `virtio-gpu`/virgl，而不是厂商驱动；会用 `lspci -k`、`glxinfo -B`、`vulkaninfo`、`vainfo` 判断当前实际走哪条路径；能识别「驱动装了但没接管」「升级内核后 NVIDIA 模块丢失」「混合显卡用错 GPU」三类问题。
> 对应 Wiki：[Intel graphics](https://wiki.archlinux.org/title/Intel_graphics)、[AMDGPU](https://wiki.archlinux.org/title/AMDGPU)、[NVIDIA](https://wiki.archlinux.org/title/NVIDIA)、[Hardware video acceleration](https://wiki.archlinux.org/title/Hardware_video_acceleration)、[PRIME](https://wiki.archlinux.org/title/PRIME)

## 驱动链条：四层各管什么

| 层 | 典型组件 | 作用 | 缺了会怎样 |
| -------------------- | ------------------------------------------- | ------------------------------------ | ------------------------------ |
| 内核模块 | `i915`/`xe`、`amdgpu`、`nvidia`、`nouveau` | 初始化 GPU、KMS 显示模式、暴露 `/dev/dri` | 只能用 `llvmpipe` 软件渲染 |
| 固件 | `linux-firmware` 中的 GPU 固件 | 驱动加载微码与电源管理 | 驱动加载失败或功能受限 |
| 用户态图形库 | `mesa`（OpenGL/EGL） | 实现 OpenGL/EGL，供桌面与游戏调用 | `glxinfo`/EGL 应用异常 |
| Vulkan ICD | `vulkan-intel`、`vulkan-radeon`、`vulkan-nouveau` | 提供 Vulkan 驱动清单与实现 | `vulkaninfo` 找不到设备 |

视频加速与计算是另外两条并行栈：VA-API（`intel-media-driver`/Mesa 的 `radeonsi`）负责硬解硬编；CUDA/ROCm 负责 GPU 计算。它们与 OpenGL 共用内核模块，但**包与验证命令完全不同**，不要把 `glxinfo` 正常当成「硬解也可用」。

## 三条硬件路线

### Intel：内核模块 + Mesa + 分代 VA-API

```bash
sudo pacman -S mesa vulkan-intel
sudo pacman -S intel-media-driver # Broadwell（Gen8）及以后平台的 VA-API
# 更老的平台改用 libva-intel-driver（i965）；按 Wiki 的硬件代际表选择
```

- 内核模块：老平台 `i915`，Xe 架构新平台由 `xe` 驱动接管；两者都由内核提供，装 `linux-firmware` 即可，不要从厂商站点手抓固件。
- OpenGL：`mesa` 内置 Intel 驱动；Vulkan 由 `vulkan-intel` 提供 ICD。
- 硬解：`intel-media-driver`（iHD）与 `libva-intel-driver`（i965）**不要同时依赖**，按代际选一个；验证用 `vainfo`。
- 混合显卡笔记本的核显通常负责显示输出，独显按需渲染（见下文 PRIME）。

### AMD：开源栈最省心

```bash
sudo pacman -S mesa vulkan-radeon
# 计算用途另装：rocm-hip-runtime、rocm-opencl-runtime（按需）
```

- 内核模块 `amdgpu`（GCN 及以后）；更老的卡可能落到 `radeon`，按 Wiki 的硬件表确认。
- OpenGL/Vulkan 都由 `mesa` 提供，`vulkan-radeon` 只是 ICD 清单。
- VA-API 由 `mesa` 的 `radeonsi` 实现，**不需要额外装 VA-API 驱动包**；这是与 Intel 最大的差别。
- ROCm 只支持特定代际，装之前先查官方支持列表，别把「能装」当成「能用」。

### NVIDIA：闭源与开源内核模块

```bash
sudo pacman -S nvidia-open nvidia-utils # Turing（GTX 16xx / RTX 20xx）及以后
# 自定义内核用 nvidia-open-dkms；更老的卡走 AUR 的 legacy 分支
```

- `nvidia-open` 是官方开源内核模块，用户态仍是闭源 `nvidia-utils`；Turing 之前的卡不支持，必须用对应 legacy 包。
- 内核参数：`nvidia_drm.modeset=1`（Wayland 必需，545 之后不再是实验项），需要控制台帧缓冲时再加 `nvidia_drm.fbdev=1`。
- 自定义内核或频繁升级内核时用 `-dkms` 变体，并确认 DKMS 在每次内核升级后真的重建成功（`dkms status`）。
- `nouveau` 是内核自带的反向工程驱动，日常桌面够用但性能与电源管理弱；`xf86-video-nouveau` 只是 X11 的 DDX，现代环境多走 `modesetting`，不必强装。
- 混合显卡用 PRIME：`prime-run <命令>`（`nvidia-prime`），或设 `__NV_PRIME_RENDER_OFFLOAD=1 __GLX_VENDOR_LIBRARY_NAME=nvidia`。

## 虚拟机：走 virtio，不装厂商驱动

虚拟机里没有真实 GPU，只有虚拟显示设备：

| 设备 | 能力 | 适用 |
| ------------- | ------------------------------------------ | ------------------------------ |
| `virtio-gpu` | 2D + 3D（virgl）；Vulkan 走 Venus，实验性 | 推荐的通用选择 |
| `qxl` | 基本 2D，无 3D | 老系统、兼容性优先 |
| `vmware` | VMware 专用，2D 为主 | VMware 宿主 |
| `vga` | 纯 2D 帧缓冲 | 排障、最小环境 |

虚拟机里只需 `mesa`，**不要装 `nvidia`/`amdgpu` 厂商包**——设备根本不存在，装了只会让 `lspci -k` 与模块加载更混乱。看到 `glxinfo` 的渲染器是 `llvmpipe`，说明 3D 加速没开或宿主不支持；开宿主 3D 加速后应看到 `virgl`（或 `SVGA3D`）。

## 可复现实验：判断当前走哪条路径

全部只读，无图形会话也能跑；预期结果已在本机验证：

```bash
lspci -k | grep -A3 -E 'VGA|3D|Display'
lsmod | grep -E 'i915|xe|amdgpu|nvidia|nouveau|virtio_gpu|qxl'
glxinfo -B 2>&1 | head -6
vulkaninfo --summary 2>&1 | head -8
vainfo 2>&1 | head -8
journalctl -b -k | grep -iE 'drm|amdgpu|i915|nvidia|nouveau' | tail -20
```

- 无 `DISPLAY`/`WAYLAND_DISPLAY` 时，`glxinfo` 会报 `Error: unable to open display`，`vainfo` 报 `can't connect to X server!`，`vulkaninfo` 报 `Failed to detect any valid GPUs`——**这些是「没有图形会话/没有 GPU」，不是「驱动装错」**。先确认会话类型，再判断驱动。
- 有图形会话时，`glxinfo -B` 的 `OpenGL renderer string` 是最终答案：出现真实 GPU 型号才算硬件加速，`llvmpipe` 就是软件渲染。
- `lspci -k` 的 `Kernel driver in use:` 一行直接告诉你内核用了哪个模块，比猜包名可靠。

强制软件渲染做对比（用户级、安全）：

```bash
LIBGL_ALWAYS_SOFTWARE=1 glxinfo -B 2>/dev/null | grep -E 'renderer|version'
```

两次输出的渲染器不同，就证明「硬件加速路径确实生效过」，而不是一直靠 CPU 渲染。

## 失败模式

| 现象 | 根因 | 处置 |
| ------------------------------ | ------------------------------------------ | ------------------------------------------------------ |
| `lspci -k` 显示 `Kernel driver in use` 为空 | 驱动包没装或模块被黑名单 | 装对应包、`lsmod` 查模块、检查 `/etc/modprobe.d/` 黑名单 |
| 升级内核后 NVIDIA 报 `module not found` | 闭源模块未随内核重建 | 用 `-dkms` 变体，`dkms status` 确认；或等官方包重建 |
| 开机后 NVIDIA 模块加载失败 | Secure Boot 拒绝未签名模块 | 签名模块或走 MOK 流程（第 61 章），不要直接关 Secure Boot |
| Wayland 下黑屏/闪烁 | `nvidia_drm.modeset` 未开 | 内核参数加 `nvidia_drm.modeset=1`，重建引导配置 |
| 笔记本外接屏无输出 | 显示输出接在独显，渲染在核显 | 用 PRIME 反向方案或 BIOS 切换显示模式 |
| `glxinfo` 一直是 `llvmpipe` | 3D 加速没开 / 虚拟设备不支持 | 虚拟机开 3D；真机确认模块与 ICD 已装 |
| `vainfo` 报 `unknown libva error` | VA-API 驱动未装或代际选错 | Intel 按代际选 iHD/i965；AMD 确认 `mesa` 版本 |
| 装了 `vulkan-intel` 仍找不到设备 | 内核模块未加载 / ICD 清单未生效 | `lsmod` + `vulkaninfo --summary`；核对 `/usr/share/vulkan/icd.d/` |

## 验证与回滚

驱动变更的验证顺序是「模块 → 设备 → 渲染器 → 硬解」：

```bash
lsmod | grep -E 'i915|xe|amdgpu|nvidia|nouveau'
ls -l /dev/dri/
glxinfo -B 2>/dev/null | grep 'OpenGL renderer'
vulkaninfo --summary 2>/dev/null | grep -E 'deviceName|driverName'
vainfo 2>/dev/null | grep -E 'vainfo|VAProfile'
```

`/dev/dri/card*` 与 `renderD*` 存在，说明内核层已暴露设备；`renderer` 出现真实型号，说明用户态链路通了；`vainfo` 列出 profile，才说明硬解可用。三者缺一，问题就定位在对应层。

回滚：

- **驱动包**：`sudo pacman -Rns <驱动包>` 回到 `modesetting`/`nouveau`；删除前记录 `pacman -Q | grep` 的清单，便于重装。
- **内核参数**：从引导配置移除 `nvidia_drm.*`，重新生成（GRUB `grub-mkconfig` / systemd-boot 改 entry），重启验证。
- **Xorg 片段**：删除 `/etc/X11/xorg.conf.d/` 下对应文件，恢复备份。
- **DKMS**：`sudo dkms remove <模块>/<版本> --all`，再重装官方包；不要手工往 `/lib/modules` 里塞 `.ko`。

改动前先 `cp -a /etc/X11/xorg.conf.d /tmp/xorg.bak`、`cp /etc/default/grub /tmp/grub.bak`；图形起不来时用第 81 章的 tty 路径回退。

## 取舍边界

- **开源 vs 专有（NVIDIA）**：`nvidia-open` 在 Turing 之后兼顾 Wayland 与性能；老卡只能 legacy 闭源；`nouveau` 免维护但性能弱。按卡代际与是否需要 CUDA 决定。
- **Mesa 自带 vs 厂商栈（AMD）**：桌面与游戏用 Mesa 足够；需要 ROCm 计算时再装厂商运行时，别为了「齐全」把两套都塞进系统。
- **VA-API vs NVDEC/CUDA**：视频硬解优先 VA-API（Intel/AMD）或 NVDEC（NVIDIA）；跨厂商统一编码用软件 `libx264` 更稳，硬编的画质与兼容性要单独验证。
- **虚拟机 3D vs 稳定**：virgl 能验证合成器与 OpenGL，但性能有限；Vulkan 的 Venus 仍属实验，生产验证不要把虚拟机结论当成真机结论。
- **DKMS vs 官方预编译包**：官方包跟内核版本节奏，升级最稳；自定义内核必须 DKMS，代价是每次内核升级都要确认重建。
- **硬件加速 vs 功耗/发热**：硬解省 CPU 但可能增加 GPU 功耗与驱动复杂度；笔记本上按「续航优先还是兼容优先」取舍。

## 小结

- 驱动链条四层：内核模块 → 固件 → Mesa → Vulkan ICD/VA-API；缺一层就退化。
- Intel 用 `mesa` + `vulkan-intel` + 按代际选 VA-API；AMD 用 `mesa` + `vulkan-radeon`，硬解由 Mesa 提供；NVIDIA 用 `nvidia-open` + `nvidia-utils`，Turing 之前走 legacy。
- NVIDIA 的 `nvidia_drm.modeset=1` 是 Wayland 的前提；内核升级后要确认 DKMS 重建。
- 虚拟机只用 `mesa` 与 `virtio-gpu`，不要装厂商驱动；`virgl` 才代表 3D 生效。
- 判断路径的顺序：`lspci -k` → `/dev/dri` → `glxinfo -B` → `vulkaninfo`/`vainfo`。
- 无图形会话时 `glxinfo`/`vainfo` 失败是正常现象，不要误判为驱动故障。

1. 路径辨认：跑正文六条只读命令，写出「内核模块、渲染器、Vulkan 设备、VA-API」四项的实际结果，并指出哪一层缺失。
2. 软件渲染对比：在有图形会话时分别跑 `glxinfo -B` 与 `LIBGL_ALWAYS_SOFTWARE=1 glxinfo -B`，记录两次 `renderer` 的差异并解释。
3. 代际选包：查你机器的 CPU/GPU 代际，说明 Intel 该选 `intel-media-driver` 还是 `libva-intel-driver`，AMD 为什么不需要额外 VA-API 包。
4. 虚拟机设备：在虚拟机设置里切换 `virtio-gpu` 与 `qxl`，各跑一次 `glxinfo -B`，说明 3D 加速与 2D 设备的差别（无 GUI 时写出手动步骤并标未实测）。
