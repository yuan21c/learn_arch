# 第 81 章 图形栈与显示服务器

前六章都在命令行里。这一章讲图形栈：从内核的显示驱动到窗口系统，再到桌面环境。**动手实验默认可在虚拟机完成**——自带虚拟显卡与显示服务，足以完成大部分桌面实验；显卡驱动与混合显卡等真机部分不要求实机完成，单独说明「需要真机」并标为选做。

> 本章目标：能说清「内核 DRM/KMS → 显示服务器 → 窗口管理器/桌面环境」的三层结构；能区分 X11 与 Wayland 的架构差异与各自的兼容性问题；能在虚拟机里装好一个最小图形环境并排障（黑屏、无信号、登录循环）；知道显卡驱动的三种选择（开源、专有、混合显卡）以及虚拟机里该用哪一类。
> 对应 Wiki：[Xorg](https://wiki.archlinux.org/title/Xorg)、[Wayland](https://wiki.archlinux.org/title/Wayland)、[Desktop environment](https://wiki.archlinux.org/title/Desktop_environment)

## 图形栈的三层

```text
应用 → 工具包（GTK/Qt）→ 显示服务器（X11 或 Wayland）→ 合成器 → 内核 DRM/KMS → 显卡驱动 → 显示输出
```

三个概念必须先分清：

- **DRM/KMS**：内核里的显示子系统，负责设置分辨率、模式、扫描输出；驱动（`i915`、`amdgpu`、`nouveau`、`virtio-gpu`）都挂在这里。
- **显示服务器**：X11 是一套独立服务（`Xorg`），应用通过 X 协议连它；Wayland 是协议，合成器（`sway`、`KWin`、`GNOME Shell`）同时充当服务器。
- **桌面环境**：窗口管理 + 面板 + 设置 + 文件管理器 + 一套应用（GNOME、KDE Plasma、Xfce）。

理解这三层，才能判断「黑屏」是哪一层的问题：内核日志有输出说明 DRM 起来了；能看到登录界面说明显示服务器起来了；登录后回到登录界面，通常是桌面环境的会话或驱动问题。

## X11 与 Wayland

| 维度 | X11 | Wayland |
| ---------- | ------------------------------ | ----------------------------- |
| 架构 | 独立服务 + 客户端 | 合成器即服务器，协议直连 |
| 输入与显示 | 全局抓取容易（也意味着不安全） | 按窗口隔离，抓屏需授权 |
| 混成与撕裂 | 需合成器（如 `picom`） | 合成是协议的一部分 |
| 兼容性 | 几乎所有老程序 | XWayland 兜底，个别程序仍异常 |
| 多屏/缩放 | 配置繁琐 | 按输出独立缩放，体验更好 |
| 远程/串流 | 成熟（`x11vnc` 等） | 方案较新，支持参差 |

结论：新装环境优先 Wayland；需要特定老软件、远程桌面或输入法兼容性时，X11 仍是稳妥选择。两者在 Arch 上可以共存（登录界面里选会话），不必二选一装系统。

## 最小图形环境（VM）

先只装 Xorg 与一个轻量窗口管理器，把链路跑通，再上桌面环境：

```bash
sudo pacman -S xorg-server xorg-xinit xterm xorg-twm xorg-xclock
startx
```

`xorg-xinit` 提供 `startx`，它读 `~/.xinitrc`；**没有这个文件时用系统默认的 `/etc/X11/xinit/xinitrc`（启动 `twm`、`xclock` 与两个 `xterm`，所以 `xorg-twm`/`xorg-xclock` 必须装上，否则报 command not found）**。虚拟机里一律用内核 `modesetting` 驱动（配合 `virtio-gpu`/`qxl`/`vmwgfx` 设备）——只有 VMware 的 `xf86-video-vmware` 已不在官方仓库（`pacman -Si xf86-video-vmware` 查无此包，需要时找 AUR）；`xf86-video-qxl`、`xf86-video-amdgpu` 等仍有对应包。但现代 Xorg 默认走 `modesetting`，厂商 DDX 只在特定设备或旧硬件需要时再装，以 `pacman -Ss xf86-video-<厂商>` 与 `Xorg.0.log` 的实际加载结果为准。自写最小 `~/.xinitrc` 只要一行：

```bash
exec twm # 或 exec dbus-run-session -- startplasma-x11 等桌面会话
```

确认驱动走的是哪条路：

```bash
lspci -k | grep -A3 -E 'VGA|3D' # 看设备与内核在用哪个驱动
sudo journalctl -b -k | grep -Ei 'drm|kms'
glxinfo | grep 'OpenGL renderer' # 需要 mesa-utils
```

看到 `llvmpipe` 说明在用**软件渲染**——能跑，但慢；看到 `virgl` 或真实 GPU 名字才算硬件加速。

## 桌面环境与显示管理器

- **桌面环境**：`gnome`、`plasma-meta`（KDE）、`xfce4`。功能与资源占用递减。
- **显示管理器（DM）**：登录界面与图形会话启动器，`gdm`（GNOME）、`sddm`（KDE/通用）、`lightdm`（轻量）。也可以不用 DM，用 `startx` 或 `exec dbus-run-session -- gnome-session` 手动启动。

```bash
sudo systemctl enable --now gdm # 装好后重启进入图形登录
```

`enable` 一个 DM 只是加自启链接，**不会自动把默认 target 改成图形**——用 `systemctl get-default` 确认，仍是 `multi-user.target` 就 `sudo systemctl set-default graphical.target` 再重启。想临时回纯命令行（排障常用）：`systemctl isolate multi-user.target`（只影响本次启动），或引导菜单加 `systemd.unit=multi-user.target`（第 18、58 章）。

虚拟机里的推荐路径：先用 `startx` + 轻量 WM 验证链路，再装桌面环境；不要一上来就装完整 GNOME——一旦黑屏，你很难判断是驱动、DM 还是会话的问题。

## 显卡驱动：三种选择

> 下表驱动选型针对真机（需要真机）；虚拟机用 `virtio-gpu`/`modesetting`，见最后一行。

| 场景 | 驱动 | 说明 |
| ---------- | ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Intel 核显 | 内核 `i915`/`xe` + 用户态 `mesa` | 免配置，Wayland 支持好；Vulkan 装 `vulkan-intel`，VA-API 按代际选 `intel-media-driver`/`libva-intel-driver` |
| AMD | 内核 `amdgpu` + `mesa` + `vulkan-radeon` | 开源栈成熟 |
| NVIDIA | `nvidia-open`/`nvidia-open-dkms` + `nvidia-utils` | Turing 及以后用开源内核模块，参数加 `nvidia_drm.modeset=1`；旧卡走 AUR legacy；`nouveau` 内核模块随内核提供，Xorg 下可选装 `xf86-video-nouveau`，现多用 modesetting |
| 虚拟机 | `mesa` + `modesetting`/`virtio-gpu` | 不要装厂商专有驱动 |

混合显卡（笔记本双显卡）用 `optimus` 方案或 `prime-run` 按程序切换；这是真机话题，虚拟机里不涉及。

## 黑屏与登录循环的排查

| 现象 | 先查 |
| ---------------------------- | ----------------------------------------------------------------- |
| 引导后完全黑屏、无光标 | 内核参数加 `nomodeset` 试进；看 `journalctl -b -k` 的 DRM 报错 |
| 有登录界面，登录后黑屏回登录 | 会话配置/桌面环境依赖缺失；换 `startx` 手工启动看终端报错 |
| 分辨率不对、只有低分辨率 | 驱动未加载（在用 `llvmpipe`）；检查 `lspci -k` 与 `journalctl -k` |
| 花屏、随机闪烁 | 驱动/固件问题；虚拟机换显示设备（qxl/virtio/vmware）对比 |
| 鼠标键盘无响应 | 输入驱动与 `/dev/input` 权限；Wayland 下看合成器日志 |

X11 的日志在 `/var/log/Xorg.0.log`（或 `~/.local/share/xorg/`），Wayland 各合成器的日志进 journal。**先看日志再改配置**，图形问题最忌凭猜测反复重启。

## 失败模式

| 现象 | 根因层 | 处置 |
| ------------------------------ | ---------------------- | ------------------------------------------------------ |
| 引导后全黑、无光标，SSH 仍能进 | 内核 DRM/驱动未起 | 内核参数临时加 `nomodeset` 进系统，看 `journalctl -b -k` 的 DRM 报错 |
| 有登录界面，登录后闪回登录页 | 会话/桌面环境启动失败 | 换 `startx` 或 `exec dbus-run-session -- <会话>` 在 tty 手工启动，读终端报错 |
| 分辨率只有 1024×768 且不可调 | 驱动未接管，走 `llvmpipe` | `glxinfo -B` 确认渲染器；核对 `lspci -k` 与 `journalctl -k` |
| 花屏/随机闪烁 | 驱动或虚拟显示设备不匹配 | 虚拟机换 `qxl`/`virtio`/`vmware` 设备对比；真机看驱动版本 |
| 图形界面卡死但键盘无响应 | 合成器/会话挂起 | 切 tty（`Ctrl+Alt+F3`），重启 DM 或 `systemctl restart <dm>` |
| 装完第二个 DM 后进错登录界面 | 两个 DM 都在抢显示 | `systemctl disable --now` 其中一个，见第 86 章 |

两个高频人为失误：**在同一台机器上同时按 X11 与 Wayland 两套教程改配置**，导致 `xorg.conf.d` 的驱动选项与合成器行为互相矛盾；**没备份 `xorg.conf.d` 就批量改**，出问题后无法快速回到已知可用状态。

## 验证与回滚

图形栈的验证分三层，一次至少看两层的证据：

```bash
echo "$XDG_SESSION_TYPE" # x11 / wayland / tty
journalctl -b -k | grep -iE 'drm|kms' | tail -20
ps -o comm= -C Xorg 2>/dev/null || echo "无 Xorg 进程"
glxinfo -B 2>/dev/null | head -12
```

没有 `DISPLAY`/`WAYLAND_DISPLAY` 时 `glxinfo`、`wayland-info` 会直接报 `unable to open display`——这本身就说明当前是纯 tty，不是显卡故障。判断顺序是「会话类型 → 内核 DRM → 渲染器」，不要一上来就重装驱动。

回滚按「先回会话、再回配置、最后回驱动」：

```bash
sudo systemctl isolate multi-user.target # 图形起不来时先回命令行
cp -a /etc/X11/xorg.conf.d /tmp/xorg.conf.d.bak # 改之前先备份
sudo rm /etc/X11/xorg.conf.d/20-mydriver.conf # 撤销单条配置
sudo pacman -Rns <刚装的驱动包> # 驱动层面回退
```

`isolate multi-user.target` 只影响本次启动，重启仍回图形；要长期回命令行用 `set-default multi-user.target`。删除驱动包后 nouveau/modesetting 通常会自动接管，重启前先确认 `lsmod` 与 `journalctl -k` 不再引用旧模块。

## 取舍边界

- **X11 vs Wayland**：老软件、远程桌面、输入法兼容优先选 X11；新硬件、多屏不同缩放、安全隔离优先选 Wayland。两者可共存，按会话切换而不是重装系统。
- **轻量 WM vs 完整 DE**：排障与验证链路用 `twm`/`sway`/`openbox`，依赖少、日志清楚；日常使用要面板、设置中心、文件管理器时再上 DE（第 85 章）。
- **软件渲染 vs 硬件加速**：虚拟机或无 GPU 环境下 `llvmpipe` 足以跑桌面与验证配置，只是慢；只有视频解码、游戏、3D 才值得为硬件加速折腾驱动。
- **虚拟机 3D 加速 vs 稳定性**：开 3D 能测 Wayland 合成器与 OpenGL 应用，但宿主/驱动组合不稳时先关掉，把图形问题与虚拟化问题分开定位。
- **一个 DE vs 多 DE 并存**：多装几套便于对比，但会带来会话文件、portal、主题的冲突；生产或日常机只留一套。

## 小结

- 三层结构：DRM/KMS（内核）→ 显示服务器/合成器 → 桌面环境；判断故障先定位层。
- X11 独立服务、兼容性好；Wayland 合成器即服务器、隔离与缩放更好；两者可共存。
- 虚拟机里用 `mesa` + `modesetting`/`virtio-gpu`，看到 `llvmpipe` 就是软件渲染。
- 先 `startx` + 轻量 WM 验证链路，再装桌面环境与 DM。
- 驱动按硬件选：Intel/AMD 用内核模块 + `mesa`，NVIDIA 用 `nvidia-open` 系 + `nvidia-utils`，虚拟机不用专有驱动。
- 黑屏先 `nomodeset` + 看 `journalctl -k`/`Xorg.0.log`，不要盲改配置。

## 练习

1. 三层辨认：装好最小 X 环境后，分别用 `journalctl -b -k | grep -i drm`、`ps aux | grep -E 'Xorg|wayland'`、`echo $XDG_SESSION_TYPE` 找出三层各自的证据。
2. X11 与 Wayland：装一个 Wayland 合成器（如 `sway`）与 Xorg，在登录界面切换会话各进一次，记录 `echo $XDG_SESSION_TYPE` 与常用程序的表现差异。
3. 渲染路径：`glxinfo | grep 'OpenGL renderer'`，判断是软件还是硬件渲染；再切换到另一种虚拟显示设备，对比结果。
4. 无 DM 启动：不启用任何 DM，用 `startx` + `~/.xinitrc` 启动一个 WM，验证 `graphical.target` 与手工启动的差别。
5. 黑屏排查：故意把 `~/.xinitrc` 写错一行，重现「启动后立刻回命令行」，从终端输出与 `Xorg.0.log` 找出错误行。
6. 驱动核对：`lspci -k | grep -A3 VGA` 与 `lsmod | grep -E 'virtio|qxl|vmwgfx|i915|amdgpu'`，说明当前虚拟机用的是哪条驱动路径。
