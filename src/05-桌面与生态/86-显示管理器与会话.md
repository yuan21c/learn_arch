# 第 86 章 显示管理器与会话

第 85 章装了桌面环境，但「装完重启却停在黑底白字的登录提示符」是最常见的落差。原因往往不在桌面，而在**显示管理器（DM）与默认 target**。这一章讲 DM 的职责、会话文件、`logind` 会话，以及「`enable` 了 DM 为什么还是进不了图形」。

> 本章目标：能说出 DM 的四个职责（登录界面、认证、启动会话、会话登记）；能在 GDM、SDDM、LightDM、greetd 之间按桌面与需求选择；理解 `enable` DM 与 `set-default graphical.target` 是两件不同的事；知道 `/usr/share/xsessions` 与 `/usr/share/wayland-sessions` 的作用；会用 `loginctl` 查看会话类型与来源；能识别「启用了 DM 却进 tty」「两个 DM 抢显示」「自动登录配置错」三类问题。
> 对应 Wiki：[Display manager](https://wiki.archlinux.org/title/Display_manager)、[GDM](https://wiki.archlinux.org/title/GDM)、[SDDM](https://wiki.archlinux.org/title/SDDM)、[LightDM](https://wiki.archlinux.org/title/LightDM)、[Greetd](https://wiki.archlinux.org/title/Greetd)

## DM 做什么

| 职责 | 说明 | 失败时的表现 |
| ---------------------- | ------------------------------------------------ | ------------------------------ |
| 提供登录界面（greeter） | 图形或文本的账号/密码输入 | 黑屏、只显示背景 |
| 认证 | 通常通过 PAM，复用系统账号与密码策略 | 密码正确也被拒 |
| 启动会话 | 按用户选择执行 `xsessions`/`wayland-sessions` 里的 `Exec` | 登录后闪回登录界面 |
| 登记会话 | 通过 `logind` 创建 session，供权限与设备访问使用 | 音频/设备权限异常 |

DM 本身不是桌面的一部分：GDM 来自 GNOME、SDDM 来自 KDE，但**任何 DM 都能启动任何会话**（只要会话文件存在）。这就是「装 KDE 却用 GDM 登录 Plasma」也能工作的原因。

## 选型

| DM | 生态 | 界面技术 | 特点 | 适合 |
| -------------- | ---------- | ---------------- | ------------------------------------------ | ------------------------------ |
| GDM | GNOME | GTK / Wayland | 与 GNOME 集成最好，Wayland 会话成熟 | GNOME 用户、要开箱即用 |
| SDDM | KDE | QML | 主题多、可换主题，配置简单 | Plasma 用户、要自定义登录界面 |
| LightDM | 通用 | GTK/Qt/文本 | 轻量、greeter 可换 | Xfce/轻量桌面、老机器 |
| greetd | 通用 | 文本/自定义 | 无图形依赖，配 `tuigreet` 等前端 | 极简、服务器带图形、脚本化 |
| plasma-login-manager | KDE | Qt | KDE 提供的登录管理器，可替代 SDDM | 想跟随 Plasma 官方组件的用户 |

选择原则：**跟桌面生态走**（GNOME→GDM、Plasma→SDDM/PLM），减少主题与 portal 的适配问题；极简或远程场景用 greetd，连图形 greeter 都不要。

## 启用 DM ≠ 默认进图形

这是本章最重要的一条。`systemctl enable sddm` 只是把 DM 挂到 `graphical.target` 上；**如果系统默认 target 仍是 `multi-user.target`，开机根本不会启动它**。

本机的真实现场：

```bash
systemctl get-default
# multi-user.target

ls -l /etc/systemd/system/display-manager.service
# -> /usr/lib/systemd/system/sddm.service

systemctl status display-manager --no-pager | head -6
# Loaded: ... sddm.service; enabled
# Active: inactive (dead)
```

`display-manager.service` 已指向 sddm 且处于 `enabled`，但默认 target 是 `multi-user`，所以 sddm 没有启动，SSH 登录进去看到的是 tty。**这不是 DM 坏了，是 target 没切**。

```bash
sudo systemctl enable --now sddm # 立即启动并开机自启
sudo systemctl set-default graphical.target # 让下次开机进图形
systemctl get-default # 复核
```

反过来，排障时想临时回命令行：

```bash
sudo systemctl isolate multi-user.target # 只影响本次启动
```

`isolate` 不会改默认 target，重启仍回图形；要长期回命令行才用 `set-default multi-user.target`。

## 会话文件：登录界面能选什么

DM 读取两个目录生成会话列表：

```bash
ls /usr/share/xsessions/ 2>&1
ls /usr/share/wayland-sessions/ 2>&1
cat /usr/share/wayland-sessions/plasma.desktop
```

一个会话文件就是一个 `.desktop`：

```ini
[Desktop Entry]
Name=Plasma (Wayland)
Exec=/usr/lib/plasma-dbus-run-session-if-needed /usr/bin/startplasma-wayland
TryExec=/usr/bin/startplasma-wayland
DesktopNames=KDE
Type=Application
```

- `Exec` 是真正启动会话的命令；`TryExec` 用于「程序不存在就隐藏该会话」。
- `DesktopNames` 会变成 `XDG_CURRENT_DESKTOP`，是应用判断「当前是哪个桌面」的依据。
- 会话缺失或 `Exec` 指向不存在的程序时，登录界面里看不到该选项，或选了之后闪退回登录页。

## 会话与 logind

登录成功后，`logind` 会登记一个 session，记录类型与来源：

```bash
loginctl list-sessions
loginctl show-session 1 -p Type -p Class -p Active -p Remote
```

本机 SSH 会话的实际输出：

```text
Remote=yes
Type=tty
Class=user
Active=yes
```

- `Type`：`tty`/`x11`/`wayland`/`unspecified`；判断「到底进了哪种会话」比看环境变量更权威。
- `Class`：`user` 是普通登录，`greeter` 是 DM 的登录界面会话，`manager` 是系统管理会话。
- `Remote=yes` 表示来自 SSH/远程，本地图形会话通常是 `no`。
- `Active`/`State` 用来判断会话是否还活着；`loginctl terminate-session <id>` 可结束指定会话。

会话类型也决定设备权限：音频、亮度、电源键通常只授予「当前活跃的本地会话」，远程 tty 会话拿不到，这就是「SSH 里调亮度失败」的原因。

## 自动登录：方便与风险的交换

自动登录配置因 DM 而异：

```ini
# /etc/sddm.conf.d/autologin.conf
[Autologin]
User=y2c
Session=plasma
```

```ini
# /etc/gdm/custom.conf
[daemon]
AutomaticLoginEnable=True
AutomaticLogin=y2c
```

```ini
# /etc/lightdm/lightdm.conf
[Seat:*]
autologin-user=y2c
autologin-session=xfce
```

自动登录意味着**任何能物理接触机器的人直接进入你的账号**；它只适合 kiosk、单用户虚拟机、无敏感数据的演示机。需要「开机即图形但仍要密码」时，正确做法是启用 DM + `graphical.target`，而不是自动登录。

## 可复现实验：只看状态，不改系统

```bash
systemctl get-default
readlink -f /etc/systemd/system/display-manager.service
systemctl status display-manager --no-pager | head -8
ls /usr/share/xsessions/ /usr/share/wayland-sessions/ 2>&1
loginctl list-sessions
loginctl show-session 1 -p Type -p Class -p Remote -p Active
systemctl list-unit-files --state=enabled | grep -E 'gdm|sddm|lightdm|greetd'
```

**预期**：本机 `get-default` 是 `multi-user.target`，`display-manager.service` 指向已 `enabled` 的 sddm，但 sddm 处于 `inactive (dead)`——正好演示「enable 了但没进图形」。若你的机器同时列出两个已启用的 DM，说明存在抢显示的风险，见失败模式第一条。

## 失败模式

| 现象 | 根因 | 处置 |
| ------------------------------ | ------------------------------------------ | ------------------------------------------------------ |
| 开机停在 tty，`display-manager` 却是 enabled | 默认 target 仍是 `multi-user` | `set-default graphical.target` 后重启 |
| 两个 DM 都在 enabled，登录界面忽好忽坏 | 两个服务都写 `display-manager.service` 链接 | 只保留一个：`systemctl disable --now` 另一个 |
| 登录后立刻闪回登录界面 | 会话 `Exec` 失败/依赖缺失 | 切 tty 手工跑 `Exec` 命令看报错（第 81 章） |
| 登录界面没有想要的会话 | 会话文件缺失或 `TryExec` 不存在 | 检查 `/usr/share/*sessions` 与 `Exec` 路径 |
| 自动登录不生效 | 用户名/会话名写错，或 DM 配置文件位置不对 | 查对应 DM 的 journal 与配置路径 |
| 密码正确但登录被拒 | PAM/账号被锁/家目录权限 | `journalctl -u <dm>` 与 `passwd -S` 排查 |
| DM 崩溃后黑屏 | DM 进程退出，未回 tty | `Ctrl+Alt+F3` 切 tty，`systemctl restart <dm>` |
| 远程桌面能连但音频/亮度不可用 | 远程会话不是本地活跃会话 | 用本地会话或专用远程方案（第 26 章） |

## 验证与回滚

验证「DM 真的接管了图形启动」：

```bash
systemctl get-default
systemctl is-enabled <dm>
systemctl is-active <dm>
loginctl list-sessions
journalctl -u <dm> -b --no-pager | tail -20
```

四项分别对应「默认 target、开机自启、当前状态、会话登记、启动日志」。`is-enabled` 为 `enabled` 但 `is-active` 为 `inactive`，几乎一定是 target 没切或服务被手动停了。

回滚：

```bash
sudo systemctl disable --now <dm>
sudo systemctl set-default multi-user.target
sudo rm /etc/sddm.conf.d/autologin.conf # 撤销自动登录
sudo systemctl isolate multi-user.target # 立即回 tty
```

删除 DM 包之前先 `disable`，否则 `display-manager.service` 会留下悬空链接；发现链接指向已删除的服务时，重装任一 DM 或手工修正链接后再切换。

## 取舍边界

- **DM vs `startx`**：DM 提供图形登录、会话选择、自动登录；单用户开发机用 `startx` 更轻、更少故障点。服务器不需要图形登录时不要装 DM。
- **GDM/SDDM/LightDM/greetd**：跟桌面生态选最省事；要主题化选 SDDM；要极简选 greetd；LightDM 适合轻量 X11 桌面。
- **自动登录 vs 密码登录**：自动登录省一次输入，换来物理接触即失守；只在无敏感数据的场景使用。
- **`graphical.target` vs `multi-user.target`**：日常桌面机设 `graphical`；服务器、排障机设 `multi-user`，需要图形时再 `isolate`。
- **一个 DM vs 多个 DM**：多装可以对比，但同时启用必然冲突；保留一个启用，其余只装不启用。
- **本地会话 vs 远程会话**：设备权限（音频、亮度、电源）偏向本地活跃会话；远程需求要用 SSH 转发或专用远程桌面，不要指望 logind 给远程会话同等权限。

## 小结

- DM 四职责：登录界面、PAM 认证、启动会话、logind 登记。
- `enable` DM 只挂到 `graphical.target`；默认 target 是 `multi-user` 时开机不会启动它。
- 会话由 `/usr/share/xsessions` 与 `/usr/share/wayland-sessions` 的 `.desktop` 定义，`Exec` 决定启动命令。
- `loginctl` 的 `Type`/`Class`/`Remote` 比环境变量更能说明「当前是什么会话」。
- 自动登录是物理安全的交换，只适合 kiosk/演示/无敏感数据环境。
- 回滚顺序：停 DM → 改回 `multi-user` → 删自动登录配置 → `isolate`。
