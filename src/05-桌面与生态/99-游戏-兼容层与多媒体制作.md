# 第 99 章 游戏、兼容层与多媒体制作

游戏与内容创作是桌面 GPU 压力的两个极端：前者要**低延迟、32 位兼容、反作弊**，后者要**稳定、大内存、硬件编码**。它们的共同点是都高度依赖第 82 章的驱动链条——驱动不对，后面全是白费。

> 本章目标：知道 Steam 位于 `multilib` 仓库、启用它需要改 `pacman.conf`；理解 Proton/Wine 的兼容层原理与 DXVK/VKD3D 的作用；能按「原生 / Proton / Lutris / 模拟器」选择运行方式；知道 32 位图形库（`lib32-*`）为什么是游戏的前提；能区分 Blender、Kdenlive、DaVinci Resolve 的定位；会验证 Vulkan、驱动与 multilib 状态；能识别「Steam 装不上」「游戏启动即崩」「反作弊拦截」三类问题。
> 对应 Wiki：[Steam](https://wiki.archlinux.org/title/Steam)、[Proton](https://wiki.archlinux.org/title/Proton)、[Wine](https://wiki.archlinux.org/title/Wine)、[Lutris](https://wiki.archlinux.org/title/Lutris)、[Blender](https://wiki.archlinux.org/title/Blender)、[Kdenlive](https://wiki.archlinux.org/title/Kdenlive)

## 兼容层的层次

| 层 | 作用 | 例子 |
| ---------------- | ------------------------------------------------ | ------------------------------ |
| Wine | 在 Linux 上实现 Win32 API | `wine`、`wine-staging` |
| Proton | Valve 定制的 Wine + DXVK/VKD3D + 补丁 | Steam 内置 Proton |
| 图形翻译 | 把 D3D 调用翻译到 Vulkan | DXVK（D3D9/10/11）、VKD3D（D3D12） |
| 启动器/前缀管理 | 管理不同游戏的前缀与环境 | Lutris、Steam Play |

- **Wine** 负责「让 Win32 程序以为自己在原生环境」；**DXVK/VKD3D** 负责把图形调用转成 Vulkan。两者组合才让 3D 游戏能跑。
- **Proton** 是打包好的组合，随 Steam 更新；手动 Wine 调优适合非 Steam 程序。
- **Lutris** 是启动器，帮你管理前缀、安装脚本与运行库；它不替代 Wine，只是组织者。

## multilib：32 位是前提

大量商业游戏是 32 位的，需要 32 位图形库：

```bash
grep -n -A4 '^\[multilib\]' /etc/pacman.conf
pacman -Si steam 2>&1 | head -3
```

**本机实测**：`/etc/pacman.conf` 里没有启用的 `[multilib]` 段，因此 `pacman -Si steam` 找不到包。启用方式（**改系统配置，未实测**）：

```ini
[multilib]
Include = /etc/pacman.d/mirrorlist
```

改完 `sudo pacman -Syu`，再装 `steam` 与对应 32 位驱动：

```bash
sudo pacman -S lib32-mesa lib32-vulkan-radeon # AMD/Intel
sudo pacman -S lib32-nvidia-utils # NVIDIA
```

- 只装 64 位驱动，32 位游戏会报「找不到 Vulkan/OpenGL」。
- Intel 核显的 32 位 Vulkan 由 `lib32-vulkan-intel` 提供；AMD 用 `lib32-vulkan-radeon`。
- 不启用 multilib 时，Steam 与部分 Proton 组件无法安装，这不是「包坏了」。

## 运行方式选型

| 方式 | 适用 | 优点 | 代价 |
| -------------- | ------------------------------ | ------------------------------ | ------------------------------ |
| 原生 Linux | 有 Linux 版且反作弊支持 | 性能最好、最稳定 | 游戏数量有限 |
| Steam + Proton | Steam 库里的 Win32 游戏 | 开箱即用、自动更新 | 反作弊与个别游戏兼容 |
| Lutris + Wine | 非 Steam、老游戏、独立客户端 | 脚本化、可调前缀 | 要自己排错 |
| 模拟器 | 主机/掌机老游戏 | 体验接近原机 | 需要 BIOS/ROM 与配置 |

反作弊（EAC/BattlEye）是硬边界：**游戏标明「不支持 Proton」时，任何兼容层都绕不过**，除非厂商主动支持。不要在竞技游戏里尝试绕过反作弊。

## 辅助工具

- **MangoHud**：叠加帧率/温度/占用，用 `mangohud %command%` 启动。
- **GameMode**：游戏运行时临时切 CPU governor、提优先级；`gamemoderun %command%`。
- **Proton 版本管理**：Steam 里可切换 Proton 版本；社区版（如 Proton-GE）适合需要额外补丁的游戏，来源要可信。

```bash
mangohud --version 2>/dev/null
gamemoded -s 2>/dev/null
vulkaninfo --summary 2>&1 | grep -E 'deviceName|driverName' | head -6
```

`vulkaninfo` 能看到设备与驱动版本，是「Proton 能不能跑」的前置条件；`vulkaninfo` 失败时先修驱动（第 82 章），不要归咎于 Proton。

## 多媒体制作

| 工具 | 用途 | 特点 | 来源 |
| -------------- | ------------------------------ | ------------------------------ | ------------------------------ |
| Blender | 3D 建模/渲染/合成 | 开源、GPU 渲染、脚本化 | 官方仓库 |
| Kdenlive | 视频剪辑 | 开源、MLT 框架、硬件编码 | 官方仓库 |
| DaVinci Resolve | 专业剪辑/调色 | 功能强、对 GPU 与驱动挑剔 | AUR/厂商包 |
| Ardour | 音频制作 | 低延迟、JACK/PipeWire | 官方仓库（第 89 章） |

制作类工具对驱动与显存更敏感：DaVinci Resolve 在 Linux 上对 GPU 型号与 OpenCL/CUDA 有明确要求，装前先查官方支持列表；Blender 的 Cycles 可用 CUDA/OptiX 或 HIP，渲染前用 `blender -b` 做小样验证。

## 可复现实验：仓库、驱动与 Vulkan

```bash
grep -c '^\[multilib\]' /etc/pacman.conf
pacman -Si blender | grep -E 'Repository|Version' | head -2
pacman -Si kdenlive | grep -E 'Repository|Version' | head -2
pacman -Ss steam 2>&1 | head -3
vulkaninfo --summary 2>&1 | head -12
glxinfo -B 2>&1 | head -6
```

本机结果：`grep -c '[multilib]'` 为 0（未启用），`pacman -Ss steam` 无输出；`blender`/`kdenlive` 在官方仓库；`vulkaninfo`/`glxinfo` 在没有 GPU 与图形会话时报初始化失败。**这些失败是环境状态，不是配置错误**——先看有没有会话与 GPU。

## 失败模式

| 现象 | 根因 | 处置 |
| ------------------------------ | ------------------------------------------ | ------------------------------------------------------ |
| `pacman -S steam` 找不到包 | 未启用 `multilib` | 按上文启用并 `-Syu`，再装 32 位驱动 |
| 游戏启动即崩、日志报 Vulkan 缺失 | 缺 32 位 Vulkan/驱动 | 装 `lib32-vulkan-*` 与对应 `lib32-*-utils` |
| Proton 游戏黑屏 | 驱动/Proton 版本不兼容 | 换 Proton 版本，开/关 DXVK，先 `vulkaninfo` |
| 反作弊提示不支持 | 兼容层无法通过反作弊 | 放弃该游戏或双系统，不要尝试绕过 |
| 着色器编译卡顿 | 首次运行编译缓存 | 允许预编译/下载缓存，后续会改善 |
| 手柄/音频设备不识别 | 权限/协议/Steam Input 配置 | 查 `lsusb`、Steam Input 设置、会话类型 |
| DaVinci 启动报 GPU 不支持 | 驱动/OpenCL 不满足要求 | 按官方支持列表换驱动或显卡 |
| Kdenlive 导出很慢 | 用了软件编码 | 开硬件编码（第 90 章），确认编码器可用 |

## 验证与回滚

```bash
grep -A3 '^\[multilib\]' /etc/pacman.conf
pacman -Q lib32-mesa lib32-vulkan-radeon 2>&1
vulkaninfo --summary 2>&1 | grep -E 'apiVersion|driverVersion' | head -4
mangohud --version 2>/dev/null
```

「multilib 是否启用、32 位驱动是否在、Vulkan 版本、叠加工具是否可用」四项决定游戏能否启动。真正的验收是**进游戏跑 10 分钟**，看帧率、温度与是否崩溃。

回滚：

- 关掉 multilib 不会破坏系统，但已装的 32 位包会变成孤儿，需 `pacman -Qtdq` 清理。
- Proton 前缀损坏：删除对应 `compatdata` 目录让 Steam 重建（会丢该游戏存档，先备份）。
- 驱动回退按第 82 章；`MangoHud`/`GameMode` 卸载用 `pacman -Rns`。

## 取舍边界

- **原生 vs Proton**：有原生版优先原生；只有 Win32 版才用 Proton。
- **Steam vs Lutris**：Steam 库内游戏用 Steam；库外、老游戏、独立客户端用 Lutris。
- **双系统 vs 兼容层**：反作弊游戏与专业 Win32 软件用双系统；其余尽量兼容层，避免重启切换。
- **性能 vs 画质**：Proton 的 DXVK 可能有少量性能损失；追求极限帧率时调低画质或等原生支持。
- **发行版包 vs 厂商二进制**：Blender/Kdenlive 走仓库；DaVinci 只能厂商包/AUR，接受更新风险。
- **硬件编码 vs 软件编码**：硬件快但画质/兼容性要验证；交付母版可用软件编码。

## 小结

- 兼容层四层：Wine、Proton、DXVK/VKD3D、启动器；Proton 是打包组合。
- Steam 在 `multilib`，需改 `pacman.conf` 并装 32 位图形库；本机未启用是实测事实。
- 反作弊是硬边界，标「不支持」的游戏不要尝试绕过。
- Blender/Kdenlive 在官方仓库；DaVinci Resolve 在 AUR/厂商渠道，驱动要求高。
- `vulkaninfo` 与 32 位驱动是游戏的前置条件；先修驱动再排兼容层。
- 辅助工具 MangoHud/GameMode 只做监控与调度，不解决兼容性问题。
