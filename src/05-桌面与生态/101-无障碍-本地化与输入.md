# 第 101 章 无障碍、本地化与输入

这是第五篇的最后一章。前面各章分别讲了桌面、主题、字体、输入法与工具；这一章把它们收束到两个问题：**系统是否按你的语言与习惯工作**，以及**不同能力的人是否都能用**。本地化不只是「装个中文包」，无障碍也不只是「装个读屏软件」。

> 本章目标：理解 `LANG` 与 `LC_*` 的分工及 `locale.gen` 的作用；会用 `localectl`/`locale`/`locale -a` 验证本地化状态；知道「界面语言」与「输入中文」是两件不同的事；能配置 CJK/emoji 字体并验证匹配；知道 Orca、放大镜、高对比度、`org.a11y.Bus` 各自解决什么；能识别「locale 未生成」「中文显示方块」「读屏没声音」三类问题。
> 对应 Wiki：[Locale](https://wiki.archlinux.org/title/Locale)、[Localization](https://wiki.archlinux.org/title/Localization)、[Accessibility](https://wiki.archlinux.org/title/Accessibility)、[Fonts](https://wiki.archlinux.org/title/Fonts)

## locale 体系：一个总开关加若干分项

| 变量 | 控制什么 | 举例 |
| ---------- | ------------------------------ | ------------------------------ |
| `LANG` | 未单独设置的 `LC_*` 的默认值 | `zh_CN.UTF-8` |
| `LC_TIME` | 日期/时间格式 | `en_GB.UTF-8` |
| `LC_NUMERIC` | 小数点与千分位 | `de_DE.UTF-8` |
| `LC_COLLATE` | 排序规则 | `zh_CN.UTF-8` |
| `LC_MESSAGES` | 界面翻译语言 | `zh_CN.UTF-8` |
| `LC_ALL` | 强制覆盖以上全部 | 排障临时用，不写进配置 |

生成与设置：

```bash
locale
locale -a | head -10
sudo grep -n '^#\?zh_CN' /etc/locale.gen
sudo locale-gen
sudo localectl set-locale LANG=zh_CN.UTF-8
```

- `/etc/locale.gen` 里被注释的语言不会生成；`locale-gen` 之后 `locale -a` 才能看到。
- `localectl set-locale` 写 `/etc/locale.conf`，是系统级；用户级可用 `~/.config/locale.conf`（部分工具读取）或会话环境。
- **`LANG` 管界面语言，不管输入法**；中文界面 + 英文输入法、英文界面 + 中文输入法都是合法组合。输入法见第 94 章。

本机在 SSH 会话里 `locale` 的 `LANG` 为空，而 `localectl status` 显示系统 locale 是 `en_US.UTF-8`——**「当前 shell 的 locale」与「系统默认 locale」是两件事**，排障要先分清。

## 字体：本地化的另一半

系统有中文 locale 但没有 CJK 字体，界面仍会出现方块：

```bash
fc-match sans-serif
fc-match 'Noto Sans CJK SC'
fc-list :lang=zh | wc -l
fc-list :lang=emoji | head -3
```

本机实际结果：`fc-match sans-serif` 返回 `Noto Sans`，`fc-list :lang=zh` 有大量 `Noto Sans CJK` 条目，`fc-list` 总数 2703。**字体装了不等于匹配对**：界面字体由 `fontconfig` 规则决定，`fc-match` 的输出文件才是最终结果。

- 中文：`noto-fonts-cjk`（含 SC/TC/JP/KR）；emoji：`noto-fonts-emoji`。
- 等宽：`ttf-dejavu`/`noto-fonts` 的 Mono 变体；终端与代码编辑器需要单独指定。
- 字体替换导致排版变化，在办公文档里尤其明显（第 97 章）。

## 无障碍：读屏、放大与对比度

| 能力 | 工具/接口 | 作用 |
| -------------- | ------------------------------ | ---------------------------------------------- |
| 屏幕阅读 | Orca | 朗读界面文字、焦点与通知 |
| 放大 | 桌面放大镜 | 局部放大，低视力用户 |
| 高对比度 | 主题/`gsettings` | 提高前景背景对比 |
| 大字号 | 字体缩放 | 全局或按应用放大 |
| 盲文 | `brltty` | 驱动盲文终端 |
| 辅助总线 | `org.a11y.Bus` | 应用与辅助技术通信的基础 |

```bash
gsettings list-schemas 2>/dev/null | grep -c a11y
gsettings get org.gnome.desktop.interface text-scaling-factor 2>/dev/null
busctl --user list 2>/dev/null | grep -i a11y # 需在图形桌面会话内执行
```

`org.a11y.Bus` **不是 systemd 单元**，别用 `systemctl --user status org.a11y.Bus` 查（会得到 unit not found）；它是 DBus 激活的用户级服务，用 `busctl`/`gdbus` 观察：

```bash
gdbus call --session --dest org.a11y.Bus --object-path /org/a11y/bus \
 --method org.freedesktop.DBus.Properties.Get org.a11y.Status IsEnabled
```

本书验证环境里 `gsettings list-schemas | grep -c a11y` 返回 6，说明辅助功能 schema 已安装；`org.a11y.Bus` 是 DBus 激活的用户级服务，读屏软件依赖它，被禁用时 Orca 会「启动但不出声」。

Orca 需要语音后端（如 `speech-dispatcher` + `espeak-ng`）；**「读屏没声音」通常是语音合成后端缺失，而不是 Orca 本身坏了**。

## 时区与格式

```bash
timedatectl
timedatectl set-timezone Asia/Shanghai
```

时区影响日志时间戳与 `LC_TIME` 的显示；多机排障时时间不同步会让事件顺序错乱（第 79 章）。`timedatectl` 同时显示 NTP 同步状态，时区对但时间漂移仍要修 NTP。

## 可复现实验：本地化与辅助的证据

```bash
locale
localectl status
locale -a | grep -E 'zh_CN|en_US' | head -4
fc-match sans-serif
fc-list :lang=zh | wc -l
gsettings list-schemas | grep -c a11y
timedatectl | head -6
```

本机结果：`locale` 的 `LANG` 为空（SSH 非登录 shell），`localectl` 显示系统默认 `en_US.UTF-8`，`zh_CN` 是否可用要看 `locale -a`；CJK 字体存在；a11y schema 数量为 6；`timedatectl` 可读时区与 NTP 状态。**这些只读命令能回答「系统按什么语言/时区工作」，不必改任何配置**。

## 失败模式

| 现象 | 根因 | 处置 |
| ------------------------------ | ------------------------------------------ | ------------------------------------------------------ |
| 启动时报 `setlocale: LC_ALL: cannot change locale` | `/etc/locale.gen` 未生成对应 locale | 取消注释后 `locale-gen` |
| 界面一半中文一半英文 | 翻译不完整或 `LC_MESSAGES` 未生效 | 确认 `locale` 实际值；缺翻译只能等上游 |
| 中文显示为方块 | 缺 CJK 字体或 `fc-match` 匹配错 | 装 `noto-fonts-cjk`，`fc-cache -fv` |
| emoji 显示为黑白/方块 | 缺 emoji 字体 | 装 `noto-fonts-emoji` |
| Orca 启动没声音 | 缺 `speech-dispatcher`/语音后端 | 装语音后端，检查 `org.a11y.Bus` |
| 高对比度主题无效 | 主题不支持或未在桌面启用 | 在设置中心启用，或换支持的主题 |
| 时间显示差 8 小时 | 时区错误 | `timedatectl set-timezone` |
| 日志时间顺序错乱 | NTP 未同步 | 启用 `systemd-timesyncd`/chrony，核对 `timedatectl` |
| `LC_ALL` 设了但应用仍英文 | 应用不读环境或自带语言设置 | 查应用自身语言选项；`LC_ALL` 只对兼容程序生效 |

## 验证与回滚

```bash
locale | grep -E 'LANG|LC_MESSAGES|LC_ALL'
locale -a | grep -c zh_CN
fc-match 'Noto Sans CJK SC'
gsettings get org.gnome.desktop.interface text-scaling-factor
timedatectl | grep -E 'Time zone|synchronized'
```

「locale 实际值、是否生成、字体匹配、缩放、时区/NTP」五项覆盖本地化与辅助的主要面。验收标准是**新开一个会话看界面**，而不是只看当前 shell 的变量。

回滚：

```bash
sudo cp /etc/locale.conf.bak /etc/locale.conf
sudo localectl set-locale LANG=en_US.UTF-8
sudo timedatectl set-timezone UTC
```

`locale.gen` 的修改可以还原后重新 `locale-gen`；生成的 locale 不会因为注释掉就消失，需要时重新生成即可。字体与辅助工具卸载用 `pacman -Rns`，不影响系统语言设置。

## 取舍边界

- **系统 locale vs 用户 locale**：多用户机器设系统默认 `en_US.UTF-8`、用户按需覆盖；单用户可直接设中文。
- **`zh_CN.UTF-8` vs `C.UTF-8`**：要中文界面与排序用 `zh_CN`；只要 UTF-8 编码、不介意英文界面用 `C.UTF-8`。
- **中文界面 vs 英文界面 + 中文输入**：开发者常选英文界面减少翻译歧义，输入法单独配置；两者不冲突。
- **矢量字体 vs 位图字体**：矢量清晰、可缩放；位图字体在特定字号下更锐利，但缩放差。
- **Orca vs 放大镜/高对比度**：全盲用读屏；低视力用放大与对比度；按需求组合，不必全装。
- **完整翻译 vs 原文**：翻译不全时混用更困惑；可选择关键应用用中文、其余保持英文。

## 小结

- `LANG` 是默认，`LC_*` 分项控制，`LC_ALL` 只用于临时排障。
- locale 必须先在 `/etc/locale.gen` 生成，`localectl` 只是设置默认值。
- 界面语言与输入法是两件事：输入法见第 94 章。
- 中文显示依赖 CJK 字体与 `fc-match` 匹配，emoji 另有字体。
- 无障碍链路：Orca + 语音后端 + `org.a11y.Bus`；低视力用放大与高对比度。
- 时区影响日志与显示，NTP 影响时间线可信度。

## 练习

1. 状态盘点：对比 `locale` 与 `localectl status`，解释为什么 SSH 会话里 `LANG` 可能为空。
2. 生成演练：查 `/etc/locale.gen` 中 `zh_CN` 是否启用，写出生成与设置默认的命令（不实际执行）。
3. 字体验证：用 `fc-match` 检查中文、等宽、emoji 三类匹配结果，指出缺失项。
4. 辅助链路：查 a11y schema 数量，在桌面会话里用 `busctl --user list | grep a11y` 看总线是否在跑，说明 Orca 不出声可能缺什么。
5. 时区排查：`timedatectl` 显示时区正确但日志顺序错乱，列出下一步该查什么。
6. 组合设计：为「英文界面 + 中文输入 + 读屏」的开发者设计一套配置，说明各组件归属。
