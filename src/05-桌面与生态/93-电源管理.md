# 第 93 章 电源管理

第 88 章给了合盖睡眠与 `power-profiles-daemon` 的最小配置；这一章讲**电源状态的底层机制与调优**：S0ix/S3 到底差在哪、休眠为什么失败、CPU 调频谁在管、电池阈值怎么写、唤醒源怎么查。笔记本的续航与稳定，八成取决于这几件事有没有配对。

> 本章目标：能区分 s2idle、deep（S3）与休眠（S4）的机制与代价；会用 `/sys/power/state`、`/sys/power/mem_sleep` 判断本机支持哪些状态；理解休眠对 swap 与 `resume` 的依赖（加密 swap 细节指向第 22 章）；知道 `amd-pstate`/`intel_pstate` 与 governor 的作用；能说出 `power-profiles-daemon`、TLP、`auto-cpufreq` 的冲突关系；会查电池阈值与唤醒源；能识别「合盖掉电」「休眠失败」「TLP 与 PPD 打架」三类问题。
> 对应 Wiki：[Power management](https://wiki.archlinux.org/title/Power_management)、[Power management/Suspend and hibernate](https://wiki.archlinux.org/title/Power_management/Suspend_and_hibernate)、[CPU frequency scaling](https://wiki.archlinux.org/title/CPU_frequency_scaling)、[TLP](https://wiki.archlinux.org/title/TLP)

## 三种「睡眠」不是一回事

| 状态 | 内核写法 | 机制 | 唤醒速度 | 耗电 | 依赖 |
| ---------- | ---------------- | ------------------------------ | -------- | -------- | ------------------------------ |
| s2idle | `freeze` | 进入低功耗空闲（S0ix），内存供电 | 最快 | 较高 | 平台支持现代待机 |
| deep | `mem`（S3） | 内存保持供电，其余断电 | 快 | 低 | 固件支持 S3 |
| 休眠 | `disk`（S4） | 内存写入 swap，整机断电 | 慢 | 最低 | swap ≥ 内存 + `resume` 配置 |

判断本机支持什么：

```bash
cat /sys/power/state
cat /sys/power/mem_sleep
```

本机实际输出：

```text
freeze standby mem disk
[s2idle] shallow
```

- `/sys/power/state` 列出可写状态：有 `mem` 表示支持挂起，有 `disk` 表示支持休眠。
- `/sys/power/mem_sleep` 的方括号是**当前默认**：`[s2idle]` 表示默认走现代待机，`shallow` 是 S3 的可选项。
- 切换默认要写 sysfs（`echo deep > /sys/power/mem_sleep`），属于改系统行为，**本章不实测**；要持久化用内核参数 `mem_sleep_default=deep`。

s2idle 唤醒快但待机耗电高，部分平台还有「睡死」问题；S3 更省电但唤醒略慢。**没有普适最优**，按机型实测待机耗电与唤醒稳定性来选。

## 休眠：swap 与 resume 两个前提

休眠把内存镜像写入 swap，开机时由内核从同一位置读回：

- swap 容量 ≥ 内存（或至少覆盖实际占用，但按内存大小规划最稳）；
- 引导参数带 `resume=<swap 分区 UUID>`；swapfile 还要 `resume_offset=<物理偏移>`；
- initramfs 里有 `resume` 钩子。**Arch 默认的 `HOOKS` 不含 `resume`**，需要手动加在 `udev` 之后、`filesystems` 之前，再 `mkinitcpio -P`：

```bash
# /etc/mkinitcpio.conf
HOOKS=(base udev autodetect microcode modconf kms keyboard keymap consolefont block resume filesystems fsck)
sudo mkinitcpio -P # 改完必须重建；内核升级时同样要靠这个钩子
```

改完后逐项核对三个前提：

```bash
swapon --show
cat /proc/cmdline
grep -n 'resume' /etc/mkinitcpio.conf
```

**加密 swap 的 `resume` 与密钥配置见第 22 章**，本章不重复 LUKS 细节；只提醒一句：swap 加密后，休眠恢复依赖同一个密钥在启动早期可用，配置错会表现为「休眠后无法唤醒、直接冷启动」。

`systemctl hibernate` 失败时先看这三个前提，再看 `/sys/power/state` 是否有 `disk`。

## CPU 调频：谁在管频率

| 驱动 | 平台 | 说明 |
| -------------------- | ---------- | ------------------------------------------ |
| `intel_pstate` | Intel | 内核内置，`active` 模式下调频策略更激进 |
| `amd-pstate` | AMD | 现代 AMD 的首选，`amd-pstate-epp` 更细 |
| `acpi-cpufreq` | 通用回退 | 老平台或上述驱动不可用时 |

```bash
cpupower frequency-info # 需要 cpupower 包
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_driver
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor
```

- governor：`powersave` 省电、`performance` 性能、`schedutil` 由调度器驱动（现代默认）。
- `energy_performance_preference`（EPP）在 `amd-pstate-epp`/`intel_pstate` 下可取值 `power`/`balance_power`/`balance_performance`/`performance`。
- 手动改 governor 只是临时生效；持久化与整机策略应由电源守护统一管理，不要三处同时改。

## 电源守护：只能选一个

| 工具 | 方式 | 优点 | 冲突点 |
| -------------------- | ------------------------------ | ------------------------------ | ------------------------------ |
| `power-profiles-daemon` | DBus，桌面集成 | 切换简单、与 KDE/GNOME 联动 | 与 TLP 同时装会互相覆盖 |
| TLP | 配置文件 + 服务 | 细粒度、省电效果好 | 与 PPD 冲突，需停用其一 |
| `auto-cpufreq` | 守护进程（AUR） | 自动按负载调频 | 与上述两者都可能冲突 |

```bash
systemctl status power-profiles-daemon --no-pager | head -6
powerprofilesctl get 2>/dev/null || echo "未安装 PPD"
systemctl status tlp --no-pager | head -6
```

选择原则：**桌面用户优先 PPD**（与图形界面集成好）；**追求续航且愿意调参用 TLP**；两者只启用一个，另一个 `disable --now`。装 TLP 后要 `tlp-stat -s` 确认它真的接管了，而不是和 PPD 各改一半。

## 电池阈值与唤醒源

电池充电上限因固件/驱动而异：

```bash
ls /sys/class/power_supply/
cat /sys/class/power_supply/BAT0/charge_control_end_threshold 2>/dev/null
```

能读到该文件就可以写阈值（如 80）；读不到说明固件不支持，只能靠厂商工具。TLP 的写法是 `STOP_CHARGE_THRESH_BAT0=80`，但**底层仍依赖这个 sysfs 接口**。

唤醒源：

```bash
cat /proc/acpi/wakeup 2>/dev/null
ls /sys/class/wakeup/ 2>/dev/null | head
journalctl -b | grep -iE 'wakeup|suspend|resume' | tail -20
```

`/proc/acpi/wakeup` 里 `enabled` 的设备可以唤醒机器；网卡、USB、键盘误唤醒导致「睡一晚掉电」，就从这里逐个关闭。写入 `/proc/acpi/wakeup` 是临时操作，持久化要 udev 规则或 `systemd` 单元。

## 合盖、按键与 sleep 钩子

`logind` 负责合盖与电源键行为：

```ini
# /etc/systemd/logind.conf
HandleLidSwitch=suspend
HandleLidSwitchExternalPower=suspend
HandleLidSwitchDocked=ignore
HandlePowerKey=poweroff
```

本机这些项默认是注释状态（走内置默认值）。改完 `systemctl restart systemd-logind`；**重启 logind 会影响当前会话**，最好在 tty 操作。

需要在睡眠前后执行动作（卸载网络盘、重置设备）时用 sleep 钩子：

```bash
ls /usr/lib/systemd/system-sleep/
# 脚本接收两个参数：pre/post 与 suspend/hibernate
```

钩子脚本要短、可失败、不要阻塞；一个卡住的 `pre` 钩子会让整机睡不下去。

## 可复现实验：只读状态

```bash
cat /sys/power/state
cat /sys/power/mem_sleep
swapon --show
cat /proc/cmdline | tr ' ' '\n' | grep -E 'resume|mem_sleep'
upower -e 2>/dev/null
upower -d 2>/dev/null | head -20
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_driver 2>/dev/null
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor 2>/dev/null
journalctl -b | grep -ciE 'suspend|hibernate'
```

本机结果：`/sys/power/state` 含 `mem` 与 `disk`，`mem_sleep` 默认 `[s2idle]`；`upower -e` 只列出 AC 与 DisplayDevice（虚拟机无电池）；`scaling_driver`/`governor` 能读出当前调频策略。**这些只读值能回答「机器支持什么、现在用什么」，不必真的睡一次**。

## 失败模式

| 现象 | 根因 | 处置 |
| ------------------------------ | ------------------------------------------ | ------------------------------------------------------ |
| 合盖后整晚掉电 20%+ | 默认 s2idle 待机功耗高或唤醒源过多 | 试 `mem_sleep_default=deep`，关闭误唤醒设备 |
| `systemctl hibernate` 立即失败 | swap 不足或没配 `resume` | 查 `swapon --show`、`/proc/cmdline`、initramfs 钩子 |
| 休眠后无法唤醒、直接冷启动 | `resume` 指向错/加密 swap 密钥不可用 | 核对 UUID 与 offset；加密 swap 见第 22 章 |
| 睡眠后网卡/音频失效 | 驱动未实现 resume 回调 | 换驱动版本，或加 sleep 钩子重载模块 |
| 装了 TLP 但设置不生效 | PPD 同时在跑并覆盖 | `systemctl disable --now power-profiles-daemon` |
| 电池只充到 80% 就停 | 阈值被设置过 | 查 `charge_control_end_threshold` 或 TLP 配置 |
| 插电时也降频 | governor/EPP 被设为省电 | 查 `scaling_governor` 与 EPP，按场景切换 |
| 电源键无反应 | `HandlePowerKey` 被改成 ignore | 恢复 `logind.conf` 并重启 logind |
| 睡眠钩子卡住导致睡不下去 | 钩子脚本阻塞/等待网络 | 精简钩子，加超时 |

## 验证与回滚

```bash
cat /sys/power/state /sys/power/mem_sleep
systemctl status systemd-logind --no-pager | head -6
systemctl is-enabled power-profiles-daemon tlp 2>/dev/null
powerprofilesctl get 2>/dev/null
journalctl -b -u systemd-logind --no-pager | tail -20
```

「支持状态、当前默认、守护进程、最近一次睡眠日志」四项能解释多数电源异常。真正验证睡眠要**短时间实测**：睡 1 分钟、记时间与电量，唤醒后看 `journalctl` 的 resume 记录；长期休眠测试前先保存工作。

回滚：

```bash
sudo cp /etc/systemd/logind.conf.bak /etc/systemd/logind.conf
sudo systemctl restart systemd-logind
sudo systemctl disable --now tlp # 或反向，只留一个
sudo systemctl enable --now power-profiles-daemon
```

内核参数类改动（`mem_sleep_default`、`resume`）要改引导配置并重新生成，回滚同样要重新生成；**改前备份 `/etc/default/grub` 或对应 boot entry**。

## 取舍边界

- **s2idle vs deep**：s2idle 唤醒快、体验好但耗电高；deep 省电但唤醒慢、部分新平台不支持。按机型实测选。
- **挂起 vs 休眠**：短时间离开用挂起；长期离机、怕掉电用休眠。休眠的配置成本与失败面更大。
- **PPD vs TLP**：桌面联动与简单切换选 PPD；深度省电与细粒度控制选 TLP。只启用一个。
- **性能 vs 续航**：`performance` 响应快但耗电；`powersave` 省电但重负载时可能卡顿。按「插电/电池」分场景切换。
- **电池阈值 vs 满电**：长期插电办公设 80% 延长寿命；需要长续航外出时临时充满。
- **自动调频 vs 固定 governor**：自动策略适应负载；固定 governor 可预测但浪费。除非有明确理由，交给驱动默认。

## 小结

- 三种睡眠：s2idle（快、耗电）、deep/S3（省电、略慢）、休眠/S4（断电、依赖 swap 与 `resume`）。
- `/sys/power/state` 与 `/sys/power/mem_sleep` 是「支持什么、默认什么」的直接证据。
- 休眠三前提：swap 足够、`resume` 正确、initramfs 钩子；加密 swap 细节在第 22 章。
- CPU 调频由 `intel_pstate`/`amd-pstate` 管，governor 与 EPP 决定性能/功耗倾向。
- PPD、TLP、auto-cpufreq 只能选一个，冲突表现为「设置时好时坏」。
- 合盖与电源键在 `logind.conf`；误唤醒查 `/proc/acpi/wakeup`；睡前动作放 sleep 钩子。
