# 第 85 章 桌面环境

第 81 章把图形栈分成三层，第 84 章讲了合成器这一层；这一章讲最上层：**桌面环境（DE）**。DE 不是「一个软件」，而是一整套协同工作的组件：窗口管理、面板、设置中心、会话管理、通知、文件管理器与一批默认应用。理解这套组件，才能判断该装「元包」、「包组」还是只装其中几件。

> 本章目标：能说出 DE 的五个组成部分，并区分「DE、窗口管理器、合成器」；能按资源占用、可定制性、Wayland 支持与应用生态在 GNOME、Plasma、Xfce 等之间做选择；知道 `pacman` 的「包组」与「元包」区别，以及安装完整组的代价；能识别「装多套 DE 导致 portal/主题冲突」「删 DE 留下孤儿包与配置」两类问题；会用 `XDG_CURRENT_DESKTOP`、包查询与会话文件验证当前桌面。
> 对应 Wiki：[Desktop environment](https://wiki.archlinux.org/title/Desktop_environment)、[GNOME](https://wiki.archlinux.org/title/GNOME)、[KDE](https://wiki.archlinux.org/title/KDE)、[Xfce](https://wiki.archlinux.org/title/Xfce)

## DE 由什么组成

| 组成 | 作用 | GNOME | Plasma | Xfce |
| ---------------- | ------------------------------ | --------------------- | --------------------- | --------------------- |
| 窗口管理/合成 | 摆放窗口、动画、输入分发 | Mutter | KWin | xfwm4 |
| 面板 / shell | 任务栏、启动器、状态区 | GNOME Shell | Plasma shell | xfce4-panel |
| 设置中心 | 统一改主题、显示、网络 | `gnome-control-center` | `systemsettings` | `xfce4-settings` |
| 会话管理 | 启动组件、保存/恢复会话 | gnome-session | ksmserver | xfce4-session |
| 应用集 | 文件、终端、编辑器、截图等 | 一组 GNOME 应用 | 一组 KDE 应用 | 一组 Xfce 应用 |

窗口管理器只负责「窗口怎么摆」，合成器负责「怎么合成输出」，DE 则把这两者与设置、会话、应用打包在一起。**这就是为什么「装个 WM 也能用」但「没有设置中心、通知、portal」**——那些是 DE 提供的，不是窗口管理器的职责。

## 主流 DE 选型

| DE | 包组/元包 | 组内包数（本机查询） | 资源占用 | 可定制性 | Wayland |
| ---------- | ---------------------------- | -------------------- | -------- | -------- | ---------------------- |
| GNOME | `gnome` 组（另有 `gnome-extra`） | 58（extra 22） | 较高 | 较低（扩展补足） | 成熟 |
| KDE Plasma | `plasma-meta` 元包（`plasma` 组） | 68 | 中 | 很高 | 成熟 |
| Xfce | `xfce4` 组 | 14 | 低 | 中 | 实验/部分（多为 X11） |
| Cinnamon | `cinnamon` 包 + 依赖 | — | 中 | 中 | 以 X11 为主 |
| MATE | `mate` 组 | 14 | 低 | 中 | 以 X11 为主 |
| LXQt | `lxqt` 组 | 25 | 很低 | 中 | 部分支持 |

三个代表应用的定位：

- **GNOME**：开箱即用、设计统一，适合不想调设置的人；代价是可定制性低、扩展随版本波动。
- **Plasma**：设置项极多、可深度定制，适合愿意花时间打磨工作流的人；包多、组件多，排障面也大。
- **Xfce**：轻、稳、启动快，适合老机器与虚拟机；Wayland 支持仍不完整，默认多为 X11。

选型顺序建议：**先确定「X11 还是 Wayland」→ 再定「要图形设置还是文本配置」→ 最后看资源与生态**。反过来先看截图选 DE，常在装完才发现输入法、截屏、缩放不合预期。

## 包组与元包：安装代价

`pacman` 有两种「一次装很多」的方式，语义不同：

```bash
pacman -Sg gnome # 查看组内成员，不安装
sudo pacman -S gnome # 安装组（会交互选择成员）
sudo pacman -S plasma-meta # 元包：靠依赖关系拉齐整套
```

- **包组（group）**：`gnome`、`xfce4`、`mate`、`lxqt` 是组，成员是独立包；安装时可全部或按提示选择。组本身不被「安装」，删掉成员也不会删组。
- **元包（meta）**：`plasma-meta` 是一个真实包，靠 `depends` 拉入整套；删除元包不会自动删依赖，需要再清孤儿。

安装前先看规模：

```bash
pacman -Sg plasma | wc -l
pacman -Si plasma-meta | grep -E 'Version|Installed Size'
```

本机查询结果：`gnome` 组 58 个包、`gnome-extra` 22 个、`plasma` 组 68 个、`xfce4`/`mate` 各 14 个、`lxqt` 25 个。**「装整套」意味着几十个应用与依赖**，虚拟机里先装最小集（如 `plasma-desktop` + `kwin` + 终端）验证链路，再按需补齐。

## 安装后的验证点

装完不要只看「能不能进桌面」，要确认四件事：会话类型、当前桌面标识、portal、关键组件。

```bash
echo "$XDG_CURRENT_DESKTOP" # GNOME / KDE / XFCE
echo "$XDG_SESSION_TYPE" # wayland / x11
ls /usr/share/wayland-sessions/ /usr/share/xsessions/ 2>&1
pacman -Q | grep -E '^(plasma|gnome|xfce)' | head -10
```

`XDG_CURRENT_DESKTOP` 由会话启动时设置，是「当前到底跑的是哪套桌面」的直接证据；会话文件决定登录界面能选哪些会话；`pacman -Q` 则是「装了哪些组件」的事实清单。三者对不上时，先查会话文件与 DM（第 86 章），不要急着重装。

## 可复现实验：不安装也能比较

以下命令只查询仓库与本地状态，不修改系统：

```bash
pacman -Sg gnome | wc -l
pacman -Sg plasma | wc -l
pacman -Sg xfce4 | wc -l
pacman -Si plasma-meta | grep -E 'Version|Installed Size|Depends On' | head -4
pacman -Q | grep -cE '^(plasma|gnome|xfce)'
ls /usr/share/wayland-sessions/ /usr/share/xsessions/ 2>&1
```

本机结果：`gnome` 58、`plasma` 68、`xfce4` 14；已安装的 Plasma 组件（`plasma-meta 6.8`、`plasma-workspace 6.8.2` 等）可以在 `pacman -Q` 里逐条看到；`/usr/share/wayland-sessions` 只有 `plasma.desktop`，`/usr/share/xsessions` 不存在。**组内包数是「安装规模」的硬指标**，比任何评测文章都准确。

## 失败模式

| 现象 | 根因 | 处置 |
| ------------------------------ | ------------------------------------------ | ------------------------------------------------------ |
| 装第二套 DE 后文件选择框/截屏异常 | 多个 portal 后端抢接口 | 只保留与当前会话匹配的后端，重启 portal（第 84 章） |
| 登录后桌面主题一半是另一套 | GTK/Qt 主题与图标未统一 | 统一 `gtk-theme`、Qt 平台主题与图标（第 87 章） |
| 删掉 DE 后仍残留几十个包 | 元包依赖与孤儿未清 | `pacman -Rns <元包>` 后 `pacman -Qtdq` 查孤儿 |
| 装完进不了桌面 | 只装了组内部分组件，会话缺可执行文件 | 核对会话文件 `Exec=` 指向的程序是否存在 |
| 虚拟机里 Plasma 卡顿 | 3D 加速未开，走 `llvmpipe` | 开虚拟机 3D 或换轻量 DE（第 82 章） |
| GNOME 扩展升级后失效 | 扩展未跟进 GNOME 版本 | 禁用不兼容扩展，等作者更新；不要改扩展源码硬撑 |
| 混装 Plasma 5/6 组件报冲突 | 旧包（如 `plasma5support`）未清 | 按官方升级说明移除旧组件，不要强行 `--overwrite` |
| 多套 DE 的自启项互相拉起 | `~/.config/autostart` 与各 DE 会话都注册了 | 按当前 DE 精简自启项（第 87 章） |

## 验证与回滚

验证桌面是否「真的装对」：

```bash
echo "$XDG_CURRENT_DESKTOP / $XDG_SESSION_TYPE"
systemctl --user list-units --type=service --state=running | head -10
pacman -Q | grep -E '^(plasma|gnome|xfce)' | wc -l
ls /usr/share/wayland-sessions/ /usr/share/xsessions/
```

运行中的用户级服务能看出会话组件（通知、portal、设置守护）是否起来；包数量能看出是否只装了半套；会话文件能看出登录界面能选什么。

回滚：

```bash
sudo pacman -Rns plasma-meta # 或对应元包
pacman -Qtdq | sudo pacman -Rns - # 清理孤儿（先人工确认清单）
mv ~/.config/plasma* /tmp/ # 配置先移走，不要直接删
```

**删 DE 前先把 `~/.config` 与 `~/.local/share` 里的相关目录移走而不是删除**，否则想回退时设置全丢。会话文件与 DM 的清理见第 86 章；主题与自启的清理见第 87 章。

## 取舍边界

- **完整元包 vs 最小组件集**：元包省心、一次到位，但装了几十个用不到的应用；最小集可控，但要自己补会话、portal、设置中心。
- **一套 DE vs 多套并存**：多套便于对比，但会带来 portal、主题、自启、MIME 默认项的冲突；日常机只留一套，实验机可以多套。
- **GNOME vs Plasma**：要统一设计与少配置选 GNOME；要深度定制与丰富设置选 Plasma。两者都能跑 Wayland。
- **Xfce vs 轻量 WM**：Xfce 提供完整桌面但 Wayland 支持有限；纯 Wayland 轻量需求用 sway/Hyprland（第 84 章）加自选组件。
- **滚动更新 vs 稳定优先**：Arch 上 DE 跟随上游快速更新，扩展与主题可能滞后；保守做法是延迟升级 DE 相关包并关注 Arch News（第 52 章）。
- **图形设置 vs 文本配置**：图形设置直观但难版本化；文本配置可复现但学习成本高。按「是否需要重装后一键恢复」决定。

## 小结

- DE = 窗口管理/合成 + 面板 + 设置中心 + 会话 + 应用集；与 WM、合成器不是一回事。
- 包组是成员集合（`gnome`/`xfce4`/`mate`/`lxqt`），元包是真实包（`plasma-meta`），安装规模看组内包数。
- 本机组内包数：GNOME 58、Plasma 68、Xfce 14；整套安装代价可观。
- 选型先定会话类型（X11/Wayland），再看配置方式与资源占用。
- 多套 DE 并存会引发 portal、主题、自启冲突；日常机只留一套。
- 删除 DE 用 `pacman -Rns` 加孤儿清理，配置目录先移走再决定。

## 练习

1. 组规模：用 `pacman -Sg` 统计 `gnome`、`plasma`、`xfce4` 的成员数，写出你会从元包里剔除的三个应用及理由。
2. 当前桌面：记录 `XDG_CURRENT_DESKTOP`、`XDG_SESSION_TYPE`、会话文件与已装组件数，判断当前桌面是否完整。
3. 最小安装路径：为 Plasma 设计一个「只含桌面、窗口管理、终端、设置」的最小包清单（不实际安装）。
4. 混合安装分析：列出两套 DE 并存时可能冲突的四类资源（portal、主题、自启、MIME 默认），各给一条排查命令。
5. 回滚设计：写出一套「卸载 DE 并保留配置备份」的命令序列，说明为什么先 `mv` 而不是 `rm`。
6. 选型论证：给定「8GB 内存的老笔记本、要 Wayland、要平铺」三个条件，选出 DE/WM 组合并说明取舍。
