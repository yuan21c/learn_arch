# 第 97 章 办公、文档与笔记

办公软件在 Linux 上的难点不是「有没有」，而是**格式保真与协作兼容**。同一份 `.docx` 在 Microsoft Office、LibreOffice、OnlyOffice 里可能排版不同，原因通常是字体、行距计算、以及 OOXML 的实现差异。这一章按「套件、格式、笔记、阅读」四类讲，重点是选型与故障定位。

> 本章目标：能按兼容性、体积、协作需求在 LibreOffice、OnlyOffice、WPS 之间选择；理解 ODF 与 OOXML 的差别及「格式保真」为什么难；知道字体替换是排版错乱的首要原因；能按「富文本 / Markdown / 双链笔记」选择笔记工具；会用 `pandoc` 做 Markdown 与 docx/pdf 的转换；能识别「打开后版式全乱」「文件被锁」「同步冲突」三类问题。
> 对应 Wiki：[LibreOffice](https://wiki.archlinux.org/title/LibreOffice)、[List of applications/Documents](https://wiki.archlinux.org/title/List_of_applications/Documents)、[Pandoc](https://wiki.archlinux.org/title/Pandoc)

## 套件选型

| 套件 | 许可/来源 | 兼容性 | 体积/资源 | 适合 |
| -------------- | ---------------------- | ------------------------------ | -------- | ------------------------------ |
| LibreOffice | 开源，官方仓库 | OOXML 兼容较好，复杂排版仍有差异 | 中 | 日常办公、离线、无协作平台 |
| OnlyOffice | 开源桌面版，AUR | 对 docx/xlsx/pptx 保真较好 | 较大 | 需要与 Office 高度互操作 |
| WPS Office | 专有，AUR | 界面接近 Office，兼容性较好 | 大 | 习惯 Office 界面、能接受专有 |
| Calligra | 开源，官方仓库 | 偏 KDE 生态，兼容性一般 | 中 | KDE 用户、轻量文档 |

两个官方仓库版本的区别：`libreoffice-fresh` 跟随最新功能，`libreoffice-still` 更保守、适合长期稳定使用。**同一台机器只装一个分支**，两者包名冲突。

## 格式：ODF 与 OOXML

| 格式 | 归属 | 特点 | 交换建议 |
| ------------- | ---------------- | ------------------------------ | ------------------------------ |
| ODF（odt/ods） | 开放标准 | LibreOffice 原生，结构开放 | 内部存档可用 |
| OOXML（docx/xlsx） | 微软主导 | 办公交换事实标准 | 对外交付优先 |
| PDF | 固定版式 | 不随环境变化 | 最终交付、打印 |
| Markdown | 纯文本 | 可版本化、易转换 | 笔记、文档源文件 |

「格式保真」难在三点：**字体是否一致、行距与分页算法是否一致、复杂对象（图表、批注、域代码）实现是否一致**。对外交付时最稳的做法是**导出 PDF**；需要对方继续编辑时，保留一份 OOXML 并接受少量版式差异。

## 字体是排版错乱的第一原因

文档里写的是「宋体 12pt」，系统没有宋体时，LibreOffice 会用替代字体，字宽变化导致换行、分页全变：

```bash
fc-match 'SimSun'
fc-match 'Times New Roman'
fc-list :lang=zh | head -5
```

- 装常见替代（如 `noto-fonts-cjk`）能显示中文，但**字宽不等于原字体**，版式仍可能偏移。
- 需要高保真时，安装原字体（注意许可），或让对方导出 PDF。
- `fc-match` 显示实际替换结果，是判断「为什么版式变了」的第一条命令（第 87 章）。

## 笔记工具：三种范式

| 范式 | 代表 | 优点 | 代价 |
| -------------- | ------------------------------ | ------------------------------ | ------------------------------ |
| 富文本/块编辑器 | Obsidian（官方仓库）、Joplin（AUR） | 上手快、图文混排 | 数据格式私有、迁移成本 |
| 双链/大纲 | Logseq（AUR） | 关联思考、日记流 | 学习曲线、性能随库增长下降 |
| 纯文本 Markdown | 编辑器 + `pandoc-cli` + git | 可版本化、无锁定、可转换 | 要自己搭工作流 |

- **Obsidian** 的库是本地 Markdown 文件夹，但插件与配置是私有的；适合愿意用本地文件 + 插件的人。
- **Joplin** 支持端到端加密同步，数据在 SQLite；跨平台好，但库不适合直接用 git 管理。
- **Logseq** 以块和大纲组织，适合日记与双链；大库会吃内存。
- **纯文本 + pandoc** 最可控：源文件是 `.md`，用 `pandoc` 转 docx/PDF，配合 git 做历史。

```bash
sudo pacman -S pandoc-cli
pandoc note.md -o note.docx
pandoc note.md -o note.pdf # 需要 LaTeX 引擎或 wkhtmltopdf 等
```

`pandoc-cli` 是 Arch 现在的命令行包名（库与 CLI 已拆分）；只装 `pandoc` 的旧教程可能已过时。

## 阅读器

| 工具 | 格式 | 特点 |
| ---------- | -------------------- | ------------------------------ |
| Zathura | PDF、DjVu、PS | 键盘驱动、轻量、插件式 |
| Okular | PDF、EPUB、CHM 等 | KDE 生态、批注功能全 |
| Foliate | EPUB | GTK、电子书体验好 |

三者都在官方仓库；阅读器不负责编辑，选型主要看格式覆盖与批注需求。

## 可复现实验：包、转换与字体

```bash
pacman -Si libreoffice-fresh | grep -E 'Repository|Version|Conflicts' | head -4
pacman -Si pandoc-cli | grep -E 'Repository|Version' | head -2
pacman -Q libreoffice-fresh libreoffice-still 2>&1
fc-match 'Times New Roman'
fc-match 'SimSun'
printf '# Test\n\nHello **world**.\n' > /tmp/b6-note.md
```

本机核验：`libreoffice-fresh`/`libreoffice-still`/`pandoc-cli`/`obsidian`/`zettlr`/`zathura`/`okular`/`foliate` 都在官方仓库；`onlyoffice-bin`、`joplin`、`logseq-desktop` 在 AUR。装 `pandoc-cli` 后可用 `pandoc /tmp/b6-note.md -o /tmp/b6-note.docx` 做一次最小转换（需实际安装，**未实测**）。

## 失败模式

| 现象 | 根因 | 处置 |
| ------------------------------ | ------------------------------------------ | ------------------------------------------------------ |
| 打开 docx 后版式全乱 | 字体缺失/替换、OOXML 实现差异 | 装原字体或导出 PDF；用 `fc-match` 确认替换 |
| 文件提示被锁定 | LibreOffice 的 `.~lock.*` 残留 | 确认无进程后删锁文件；不要在多机同时编辑 |
| 保存后对方打不开 | 选了不兼容格式/扩展名 | 另存为 docx/xlsx 或 PDF，确认目标软件支持 |
| 云同步出现冲突副本 | 两台机器同时改同一文件 | 用版本控制或单点编辑；冲突文件手工合并 |
| 表格公式/宏不工作 | 宏引擎/Java 依赖缺失 | 装 JRE（`jre-openjdk`），或改用无宏方案 |
| PDF 导出中文缺字 | 缺 CJK 字体或未嵌入 | 装 CJK 字体，导出时勾选嵌入 |
| 笔记库越来越大且卡 | 附件/插件过多、索引膨胀 | 拆分库、清理附件、关闭重型插件 |
| AUR 套件升级失败 | 上游二进制/依赖变化 | 关注 AUR 评论，必要时暂缓升级（第 52 章） |

## 验证与回滚

```bash
pacman -Q libreoffice-fresh 2>/dev/null
fc-match '宋体'
pandoc --version 2>/dev/null | head -2
file document.docx 2>/dev/null
```

版本决定格式支持；`fc-match` 决定排版基础；`pandoc --version` 确认转换工具可用；`file` 能识别实际容器格式（docx 本质是 zip）。**验收标准是「在目标软件里打开并另存一次仍正常」**，不是「本机能打开」。

回滚：

- 套件升级后格式异常，可回退到 `libreoffice-still` 或旧版本包（需 `pacman` 缓存/降级，第 52 章）。
- 文档损坏时从备份/云历史恢复；LibreOffice 的自动备份在用户配置目录。
- 笔记库迁移前先整体复制，确认新工具能导入再删旧库。

## 取舍边界

- **LibreOffice vs OnlyOffice**：离线、开源、轻量选 LibreOffice；与 Office 高度互操作选 OnlyOffice，接受更大体积与 AUR 维护。
- **ODF vs OOXML**：内部长期存档用 ODF；对外交换用 OOXML + PDF。
- **富文本 vs Markdown**：图文混排、演示用富文本；技术文档、要版本化用 Markdown。
- **本地库 vs 云同步**：本地库可控、可备份；云同步方便但带来冲突与隐私问题。
- **PDF vs 可编辑文档**：交付用 PDF 锁定版式；协作保留可编辑格式。
- **专有套件 vs 开源**：专有兼容性可能更好，但许可、更新与审计成本更高；开源可控但要多做兼容测试。

## 小结

- 套件按兼容/体积/许可选：LibreOffice 开源、OnlyOffice 高保真、WPS 类 Office 界面。
- `fresh` 与 `still` 是分支，不能同装；对外交付优先 PDF。
- 排版错乱先查字体替换，`fc-match` 是第一命令。
- 笔记三范式：富文本、双链、纯文本 Markdown；纯文本最可控。
- `pandoc-cli` 是当前的命令行包名，可做 Markdown 转换。
- 阅读器按格式覆盖与批注需求选：Zathura、Okular、Foliate。

## 练习

1. 分支确认：查本机装的是 `libreoffice-fresh` 还是 `still`，说明为什么不能同装。
2. 字体诊断：用 `fc-match` 检查三种文档常用字体的替换结果，解释版式偏移的原因。
3. 格式转换：写一条 `pandoc` 命令把 Markdown 转 docx，再说明转 PDF 还需要什么。
4. 选型论证：给定「要发给使用 Office 的客户、需要对方继续编辑」，选出套件与交付格式。
5. 笔记迁移：把一批 Markdown 笔记从 Obsidian 迁到纯文本 + git，列出要处理的私有配置。
6. 故障分析：文件提示被锁定，写出确认无进程、清理锁文件、恢复编辑的步骤。
