# 第 100 章 桌面工具、文件管理与搜索

桌面日常里最高频的三件事：**找文件、开程序、复制粘贴**。它们看起来琐碎，却是「桌面是否顺手」的分水岭。这一章按「文件管理、搜索、启动器/剪贴板、归档与同步」四类讲，重点是选型与索引/协议边界。

> 本章目标：能按桌面生态与操作习惯选择图形或终端文件管理器；理解 `locate` 的索引机制与 `fd`/`ripgrep` 的实时遍历差异；知道索引过期为什么导致「文件明明在却搜不到」；会在 Wayland 与 X11 下选择剪贴板工具；知道归档格式与同步工具的边界；能识别「locate 库过期」「fd 忽略隐藏文件」「Wayland 剪贴板不工作」三类问题。
> 对应 Wiki：[List of applications/Utilities](https://wiki.archlinux.org/title/List_of_applications/Utilities)、[File manager](https://wiki.archlinux.org/title/File_manager)、[Locate](https://wiki.archlinux.org/title/Locate)、[Ripgrep](https://wiki.archlinux.org/title/Ripgrep)

## 文件管理器选型

| 管理器 | 生态 | 特点 | 适合 |
| -------------- | -------------- | ------------------------------ | ------------------------------ |
| Nautilus | GNOME | 简洁、集成 GNOME 搜索 | GNOME 用户 |
| Dolphin | KDE | 功能全、分栏、内建终端 | KDE 用户、要双栏 |
| Thunar | Xfce | 轻量、启动快 | Xfce/轻量桌面 |
| Nemo | Cinnamon | 功能与轻量平衡 | 非 GNOME 的 GTK 桌面 |
| ranger / yazi | 终端 | 键盘驱动、可预览 | 终端流、远程/服务器 |

图形管理器依赖 `gvfs` 等挂载与缩略图服务：**「网络位置打不开」「缩略图不显示」通常不是文件管理器坏了**，而是 `gvfs`/缩略图生成器缺失。终端管理器不依赖这些，但也没有图形预览与拖放。

## 搜索：索引与实时是两套机制

| 工具 | 机制 | 优点 | 局限 |
| ------------- | ------------------------------ | ------------------------------ | ------------------------------ |
| `locate`/`plocate` | 预建索引，按路径查 | 全盘秒查 | 索引过期就查不到新文件 |
| `fd` | 实时遍历目录 | 默认忽略 `.gitignore`/隐藏 | 大目录慢，需显式 `-H`/`-I` |
| `ripgrep`/`rg` | 实时遍历 + 内容匹配 | 快、尊重忽略规则 | 同样受忽略规则影响 |
| `find` | 实时遍历，规则最全 | 无依赖、精确 | 语法繁琐、慢 |
| `fzf` | 交互式过滤 | 与管道组合灵活 | 本身不产生候选，要配合其他命令 |

```bash
sudo pacman -S plocate fd ripgrep fzf
sudo updatedb
locate -b '\bashrc'
fd -H -t f pattern ~
rg -n 'keyword' ~/notes
```

- `updatedb` 由 `plocate-updatedb.timer` 定期执行；**新文件搜不到先手动 `updatedb`**，而不是怀疑工具。
- `fd`/`rg` 默认尊重 `.gitignore` 与隐藏文件规则；在仓库里搜不到时加 `-I`（忽略忽略规则）或 `-H`（含隐藏）。
- `rg` 默认跳过二进制与忽略目录，适合代码；全盘搜文件内容要显式指定路径与类型。

索引的**范围**也由配置决定，不是「整块硬盘」：

```bash
grep -v '^#' /etc/updatedb.conf 2>/dev/null | grep -E 'PRUNE'
```

`PRUNEFS` 排除网络与临时文件系统，`PRUNEPATHS` 排除目录（常见是 `/proc`、`/sys`、`/tmp`、`/var/cache`）。把媒体库挂在 `/mnt` 却搜不到，先看它是否落在排除列表里，再怀疑索引。

## 启动器、剪贴板与归档

| 类别 | X11 | Wayland | 说明 |
| -------------- | ------------------------------ | ------------------------------ | ------------------------------ |
| 启动器 | `rofi`、`dmenu` | `wofi`、`rofi`（部分支持） | 按键绑定由合成器/WM 配置 |
| 剪贴板 | `xclip`、`xsel` | `wl-clipboard`（`wl-copy`/`wl-paste`） | Wayland 不允许后台任意读剪贴板 |
| 归档 | `file-roller`、`ark` | 同左 | 图形前端，底层仍是 `tar`/`7z`/`zip` |
| 同步 | `rsync`、`rclone` | 同左 | 命令行，跨平台 |
| 持续同步 | `syncthing` | 同左 | 点对点，需常驻服务 |

```bash
wl-copy "hello" && wl-paste
xclip -selection clipboard <<< "hello"
tar -czf /tmp/backup.tar.gz ~/notes
7z a /tmp/backup.7z ~/notes
```

Wayland 的剪贴板是**协议授权**的：应用失去焦点后未必还能读写，后台脚本 `wl-paste` 可能拿不到内容；这不是工具 bug（第 84 章）。

**剪贴板历史**需要额外守护进程：X11 下常见 `greenclip`（AUR），Wayland 下 `cliphist` 监听 `wl-paste --watch` 并把内容存进本地数据库。历史里会有密码与令牌，**默认不要同步到云端**，并定期清理。

**归档与同步的安全边界**：解压不可信压缩包不要用 root，先看一眼条目（`tar -tf`、`7z l`），防止路径穿越写到 `~/.ssh` 之类的目录；`syncthing` 的设备 ID 就是信任凭据，添加设备前核对完整 ID，不要接受陌生设备的共享请求。

## 可复现实验：工具与索引的事实

```bash
command -v nautilus dolphin thunar nemo ranger yazi 2>/dev/null
fd --version 2>/dev/null
rg --version 2>/dev/null | head -1
fzf --version 2>/dev/null
plocate -S 2>/dev/null || locate -S 2>/dev/null
systemctl status plocate-updatedb.timer --no-pager | head -6
time rg -l 'Wayland' /usr/share/doc 2>/dev/null | head -5
```

本机结果：`nautilus`/`dolphin`/`thunar`/`yazi` 等未安装时 `command -v` 无输出；`plocate` 的索引统计能看出条目数与更新时间；`rg`/`fd` 的版本决定可用选项。**「工具没装」「索引过期」「忽略规则生效」是三种不同原因**，分别用 `command -v`、`-S`、`-I/-H` 验证。

## 失败模式

| 现象 | 根因 | 处置 |
| ------------------------------ | ------------------------------------------ | ------------------------------------------------------ |
| `locate` 搜不到刚建的文件 | 索引未更新 | `sudo updatedb`，确认 timer 在跑 |
| `fd`/`rg` 搜不到仓库里的文件 | 被 `.gitignore`/隐藏规则排除 | 加 `-I`/`-H`，或换 `find` |
| 文件管理器看不到网络盘 | 缺 `gvfs` 或挂载服务 | 装 `gvfs` 对应模块，按桌面生态配置 |
| 缩略图不显示 | 缺缩略图生成器 | 装 `ffmpegthumbnailer`/`poppler` 等 |
| Wayland 下 `xclip` 无效 | 协议不兼容 | 改用 `wl-clipboard` |
| 后台脚本读不到剪贴板 | Wayland 焦点/授权限制 | 改成前台触发，或走合成器提供的接口 |
| 归档后中文文件名乱码 | 编码/工具选项不一致 | 统一 UTF-8，必要时用 `7z` 指定编码 |
| 同步工具产生冲突文件 | 两端同时修改 | 单点编辑或版本控制，冲突文件手工合并 |

## 验证与回滚

```bash
command -v fd rg fzf plocate
plocate -S 2>/dev/null | head -4
fd -H pattern | head -5
rg -n 'pattern' path | head -5
echo "$XDG_SESSION_TYPE"
wl-paste --version 2>/dev/null || echo "无 wl-clipboard"
```

「工具是否存在、索引是否新鲜、忽略规则是否干扰、会话是否 Wayland」四项能解释绝大多数「搜不到/复制不了」。验收标准是**用同一条查询在两种工具下对比结果**，而不是只看单次输出。

回滚：

- 工具装错用 `pacman -Rns`；它们不写系统配置，卸载即回原状。
- 索引损坏时删索引目录重建（`plocate` 的数据库路径可由 `-S` 查看），再 `updatedb`。
- 剪贴板工具切换只是换命令，不影响数据。

## 取舍边界

- **图形 vs 终端文件管理器**：要拖放、缩略图、集成搜索用图形；要键盘流、远程/低资源用 `yazi`/`ranger`。
- **`locate` vs `fd`/`rg`**：全盘按名查用 `locate`；按内容、按忽略规则、要实时结果用 `rg`/`fd`。
- **`fd` vs `find`**：日常用 `fd`（快、默认合理）；需要最全的元数据条件时用 `find`。
- **`fzf` vs 专用搜索**：`fzf` 是过滤器，适合与 `fd`/`rg` 组合；要索引与排名用专用工具。
- **`rsync` vs `syncthing`**：一次性/脚本化备份用 `rsync`；多机持续双向同步用 `syncthing`，但要处理冲突。
- **归档格式**：跨平台交付用 `zip`；保留权限/符号链接用 `tar`；高压缩比用 `7z`，注意专利与兼容性。

## 小结

- 文件管理器跟桌面生态走；网络盘与缩略图依赖 `gvfs` 与生成器。
- `locate` 靠索引、`fd`/`rg` 靠实时遍历；搜不到先分清「索引过期」与「忽略规则」。
- `updatedb` 由 timer 驱动，新文件搜不到先手动更新。
- Wayland 剪贴板用 `wl-clipboard`，且受焦点与协议限制。
- 归档、同步各选一类：`tar`/`zip`/`7z`，`rsync`/`syncthing`。
- 验证靠「同查询多工具对比」，不靠单次结果。

## 练习

1. 工具盘点：查本机有哪些文件管理器与搜索工具，列出各自版本。
2. 索引实验：新建一个文件，`locate` 搜索，再 `updatedb` 后重搜，记录差异。
3. 忽略规则：在一个 git 仓库里用 `fd` 搜一个被忽略的文件，再加 `-I`/`-H` 对比。
4. 剪贴板：按会话类型选择 `wl-copy` 或 `xclip`，验证读写，并解释 Wayland 的限制。
5. 归档对比：用 `tar` 与 `7z` 打包同一目录，比较体积与是否保留权限。
6. 同步设计：为「两台机器同步笔记」选择工具，写出冲突处理策略。
