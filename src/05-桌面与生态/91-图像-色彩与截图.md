# 第 91 章 图像、色彩与截图

图片看起来比视频简单，但「颜色不对」是桌面里最难解释的问题之一：同一张图片在不同应用、不同屏幕上不一样，往往不是应用坏了，而是**色彩管理没有贯通**。这一章讲图像格式、ICC 色彩管理、截图与批处理工具，重点是把「格式问题」与「色彩问题」分开。

> 本章目标：能按用途在 PNG、JPEG、WebP、AVIF、SVG 之间选择；理解 sRGB、Display P3、ICC profile 与渲染意图的关系；知道广色域屏幕为什么会让普通图片「发灰/过饱和」；会按会话类型选择截图工具（X11 的 `import`/Flameshot、Wayland 的 `grim`+`slurp` 或 portal）；能用 `ffmpeg`/ImageMagick 做批量转换与格式核验；能识别「截图全黑」「颜色发灰」「格式不兼容」三类问题。
> 对应 Wiki：[Color Management](https://wiki.archlinux.org/title/Color_Management)、[Screen capture](https://wiki.archlinux.org/title/Screen_capture)、[GIMP](https://wiki.archlinux.org/title/GIMP)、[ImageMagick](https://wiki.archlinux.org/title/ImageMagick)

## 格式选型

| 格式 | 压缩 | 透明 | 动画 | 典型用途 | 注意 |
| ---------- | ---------- | ---- | ---- | ------------------------ | ------------------------------ |
| PNG | 无损 | 支持 | 有（APNG） | 截图、图标、线稿 | 体积大，不适合照片 |
| JPEG | 有损 | 不支持 | 无 | 照片分发 | 多次保存会累积失真 |
| WebP | 有损/无损 | 支持 | 支持 | 网页、聊天 | 老软件兼容性一般 |
| AVIF | 有损/无损 | 支持 | 支持 | 网页、归档 | 编码慢，老设备不支持 |
| TIFF | 无损 | 支持 | 无 | 印刷、扫描 | 体积大，网页不用 |
| SVG | 矢量 | 支持 | 支持 | 图标、图稿 | 不是位图，编辑方式不同 |
| HEIF | 有损 | 不支持 | 支持 | 手机照片 | 专利与兼容性问题 |

原则：**截图与线稿用 PNG，照片分发用 JPEG/WebP，网页追求体积用 AVIF，图标用 SVG**。格式转换要区分「有损→无损」（体积暴涨、画质不恢复）与「无损→有损」（不可逆）。

## 色彩管理：为什么颜色会变

| 概念 | 含义 | 典型值 |
| -------------- | ---------------------------------- | ------------------------------ |
| 色彩空间 | 像素数值对应的颜色范围 | sRGB、Display P3、Adobe RGB |
| ICC profile | 描述某设备/文件如何解释颜色的数据 | 显示器 ICC、图片内嵌 ICC |
| 渲染意图 | 色域不匹配时如何映射 | perceptual、relative colorimetric |
| 位深 | 每通道位数 | 8-bit、10-bit、16-bit |

普通图片默认按 **sRGB** 解释；广色域显示器如果不做色彩管理，会把 sRGB 内容「拉伸」到更大色域，看起来过饱和；反之，广色域图片在没有 profile 的软件里会发灰。正确链路是：**图片内嵌或假定 sRGB → 色彩管理模块转换到显示器 ICC → 输出**。

```bash
ls /usr/share/color/icc/ 2>&1
ls ~/.local/share/color/icc/ 2>&1
```

本机没有 `/usr/share/color/icc`，说明这套最小系统既没装 ICC 配置也没有 `colord`；**这不影响看图，但意味着广色域屏幕无法被正确校准**。需要校色时装 `colord` 与校准工具（如 DisplayCAL），生成显示器 ICC 后再由色彩管理模块加载。

## 截图与录屏：按会话类型选

| 会话 | 工具 | 说明 |
| ---------- | ------------------------------ | ---------------------------------------------- |
| X11 | `import`（ImageMagick）、Flameshot | 直接抓 X 根窗口/区域 |
| Wayland（wlroots） | `grim` + `slurp` | 走合成器截屏协议，区域用 `slurp` 选 |
| Wayland（KDE/GNOME） | Spectacle、内置截图 | 走各自合成器与 portal |
| 通用（受限环境） | `xdg-desktop-portal` 截图接口 | 应用通过 portal 请求，兼容性最好 |

```bash
grim -g "$(slurp)" /tmp/shot.png # wlroots：选区截图
grim /tmp/full.png # 全屏
spectacle -b -n -o /tmp/shot.png # KDE：后台截图
```

Wayland 下「截图全黑」通常不是工具坏了，而是**工具没走合成器协议**：X11 工具在 Wayland 会话里抓到的是空根窗口。先确认 `XDG_SESSION_TYPE`，再选对应工具（第 84 章）。

## 三个代表应用

- **GIMP**：位图编辑，适合修图、合成、格式转换；启动慢，适合精修而非批处理。
- **Krita**：绘画与插画，笔刷与色彩管理更专业；也常用于概念图与贴图。
- **ImageMagick**：命令行批处理的事实标准，`magick`/`convert` 做缩放、裁剪、格式转换、加水印。

```bash
sudo pacman -S imagemagick
magick input.png -resize 50% output.webp
magick input.jpg -quality 82 output.jpg
magick identify input.png
```

`magick identify` 输出尺寸、位深、色彩类型与文件大小，是「这张图到底是什么」的快速核验；在只装了 `ffmpeg` 的环境里，`ffprobe` 也能读出 PNG/JPEG 的宽高与像素格式。

## 可复现实验：生成、核验、转换

在 `/tmp` 生成一张 PNG 并核验（本机已实测）：

```bash
ffmpeg -hide_banner -loglevel error \
  -f lavfi -i testsrc=duration=1:size=320x200 -frames:v 1 /tmp/b6-img.png -y
file /tmp/b6-img.png
ffprobe -hide_banner -show_entries stream=codec_name,width,height,pix_fmt \
  -of default=noprint_wrappers=1 /tmp/b6-img.png
```

预期输出：

```text
/tmp/b6-img.png: PNG image data, 320 x 200, 8-bit/color RGB, non-interlaced
codec_name=png
width=320
height=200
pix_fmt=rgb24
```

再转成 WebP 与 JPEG，比较体积与位深：

```bash
ffmpeg -hide_banner -loglevel error -i /tmp/b6-img.png /tmp/b6-img.webp -y
ffmpeg -hide_banner -loglevel error -i /tmp/b6-img.png -q:v 4 /tmp/b6-img.jpg -y
ls -l /tmp/b6-img.png /tmp/b6-img.webp /tmp/b6-img.jpg
```

**预期**：WebP/JPEG 明显小于 PNG；JPEG 不再有 alpha 通道。这一步同时验证了「格式转换」与「有损/无损」的差别。

## 失败模式

| 现象 | 根因 | 处置 |
| ------------------------------ | ------------------------------------------ | ------------------------------------------------------ |
| 截图全黑/只有桌面背景 | Wayland 下用了 X11 截图工具 | 换 `grim`/`spectacle`/portal 路径 |
| 图片在广色域屏上过饱和 | 未做色彩管理，sRGB 被拉伸 | 装 `colord` 与显示器 ICC，启用色彩管理 |
| 广色域图片发灰 | 软件忽略内嵌 ICC 或按 sRGB 解释 | 用支持 ICC 的查看器/编辑器，转换到 sRGB 再分发 |
| 多次另存后画质明显下降 | JPEG 反复有损压缩 | 中间编辑用 PNG/TIFF，最后只导出一次 JPEG |
| 网页图片在老设备打不开 | AVIF/WebP 兼容性不足 | 提供 JPEG/PNG 回退，或按目标平台选格式 |
| 缩放后锯齿/模糊 | 缩小未用合适重采样 | `magick -resize` 用 Lanczos；放大用 AI/专用算法 |
| 打印颜色与屏幕差异大 | 屏幕未校准、纸张/墨水 profile 缺失 | 校准显示器，打印时按纸张 ICC 做软打样 |
| 图标显示为空白方块 | SVG 渲染器缺失或图标缓存未更新 | 装 SVG 支持，`gtk-update-icon-cache`（第 87 章） |

## 验证与回滚

```bash
file image.png
ffprobe -hide_banner -show_entries stream=codec_name,width,height,pix_fmt -of default=noprint_wrappers=1 image.png
magick identify image.webp 2>/dev/null
echo "$XDG_SESSION_TYPE"
command -v grim slurp spectacle import 2>/dev/null
```

「格式/尺寸/位深」用 `file`/`ffprobe`/`identify` 核验；「截图工具是否匹配会话」用会话类型与工具存在性核验。颜色问题只能靠**带 ICC 的查看器 + 校准过的显示器**验证，命令行无法替代眼睛与校色仪。

回滚：

- 格式转换保留原文件，输出到新路径，不原地覆盖。
- 截图工具装错不会破坏系统，换回原工具即可；卸载用 `pacman -Rns`。
- 色彩管理配置（`colord`、ICC 路径）改前备份 `~/.local/share/color/icc` 与相关配置。

## 取舍边界

- **PNG vs JPEG/WebP**：要透明与无损选 PNG；照片分发选 JPEG/WebP；网页追体积选 AVIF 并提供回退。
- **sRGB vs 广色域**：跨设备分发一律 sRGB 最稳；只在印刷/影视流程内使用广色域，并全程色彩管理。
- **8-bit vs 16-bit**：8-bit 够日常；渐变多、反复调色用 16-bit，代价是体积与性能。
- **GIMP vs Krita**：修图/合成选 GIMP；绘画/笔刷选 Krita。两者都能做格式转换，但批处理不如 ImageMagick。
- **命令行 vs GUI 截图**：脚本化、可复现选 `grim`/`import`；交互标注选 Flameshot/Spectacle。
- **校准硬件 vs 纯软件**：校色仪能真正校准；纯软件只能套用厂商 ICC，效果有限。

## 小结

- 格式按用途选：截图/线稿 PNG，照片 JPEG/WebP，网页 AVIF，图标 SVG。
- 颜色变了先查色彩管理：sRGB、ICC、渲染意图、位深四个概念。
- 截图工具必须匹配会话：X11 用 `import`/Flameshot，Wayland 用 `grim`/`spectacle`/portal。
- GIMP 修图、Krita 绘画、ImageMagick 批处理，三者定位不同。
- `file`/`ffprobe`/`identify` 能核验格式与尺寸，颜色只能靠校准与 ICC 链路。
- 有损转换不可逆，编辑中间产物用无损格式。
