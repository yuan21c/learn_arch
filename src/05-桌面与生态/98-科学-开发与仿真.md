# 第 98 章 科学、开发与仿真

这一类应用跨度很大：从 Python 脚本到 CAD、EDA、数值仿真。它们的共同点不是界面，而是**依赖地狱**——同一台机器上不同项目要不同版本的库、编译器、CUDA。本章讲「怎么隔离环境、怎么验证依赖」，而不是逐个软件写安装步骤。

> 本章目标：能按「脚本统计 / 数值仿真 / CAD 与 EDA / GPU 计算」四类负载选择代表工具；理解系统 Python 的 `EXTERNALLY-MANAGED` 机制与 venv 的作用；知道什么时候该用容器而不是 venv；会核对 CUDA/ROCm 与驱动版本；能识别「pip 装不进系统」「ABI 版本不匹配」「CAD 缺 OpenGL」三类问题。
> 对应 Wiki：[List of applications/Science](https://wiki.archlinux.org/title/List_of_applications/Science)、[Python](https://wiki.archlinux.org/title/Python)、[CUDA](https://wiki.archlinux.org/title/CUDA)、[FreeCAD](https://wiki.archlinux.org/title/FreeCAD)、[KiCad](https://wiki.archlinux.org/title/KiCad)

## 四类负载

| 类别 | 代表 | 关键依赖 | 隔离方式 |
| ---------------- | ------------------------------ | ------------------------------ | ------------------------------ |
| 脚本与统计 | Python（NumPy/SciPy/pandas）、R | 解释器、BLAS/LAPACK | venv / renv |
| 数值与仿真 | Julia、Octave | 编译器、数学库 | 独立环境/容器 |
| CAD 与 EDA | FreeCAD、KiCad | OpenGL、Qt、Python 绑定 | 系统包为主 |
| GPU 计算 | CUDA、ROCm | 驱动 + 工具包版本严格匹配 | 容器（官方镜像） |

## 环境隔离：venv 是底线

Arch 的系统 Python 标记为「外部管理」，直接 `pip install` 会被拒绝：

```bash
ls /usr/lib/python3*/EXTERNALLY-MANAGED
python -m venv ~/venv/proj
source ~/venv/proj/bin/activate
pip install numpy pandas
```

- `EXTERNALLY-MANAGED` 是 PEP 668 的标记，防止 pip 覆盖 `pacman` 管理的文件；**不要用 `--break-system-packages` 绕过**，那会让 `pacman -Syu` 与 pip 互相破坏。
- 科学计算的基础库优先用 `pacman` 装（`python-numpy`、`python-scipy`、`python-matplotlib`），编译好的 BLAS 链接更省事；纯 Python 包再进 venv。
- 需要精确复现时，venv 不够——它只隔离 Python 包，不隔离系统库与 CUDA。此时用容器（第 71–73 章），把「系统 + 依赖 + 代码」一起锁定。

R 用 `renv` 做项目级包隔离；Julia 用项目环境（`Pkg.activate`）；Octave 的包管理较弱，重依赖项目更适合作容器。

## 代表应用与来源

| 应用 | 包名（官方仓库） | 用途 | 备注 |
| -------------- | ------------------------------ | ------------------------------ | ------------------------------ |
| NumPy/SciPy | `python-numpy`、`python-scipy` | 数值计算 | 先装系统包，再 venv 补 |
| R | `r` | 统计与绘图 | 项目级用 `renv` |
| Julia | `julia` | 数值/科学计算 | 自带包管理器 |
| Octave | `octave` | MATLAB 兼容仿真 | 大型工具箱需额外包 |
| FreeCAD | `freecad` | 参数化 CAD | 依赖 OpenGL/Qt |
| KiCad | `kicad` | 电路设计与 PCB | 版本与库要配套 |

CUDA/ROCm 不在「装个包就行」的范畴：**工具包版本必须与驱动匹配**，且 GPU 架构要在支持列表内（第 82 章）。拿不准时用厂商提供的容器镜像，避免污染宿主。

## 三层版本匹配：驱动 / 工具包 / 框架

GPU 计算报错十有八九是这三层里有一层对不上：

| 层 | 例子 | 由谁决定 | 不匹配的表现 |
| -------------- | ------------------------------ | ------------------------------ | ------------------------------ |
| 驱动 | `nvidia`/`nvidia-open`、`amdgpu` | 内核与 pacman（第 82 章） | `nvidia-smi` 失败、设备不可见 |
| 工具包 | CUDA Toolkit、ROCm | 手工安装或容器镜像 | 编译通过但运行时找不到库 |
| 框架 | PyTorch/TensorFlow 等 | 框架自带的运行时 | `CUDA error`、回落到 CPU |

关键点：**框架常自带 CUDA 运行时，但仍要求驱动不低于某个最低版本**；所以「装了 CUDA 12.x」不等于「任何框架都能跑」。核对顺序是先驱动（`nvidia-smi` 显示的版本）、再工具包（`nvcc --version`）、最后框架（`torch.cuda.is_available()`），从下往上修，不要一上来就重装框架。

## 可复现实验：解释器、依赖与隔离

```bash
python -c 'import sys; print(sys.executable); print(sys.prefix)'
python -c 'import numpy; print(numpy.__version__)' 2>&1
ls /usr/lib/python3*/EXTERNALLY-MANAGED 2>&1
pip --version 2>&1
pacman -Si python-numpy | grep -E 'Repository|Version' | head -2
pacman -Si freecad | grep -E 'Repository|Version' | head -2
```

本机结果：`python-numpy`、`r`、`julia`、`freecad`、`kicad`、`octave` 都在官方仓库；`EXTERNALLY-MANAGED` 存在时 `pip install` 会被拒绝。**先确认「当前解释器是谁、前缀在哪、依赖从哪来」**，再谈装包。

最小隔离演练（只写 `/tmp` 与家目录）：

```bash
python -m venv /tmp/b6-venv
/tmp/b6-venv/bin/pip install --quiet numpy
/tmp/b6-venv/bin/python -c 'import numpy; print(numpy.__version__)'
rm -rf /tmp/b6-venv
```

venv 内的 `numpy` 与系统包互不影响；`sys.prefix` 指向 venv 目录，这就是「隔离生效」的证据。

## 失败模式

| 现象 | 根因 | 处置 |
| ------------------------------ | ------------------------------------------ | ------------------------------------------------------ |
| `pip install` 报 `externally-managed-environment` | PEP 668 保护系统 Python | 用 venv/容器，不要 `--break-system-packages` |
| 升级后 `pacman -Syu` 与 pip 冲突 | 两套包管理器写同一路径 | 系统包归 pacman，第三方归 venv |
| `import` 报 ABI/`.so` 错误 | Python 版本或编译选项不匹配 | 在 venv 里重装，统一 Python 版本 |
| CUDA 程序报版本不匹配 | 工具包与驱动版本不兼容 | 按厂商矩阵选版本，或改用官方容器 |
| FreeCAD 启动黑屏/崩溃 | OpenGL/驱动问题 | 按第 82 章确认驱动；虚拟机开 3D |
| KiCad 库缺失/版本不符 | 符号库与工程版本不配套 | 装匹配的库包，按工程要求固定版本 |
| R 包编译失败 | 缺系统头文件/编译器 | 装 `base-devel` 与对应 `-dev` 库，或用二进制包 |
| 绘图中文变方块 | 缺 CJK 字体 | 装字体并配置 matplotlib 字体（第 87 章） |
| 结果无法复现 | 只锁了代码没锁依赖 | 记录版本文件 + 容器镜像，锁定全部依赖 |

## 验证与回滚

```bash
python -c 'import sys; print(sys.prefix)'
python -m pip list --format=freeze | head -10
pacman -Qo "$(python -c 'import numpy; print(numpy.__file__)')" 2>&1
nvidia-smi 2>/dev/null | head -6
rocminfo 2>/dev/null | head -8
```

- `sys.prefix` 判断「在不在 venv」；`pip list` 记录当前环境包版本；`pacman -Qo` 判断某个文件是否由系统包提供，从而区分「pacman 的 numpy」与「venv 的 numpy」。
- GPU 计算用 `nvidia-smi`/`rocminfo` 确认驱动与设备，版本不匹配时先修驱动再谈工具包。

回滚：

- venv 直接删目录即可，不影响系统；
- 系统包用 `pacman -Rns`；
- 容器环境 `podman rm -f` 加卷清理；
- 驱动/工具包降级按第 52 章的降级流程，先查缓存与 Arch Archive。

## 取舍边界

- **venv vs 容器**：只隔离 Python 包用 venv；要隔离系统库、CUDA、编译器时用容器。容器更重但复现性更强。
- **系统包 vs pip**：基础数值库用 pacman，版本一致、编译优化好；小众包用 venv，避免污染系统。
- **R/Julia 项目环境 vs 全局**：项目级隔离避免版本冲突；全局安装只适合个人一次性脚本。
- **开源 CAD vs 商业**：FreeCAD/KiCad 可控、可脚本化，复杂曲面/大规模 PCB 可能仍不如商业工具。
- **GPU vs CPU**：GPU 加速收益大但版本与架构限制多；小规模计算先用 CPU，确认瓶颈再上 GPU。
- **最新版 vs 锁定版**：科研复现优先锁定版本；追新只在不影响复现的实验环境。

## 小结

- 四类负载：脚本统计、数值仿真、CAD/EDA、GPU 计算，隔离方式不同。
- 系统 Python 有 `EXTERNALLY-MANAGED`，不要用 `--break-system-packages`；用 venv。
- venv 只隔离 Python 包；要锁系统库与 CUDA 就用容器。
- NumPy/SciPy/R/Julia/FreeCAD/KiCad/Octave 多在官方仓库；CUDA/ROCm 要匹配驱动。
- `sys.prefix` 与 `pacman -Qo` 能区分环境来源。
- 复现要锁「代码 + 依赖 + 系统」，三者缺一都可能失败。
