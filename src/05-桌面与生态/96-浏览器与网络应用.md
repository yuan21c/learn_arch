# 第 96 章 浏览器与网络应用

浏览器是现代桌面上最复杂的应用：它自己就是一个运行平台（渲染引擎、GPU 进程、沙箱、扩展、Web 应用）。这一章不比较跑分，而是讲**为什么浏览器在 Linux 上会「能用但不好用」**：硬解、Wayland、沙箱、配置隔离、字体，五个点各管一类症状。

> 本章目标：能按隐私、兼容、扩展生态在 Firefox、Chromium 及其衍生版之间选择；理解浏览器的多进程沙箱与 user namespace 依赖；知道 VA-API 硬解与 `chrome://gpu`/`about:support` 的验证方法；会在 Wayland 与 XWayland 之间切换浏览器后端；能用独立 profile 隔离工作与个人数据；能识别「视频 CPU 占用高」「Wayland 下模糊/闪烁」「profile 锁死」三类问题。
> 对应 Wiki：[Firefox](https://wiki.archlinux.org/title/Firefox)、[Chromium](https://wiki.archlinux.org/title/Chromium)、[Browser](https://wiki.archlinux.org/title/Browser)

## 选型

| 浏览器 | 引擎 | 优点 | 代价 | 适合 |
| ------------ | ---------------- | ------------------------------ | ------------------------------ | ------------------------------ |
| Firefox | Gecko | 隐私控制、容器标签、开源 | 某些企业站点兼容性略差 | 日常、隐私优先、多账号隔离 |
| Chromium | Blink | 兼容性最好、PWA 成熟 | 与 Google 生态耦合、资源占用高 | 开发调试、需要 Chrome 兼容 |
| Brave | Blink（衍生） | 内置拦截、Chromium 兼容 | 自有代币/推广争议 | 想要 Chromium 兼容 + 拦截 |
| LibreWolf | Gecko（衍生） | 隐私默认强化 | 更新略滞后、部分站点需放宽 | 隐私优先、可接受少量兼容问题 |

衍生版（Brave、LibreWolf、ungoogled-chromium）多在 AUR 或第三方仓库；**装之前确认来源与更新方式**，浏览器是攻击面最大的应用之一，不建议长期用无人维护的构建。

## 多进程与沙箱

现代浏览器把渲染、GPU、网络、扩展拆成独立进程，用沙箱限制互相影响：

- Chromium 系默认用 **user namespace 沙箱**；内核禁用非特权 user namespace 时，会退回 SUID 沙箱（`chrome-sandbox` 需 `4755` 且属主 root）。
- 在容器里跑浏览器常因缺少 namespace 权限而失败；`--no-sandbox` 能绕过，但等于关掉主要防护，**只在隔离的临时环境使用**。
- Firefox 的内容进程沙箱同样依赖内核特性，`about:support` 里能看到沙箱状态。

```bash
sysctl user.max_user_namespaces 2>/dev/null
unshare -Ur true && echo "非特权 user namespace 可用" || echo "不可用"
```

这两项决定「沙箱能不能用」：`user.max_user_namespaces` 为 0 或 `unshare` 失败，说明内核/安全策略禁用了非特权 user namespace；浏览器要么报错，要么退化到弱沙箱。

## 硬解与 Wayland

视频硬解（第 82、90 章）在浏览器里默认不一定开启：

- Firefox：`about:support` 看 `Media` 段的硬解状态；`about:config` 里确认 `media.ffmpeg.vaapi.enabled` 与硬件解码相关项；Wayland 会话通常已默认启用。
- Chromium：打开 `chrome://gpu`，看 `Video Decode` 是否为 `Hardware accelerated`；命令行可显式传 VA-API 相关 feature 开关。
- 判断标准一致：**播放 1080p/4K 时 CPU 占用明显下降**，且 `chrome://gpu`/`about:support` 显示硬件路径。

Wayland 后端：

```bash
MOZ_ENABLE_WAYLAND=1 firefox # Firefox 在现代版本通常已默认
chromium --ozone-platform=wayland
```

在 Wayland 会话里跑 XWayland 版本的浏览器，常见表现是模糊、光标异常或高 DPI 不跟随；加后端参数或改用原生 Wayland 构建可解决。Electron 应用同理，多数接受 `--ozone-platform=wayland`。

## Profile：把身份与数据分开

```bash
ls ~/.mozilla/firefox/
ls ~/.config/chromium/ 2>/dev/null
firefox -P # 打开 profile 管理器（若支持）
```

- Firefox 的 profile 在 `~/.mozilla/firefox/`，缓存另在 `~/.cache/mozilla/`。
- Chromium/Chrome 的 profile 在 `~/.config/chromium/`（或 `~/.config/google-chrome/`）。
- 用独立 profile 隔离「工作账号 / 个人账号 / 测试账号」，比在同一 profile 里反复登录安全；Firefox 还可用「容器标签」在同一窗口隔离站点数据。
- 配置目录可以整体备份，但**不要在浏览器运行时复制**，数据库可能处于不一致状态。

同步与密码：浏览器自带同步把数据交给厂商；在意隐私时用本地密码管理器（第 80 章）或自建同步，不要同时开多个来源导致冲突。

## 可复现实验：版本、配置与沙箱

```bash
pacman -Si firefox | grep -E 'Repository|Version' | head -2
pacman -Si chromium | grep -E 'Repository|Version' | head -2
command -v firefox chromium 2>/dev/null
ls -d ~/.mozilla ~/.config/chromium 2>/dev/null
cat /proc/sys/user/max_user_namespaces
ss -tlnp 2>/dev/null | grep -E ':8080|:3000' | head -5
```

本机结果：`firefox`/`chromium` 在官方仓库；未安装时 `command -v` 无输出；`max_user_namespaces` 可读，决定沙箱可用性。**包存在、程序存在、profile 存在是三件事**，排障时逐项确认。

## 失败模式

| 现象 | 根因 | 处置 |
| ------------------------------ | ------------------------------------------ | ------------------------------------------------------ |
| 播放视频 CPU 占用很高 | 硬解未启用或驱动不支持 | `about:support`/`chrome://gpu` 确认，按第 82 章修驱动 |
| Wayland 下界面模糊/闪烁 | 跑的是 XWayland 版本 | 加 `MOZ_ENABLE_WAYLAND=1` 或 `--ozone-platform=wayland` |
| 启动报 `profile is already in use` | 另一个实例占用 profile 锁 | 关掉旧进程；`ps` 查残留，必要时删 `lock` 文件 |
| 沙箱报错、无法启动 | 容器/内核缺 user namespace | 换非容器环境；不要长期 `--no-sandbox` |
| 网页字体异常/方块 | 缺字体或字体匹配错 | 装 CJK/emoji 字体，`fc-cache`（第 87 章） |
| 受 DRM 保护视频黑屏 | Widevine 未装或架构不符 | 按发行版说明装 Widevine，注意许可 |
| 扩展导致页面崩溃 | 扩展与版本不兼容 | 安全模式启动排查，逐个禁用 |
| 书签/密码丢失 | 同步冲突或 profile 损坏 | 从备份恢复 profile；先停浏览器再复制 |

## 验证与回滚

```bash
firefox --version 2>/dev/null
chromium --version 2>/dev/null
ls -l ~/.mozilla/firefox/profiles.ini 2>/dev/null
cat /proc/sys/user/max_user_namespaces
```

版本决定可用特性（Wayland 默认、VA-API 支持）；`profiles.ini` 列出所有 profile；`max_user_namespaces` 决定沙箱模式。硬解与后端只能在实际播放/会话里验证。

回滚：

- 改坏的 `about:config` 项可在安全模式重置；整个 profile 出问题用备份目录替换。
- 命令行参数（Wayland、feature 开关）去掉即可回到默认。
- 装错衍生版用 `pacman -Rns` 卸载，profile 目录先备份再删。

## 取舍边界

- **Firefox vs Chromium**：隐私与容器隔离选 Firefox；站点兼容与 PWA 选 Chromium。两者并存、按用途分工是常见做法。
- **原生包 vs Flatpak**：原生包与系统库一致、启动快；Flatpak 自带运行时、隔离强，但字体/主题/输入法要多配一层。
- **沙箱 vs 兼容**：保持沙箱是默认；`--no-sandbox` 只在一次性隔离环境用，不能当成日常方案。
- **多 profile vs 单 profile**：多 profile 隔离清晰但占空间、要手动切换；单 profile 方便但账号与扩展混在一起。
- **硬解 vs 稳定**：硬解省电但个别驱动会黑屏/花屏；不稳定时先关硬解，再按第 82 章排查。
- **同步 vs 本地**：厂商同步方便但数据出境；本地密码管理器与自建同步更可控，代价是要自己维护。

## 小结

- 浏览器是平台：多进程、沙箱、GPU 进程、扩展，各自会独立出问题。
- 选型按隐私/兼容/生态：Firefox、Chromium 为主，衍生版注意来源与更新。
- 沙箱依赖 user namespace；容器或硬化内核下失败时，不要用 `--no-sandbox` 当长期方案。
- 硬解用 `about:support`/`chrome://gpu` 验证，判据是 CPU 占用与实际解码路径。
- Wayland 后端用 `MOZ_ENABLE_WAYLAND`/`--ozone-platform=wayland`，避免 XWayland 的模糊与缩放问题。
- 多 profile 隔离身份；备份 profile 前先停浏览器。

## 练习

1. 现状盘点：查 Firefox/Chromium 的仓库版本、是否安装、profile 目录与 `max_user_namespaces`，判断沙箱模式。
2. 硬解验证：播放一段 1080p 视频，记录 `about:support` 或 `chrome://gpu` 的硬解状态与 CPU 占用。
3. 后端对比：在 Wayland 会话里分别用默认与 `--ozone-platform=wayland` 启动浏览器，记录缩放与清晰度差异。
4. Profile 隔离：为「工作/测试」建两个独立 profile，说明切换方式与数据隔离范围。
5. 沙箱分析：解释为什么容器里浏览器常启动失败，列出两种修复思路及各自代价。
6. 故障注入：故意让一个 profile 留下 `lock` 文件，观察启动报错并写出清理步骤。
