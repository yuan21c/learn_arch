# 第 20 章 分区、文件系统与挂载进阶

第 18 章走通了「分区 → 格式化 → 挂载 → fstab」的主线，第 19 章补了 LVM、btrfs 与 zram。本章只处理主线上的三个进阶问题：**分区表怎么被脚本化地管理、一次挂载在内核里究竟发生了什么、文件系统与挂载选项该怎么选。** 这里不重复 `lsblk`、`mkfs`、fstab 六字段等基础操作，遇到它们会指回第 18 章；本章的落点是「同一件事有多种做法时，边界在哪」。

> 本章目标：能用 `parted`/`sfdisk` 以脚本方式读写 GPT，并理解分区类型 GUID 的作用；能说清 VFS、挂载命名空间与 bind mount 的关系；理解 fstab 与 systemd `.mount`/`.automount` 单元的生成关系；掌握 atime 系列、`nofail`、`x-systemd.*` 等挂载选项的适用边界；能按场景选出 ext4、XFS、btrfs、f2fs、exfat、ntfs3；会用 `unshare -m` 在隔离命名空间里做零风险的挂载实验。

## 分区表进阶：类型 GUID 与脚本化

GPT 的每个分区条目除了起止扇区，还有一个**类型 GUID**，它告诉固件与操作系统「这个分区是干什么用的」——EFI 系统分区、Linux 根、swap、LVM PV 各有自己的 GUID。类型不对通常不影响 Linux 自己挂载，但会影响固件识别、双系统工具判断，以及 systemd 的 GPT 自动发现（`systemd-gpt-auto-generator` 靠它找 ESP、swap 与 `/home`）。

查看与设置（只读优先，写操作在 VM 或 loop 设备上做）：

```bash
sudo parted /dev/vda print # 列出分区、起止、大小、类型编号
sudo parted /dev/vda unit MiB print free # 以 MiB 显示，并列出空隙
sudo sfdisk -d /dev/vda # 导出分区表为可重放的脚本格式（备份用）
```

脚本化重建的关键是**先导出、再改动、最后复核**。`sfdisk` 的导出格式本身就是一份可回放的输入，这比在交互式 `fdisk` 里手敲安全：

```bash
# 会改写分区表：假设 /dev/vdb 是确认可丢弃的盘，不要在数据盘上照抄
sudo sfdisk -d /dev/vdb > /tmp/vdb.layout.bak # 1. 备份现有布局
sudo parted -s /dev/vdb mklabel gpt # 2. 建 GPT 标签（-s 非交互）
sudo parted -s /dev/vdb mkpart primary ext4 1MiB 512MiB # 3. 建分区
sudo parted -s /dev/vdb set 1 esp on # 4. 把 1 号分区标为 ESP
sudo partprobe /dev/vdb && udevadm settle # 5. 让内核重读
lsblk -f /dev/vdb # 6. 复核：分区存在、类型正确
```

与交互式工具相比，`parted -s` 的每一步都是一条可审阅的命令，适合写进安装脚本；代价是**没有确认提示**，`mklabel` 会直接重写分区表。`sfdisk` 更适合「整表回放」，`parted` 更适合「单步操作」。两者都要求目标盘未被挂载——对已挂载的分区改表，内核可能仍用旧映射，写操作会落到错误的扇区。

## 挂载在内核里发生了什么

「挂载」不是把一个目录填满，而是**在 VFS 的目录树上挂一个 `mount` 结构**：它记录「哪个文件系统、挂到哪个 dentry、用什么选项」。同一个文件系统可以被挂多次，每次是独立的 `mount` 实例；`findmnt` 看到的是这些实例，而不是磁盘布局。

```bash
findmnt -o TARGET,SOURCE,FSTYPE,OPTIONS / # 看根的挂载实例与选项
findmnt -T /etc/hosts # 查某个路径属于哪个挂载实例
```

**挂载命名空间**（mount namespace）让每个进程看到不同的挂载树。这是容器隔离的基础，也给了我们一个零风险做挂载实验的办法：在自己的命名空间里 `mount`/`umount`，不影响宿主。

**权限前提**：创建挂载命名空间需要 `CAP_SYS_ADMIN`。普通用户在 Arch 上直接跑 `unshare -m` 会得到 `unshare: unshare failed: Operation not permitted`（本书验证环境实测，`capsh --print` 的 `Current:` 为空）。两条出路：用 root 会话（`sudo -i`），或者同时创建用户命名空间——`unshare -Urm`，`-U` 建用户命名空间、`-r` 在其中映射为 root，这样普通用户也能拿到该命名空间内的 `CAP_SYS_ADMIN`。

```bash
unshare -Urm --propagation private bash # 普通用户可用；root 会话里去掉 -U、-r 即可
findmnt /tmp # 与宿主一致
mount --bind /etc /tmp # 只在当前命名空间生效
findmnt /tmp # 预期：SOURCE 显示 /etc
exit # 退出后宿主完全不受影响
```

`--propagation private` 是必要的：默认的共享传播（shared）会把子命名空间里的挂载事件传回父命名空间，实验就可能真的改到宿主。做任何「先试试挂载」的操作，都应该放进 `unshare -m`，而不是直接在宿主上 `mount` 再 `umount`。用 `-U` 建的用户命名空间还有个副作用：命名空间内的 root 只对「属于该命名空间的文件系统视图」有权限，真实的块设备与宿主的 `/etc` 仍受原本的 DAC 约束。

**bind mount** 把已有目录再挂一次，常用于给容器暴露目录、或在救援时把 `/etc` 复制到可写位置。它的回滚要点是**卸载顺序与挂载顺序相反**：后挂的先卸，否则会报 `target is busy`。

## fstab 与 systemd 单元：谁在真正执行挂载

第 18 章把 fstab 当作「开机自动挂载」的配置，但真正执行它的不是 systemd 自己解析，而是**生成器**：`systemd-fstab-generator` 在启动早期读 `/etc/fstab`，为每个条目生成 `.mount` 单元（swap 生成 `.swap`）。所以两件事同时成立：

- fstab 里能写的选项，只有生成器认识的那部分会转成单元属性；`x-systemd.*` 前缀的选项是专门给生成器看的（如 `x-systemd.automount`、`x-systemd.device-timeout`、`x-systemd.requires`）。
- 你也可以**绕过 fstab 直接写 `.mount` 单元**，获得 fstab 表达不了的能力（精确依赖、`What=` 用设备路径、按需挂载的 `.automount`）。代价是配置分散，`findmnt --verify` 不会检查它。

```bash
systemctl list-units --type=mount --all # 看当前有哪些挂载单元
systemctl status tmp-lab17.mount # 单元名由挂载点路径转义而来：/ 变 -
```

单元命名规则值得记住：挂载点 `/tmp/lab17` 对应 `tmp-lab17.mount`（开头的 `/` 去掉、`/` 换成 `-`）。路径里本身有 `-` 时转义规则更绕，所以**不要靠手算单元名**，用 `systemctl list-units --type=mount` 查。

## 挂载选项：按代价分类

挂载选项很多，按「解决什么问题」分四类就够用了：

| 类别 | 选项 | 作用 | 代价 |
| ---------- | ------------------------------ | ------------------------ | ------------------------ |
| 时间戳 | `atime`/`relatime`/`noatime` | 控制是否更新访问时间 | `noatime` 省 I/O，但依赖 atime 的工具会失真 |
| 可靠性 | `sync`/`async`、`errors=remount-ro` | 写盘时机与出错策略 | `sync` 极慢；`errors=` 决定故障时的行为 |
| 启动韧性 | `nofail`、`x-systemd.device-timeout=` | 设备缺失不阻塞启动 | 设备真的坏了也不会报警，需另行监控 |
| 按需与权限 | `x-systemd.automount`、`user`、`nosuid`/`nodev`/`noexec` | 延迟挂载、允许普通用户挂载、收紧权限 | `automount` 首次访问有延迟；`noexec` 会让脚本无法执行 |

`relatime` 是多数发行版的默认：只在 atime 早于 mtime 或超过一天时更新，兼顾兼容与开销。`noatime` 更激进，适合 SSD 与大并发读；如果跑的是依赖「读过的文件」做清理的工具（某些备份、缓存），先确认它是否需要 atime。

`nofail` 在第 18 章已出现过（外置盘必加），这里补它的反面：**加了 `nofail` 就等于放弃「设备缺失时启动失败」这个告警**。生产机上应配合监控（检查 `findmnt` 里该挂载点是否存在），否则一次没插上的盘会静默缺失几周。

`noexec`、`nosuid`、`nodev` 是给不可信挂载点用的（U 盘、`/tmp` 单独分区、容器卷）。它们的边界很明确：**只防「从这个挂载点执行」，不防「把文件复制到别处再执行」**，所以是纵深防御的一层，不是沙箱。

## tmpfs：内存里的文件系统

`tmpfs` 把文件放在内存与 swap 里，读写快、重启即失。它适合 `/tmp`、`/run`、编译缓存；不适合放需要持久化的数据。

```bash
sudo mount -t tmpfs -o size=64m tmpfs /mnt # 大小必须显式限制
df -h /mnt # 预期：总量约 64M
```

不写 `size` 时 tmpfs 默认可用一半内存，**一个失控的写入进程能把内存吃光并触发 OOM**。所以生产机上挂 tmpfs 一定要写 `size=`。`ramfs` 更原始：不限制大小、不参与 swap，几乎不该在正常系统上使用。

## 文件系统选型

| 文件系统 | 优势 | 明确短板 | 典型用途 |
| -------- | ------------------------------ | ------------------------------ | ---------------------- |
| ext4 | 成熟、可缩可扩、工具链完整 | 无内置校验和、快照弱 | 通用根、`/home`、虚拟机盘 |
| XFS | 大文件与高并发写强、扩展性好 | **只能扩不能缩**、元数据修复工具受限 | 大容量数据盘、日志盘 |
| btrfs | 校验和、快照、子卷、透明压缩 | 部分场景性能与 RAID56 有争议 | 需要快照回滚的根、桌面 |
| f2fs | 为闪存设计、随机写友好 | 成熟度与工具链不如 ext4 | eMMC、SD 卡、嵌入式 |
| exfat | 跨平台（主流桌面系统直读） | 无 Unix 权限、无日志 | U 盘、移动硬盘 |
| ntfs3 | 内核内 NTFS 驱动、性能较好 | 另一系统的休眠/快速启动会留下脏状态 | 双系统共享盘 |

选型的判据不是「哪个更快」，而是**你最需要哪个性质**：要快照回滚选 btrfs，要大文件吞吐选 XFS，要通用与可缩容选 ext4，要跨平台交换选 exfat。`ntfs3` 挂载写入在双系统间切换时仍可能因另一系统的快速启动/休眠留下脏状态；遇到内核报「卷处于休眠（hibernated）状态、拒绝挂载」，要回到那个系统做完整关机，而不是休眠或快速启动。

## 失败模式

- **挂载点被覆盖**：往一个已有内容的目录上挂载，原内容不会消失但**看不见了**；卸载后才恢复。往 `/mnt` 里 `mount` 前先确认它是空目录。
- **对已挂载分区改表**：`parted` 改分区边界后，内核仍用旧映射；必须先 `umount` 再改，改完 `partprobe`。
- **fstab 路径含空格**：fstab 用空白分字段，路径里的空格要写成 `\040`，否则解析错位导致开机进 emergency。
- **`nofail` 掩盖缺失**：设备没插时不报错，业务读到的是空目录——「文件消失」类故障先 `findmnt` 看挂载在不在。
- **传播导致实验外泄**：`unshare -m` 未加 `--propagation private` 时，子命名空间的挂载可能传播回宿主。
- **`unshare` 直接报 Operation not permitted**：普通用户没有 `CAP_SYS_ADMIN`；用 `sudo -i`，或改用 `unshare -Urm`（用户命名空间内映射 root）。
- **tmpfs 无上限**：不写 `size=` 时按内存一半，写入失控会 OOM，且 OOM 时系统可能先杀别的进程。
- **XFS 缩容**：`xfs_growfs` 只能扩，想缩小只能备份重建；规划分区时按「可能变大」留余量。

## 验证与回滚

| 操作 | 验证 | 回滚 |
| ------------------ | ---------------------------------------- | -------------------------------- |
| 改分区表 | `sfdisk -d` 备份，改后 `lsblk -f` 复核 | 用备份布局 `sfdisk` 回放（数据未必能恢复） |
| 试挂载 | `unshare -m` 隔离，`findmnt` 确认 | 退出命名空间，零残留 |
| 改 fstab | `findmnt --verify`；再 `umount` + `mount -a` 全新验证 | 恢复 `.bak`，emergency 下 `mount -o remount,rw /` |
| 加 tmpfs | `df -h` 确认 size 生效 | `umount` 即回收内存 |
| 换文件系统 | 新盘先 `mkfs` 到空分区试挂 | 格式化不可逆，唯一退路是备份 |

「格式化不可逆」这一点在第 18 章已经强调过，这里补一句它的**推论**：任何「先试试这个文件系统」的想法，都必须落在空分区、loop 设备或快照上，而不是已有数据的分区。

## 取舍边界

- **分区 vs LVM vs btrfs 子卷**：分区最简单、工具最通用；LVM 提供跨盘伸缩与快照（第 19 章）；btrfs 子卷提供目录级快照与配额。需要「在线扩容 + 快照」选后两者，只需要「一块盘一个文件系统」就留在分区。
- **单独 `/home` vs 单根**：单独 `/home` 让重装系统不影响数据，代价是分区规划要预留空间、跨分区移动数据更麻烦；桌面机常用，容器与一次性 VM 不需要。
- **fstab vs `.mount` 单元**：绝大多数场景 fstab 足够且集中；需要精确依赖、按需挂载、或挂载点由其他单元动态决定时，才写 `.mount`/`.automount`。
- **`noatime` vs `relatime`**：桌面与通用服务器用 `relatime`；高写入负载的 SSD 数据盘可用 `noatime`，但要先确认没有工具依赖访问时间。

## 小结

- GPT 分区带类型 GUID，影响固件识别与 systemd 自动发现；`sfdisk -d` 导出可回放布局，`parted -s` 适合脚本化单步操作。
- 挂载是 VFS 里的 `mount` 实例，不是「填目录」；`findmnt` 看实例，`unshare -m`（普通用户加 `-Urm`）配合 `--propagation private` 提供零风险实验环境。
- fstab 由 `systemd-fstab-generator` 转成 `.mount` 单元；`x-systemd.*` 是给生成器的选项；单元名由挂载点转义而来。
- 挂载选项按四类理解：时间戳、可靠性、启动韧性、按需与权限；`nofail` 会掩盖设备缺失，需配监控。
- tmpfs 必须写 `size=`；文件系统选型看「最需要的性质」，XFS 不能缩、exfat 无 Unix 权限、ntfs3 需防另一系统休眠残留。
- 所有分区表与格式化的回滚都依赖备份；挂载类操作可以先在命名空间里验证。

## 练习

1. 分区表侦察（只读）：`sudo parted /dev/vda print` 与 `sudo sfdisk -d /dev/vda` 各跑一次，指出分区类型编号与 GUID 的位置，并说明导出文件为什么能当备份。
2. 脚本化分区（会改写分区表：只用可丢弃的磁盘或快照）：加一块空盘，用 `parted -s` 建 GPT、建一个分区并设为 ESP，`partprobe` 后 `lsblk -f` 复核；再用 `sfdisk` 回放备份布局。
3. 命名空间挂载（零风险实验；普通用户用 `unshare -Urm`，root 用 `unshare -m`）：在命名空间里 `mount --bind /etc /tmp`，`findmnt /tmp` 确认；退出后宿主 `findmnt /tmp` 应无变化——记录两次输出的差异。
4. 挂载单元：`systemctl list-units --type=mount --all` 列出单元，挑一个把单元名还原成挂载点路径；再 `findmnt` 对照。
5. tmpfs 限制（需 root，可在实机）：`mount -t tmpfs -o size=32m tmpfs /mnt`，用 `dd if=/dev/zero of=/mnt/f bs=1M count=64` 观察写满后的报错，`df -h /mnt` 确认上限，最后 `umount`。
6. 选项对照：对一个测试挂载分别用 `relatime` 与 `noatime` 挂载，`findmnt -o OPTIONS` 确认选项生效；说明各自适合什么负载。
