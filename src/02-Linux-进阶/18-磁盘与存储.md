# 第 18 章 磁盘与存储

第 5 章把文件系统讲成了「目录树 + inode」，但没回答一个更基础的问题：这些 inode 和数据块到底长在什么上面，又是怎么被挂进那棵树的？本章从块设备开始，一路走到分区表、文件系统、`/etc/fstab`、swap 与 LVM。**注意环境差异**：本章前半的只读观察在任何机器上都适用；带「可丢弃磁盘」标记的步骤会改写块设备，只能在可丢弃的磁盘（虚拟机新增空盘或快照）里做，不要在承载数据的磁盘上照抄。真机上操作前先备份。

> 本章目标：能用 `lsblk`、`blkid`、`df`、`du` 看清磁盘与用量；理解 MBR 与 GPT 的差别、分区→格式化→挂载这条链路；会读写 `/etc/fstab`（六个字段、UUID、`nofail`）；能创建与启用 swap；理解 LVM 的 PV/VG/LV 三层模型并能扩容逻辑卷；知道 TRIM、`fsck` 与 SMART 各自的用途。
> 对应 Wiki：[File systems](https://wiki.archlinux.org/title/File_systems)、[Fstab](https://wiki.archlinux.org/title/Fstab)、[LVM](https://wiki.archlinux.org/title/LVM)、[Swap](https://wiki.archlinux.org/title/Swap)

块设备是能按块读写的设备，硬盘、SSD、U 盘、虚拟磁盘都算。查看用 `lsblk`（只读）：

```bash
lsblk # 树形列出设备、分区、挂载点
lsblk -f # 追加文件系统类型、UUID、LABEL
blkid # 只列带文件系统的设备及其 UUID
```

`lsblk -f` 的输出是理解整章的钥匙：`NAME` 是设备名（`sda`、`nvme0n1`、`vda`），下一层缩进的是分区（`sda1`、`nvme0n1p2`），`FSTYPE` 是文件系统，`UUID` 是格式化时生成的身份标识，`MOUNTPOINT` 是它挂在哪。虚拟机里看到的是可随意重建的虚拟磁盘，分区、格式化、改 fstab 都能反复练——这正是练习安装要用虚拟机的原因。

用量有两个命令，容易混：

| 命令 | 回答的问题 | 数据来源 |
| ------------- | ---------------------------------------- | --------------------------------------------------- |
| `df -h` | 每个**已挂载文件系统**用了多少、还剩多少 | 超级块统计 |
| `du -sh 目录` | **某个目录**下所有文件占了多少 | 按目录树累加块占用（`st_blocks`），口径与 `df` 不同 |

`df` 与 `du` 对不上是常态：被删除但仍被进程打开的文件仍占空间（`df` 算、`du` 不算），可以用 `lsof +L1` 找出来（`lsof` 不在 base，`sudo pacman -S lsof`；也可遍历 `/proc/*/fd` 看指向已删除（deleted）的 fd——`fuser` 不能定位已删除但仍打开的文件）；文件系统的保留块（ext4 默认 5%，`tune2fs -m` 可调）也只体现在 `df` 里。

## 分区表：MBR 与 GPT

分区表是磁盘开头的一小块元数据，描述「哪一段扇区属于哪个分区」。

| 对比 | MBR（msdos） | GPT |
| ---------- | ---------------------------------------------- | --------------------- |
| 分区数上限 | 4 个主分区（或 3 主 + 扩展分区里再分逻辑分区） | 默认 128 个 |
| 容量上限 | 2 TiB | 极大（64 位 LBA） |
| 冗余 | 无备份 | 主副两份表 + CRC 校验 |
| 固件配合 | BIOS | UEFI（也兼容 BIOS） |

现代系统用 GPT。三种工具各有习惯（**均在虚拟机里操作**）：

```bash
sudo fdisk -l /dev/vda # 只读：列出分区表
sudo fdisk /dev/vda # 交互式：g 先建 GPT（默认是 MBR！）、m 帮助、n 新建、t 改类型、p 复核、w 写入
sudo gdisk /dev/vda # GPT 专用，交互逻辑类似
sudo parted /dev/vda print # 非交互友好：print / mkpart / rm
```

> **危险**：分区表写入（`fdisk` 的 `w`、`parted` 的 `mkpart`）会立刻改变磁盘布局。在真机上操作前先确认设备名——`/dev/sda` 与 `/dev/sdb` 一字之差就是另一块盘。

## 格式化：创建文件系统

分区只是容器，里面还要放文件系统。**格式化会清空该分区上的数据**（会改写块设备：只在可丢弃的磁盘或虚拟机快照里做）：

> **危险**：`mkfs` 系列重建文件系统，目标分区数据全部消失且不可恢复。执行前 `lsblk -f` 确认设备名与现有文件系统，重要数据先备份；演练一律用虚拟机的空白盘。

```bash
sudo mkfs.ext4 /dev/vda2 # ext4：通用、可缩可扩
sudo mkfs.xfs /dev/vda2 # XFS：大文件与并发好，只能扩不能缩
sudo mkfs.fat -F 32 /dev/vda1 # FAT32：EFI 系统分区常用
```

检查与调参：

```bash
sudo fsck -N /dev/vda2 # 只列出会做什么，不真跑
sudo tune2fs -l /dev/vda2 # 看 ext4 超级块参数（保留块比例、UUID）
sudo tune2fs -m 1 /dev/vda2 # 把保留块从 5% 调到 1%（大盘常用）
```

`fsck` 必须在**未挂载**状态下运行；对已挂载的 ext4 强行检查可能损坏数据。日常不需要手跑：开机时 `systemd-fsck-root.service` 与 `systemd-fsck@.service` 会按 fstab 的 `pass` 字段决定检查哪些文件系统（Arch 没有 `fsck.timer`）。

## 挂载：把文件系统接进目录树

Linux 没有「C 盘」，只有一棵树，挂载就是把某个文件系统的根接到树上某个目录（挂载点）。

```bash
sudo mkdir -p /mnt/data
sudo mount /dev/vda2 /mnt/data # 手动挂载
findmnt /mnt/data # 确认挂载参数与来源
sudo umount /mnt/data # 卸载；设备忙时先找占用进程
sudo mkdir -p /mnt/etc-copy
sudo mount --bind /etc /mnt/etc-copy # 绑定挂载：把已有目录再挂一次
```

`umount` 报 `target is busy` 时，用 `lsof +D /mnt/data` 或 `fuser -vm /mnt/data` 找占用者。

### /etc/fstab：开机自动挂载

手挂只在本次开机有效。要持久化就写 `/etc/fstab`，每行六个字段：

```text
# <设备> <挂载点> <类型> <选项> <dump> <pass>
UUID=1234abcd-... / ext4 rw,relatime 0 1
UUID=5678ef01-... /home ext4 rw,noatime 0 2
UUID=ABCD-1234 /boot vfat rw,umask=0077 0 2
UUID=9999aaaa-... none swap defaults 0 0
```

字段含义：`dump` 是旧工具用的备份标志，填 `0`；`pass` 是开机 `fsck` 顺序，根为 `1`、其他为 `2`、不检查为 `0`。设备**优先写 `UUID=`**（用 `blkid` 取），因为 `/dev/sda1` 会随插拔顺序变化。常用选项：`noatime`（不记录访问时间，SSD 友好）、`nofail`（设备不存在也能开机，U 盘与外置盘必加）、`x-systemd.automount`（按需挂载）。

改完**先测试再重启**（会改写块设备：只在可丢弃的磁盘或虚拟机快照里做）：

```bash
sudo mount -a # 只处理「尚未挂载」的条目；已手挂的不会被读——验证要先 umount 再 mount -a，然后 findmnt 确认
```

> **危险**：fstab 写错且没加 `nofail` 可能导致系统起不来。改之前备份 `sudo cp /etc/fstab /etc/fstab.bak`，并保留一个可用的 recovery 入口。

## swap：把磁盘当内存的延伸

swap 是内核在内存紧张时换出匿名页的场所。传统做法是 swap 分区，现在更常用 swap 文件：

```bash
sudo dd if=/dev/zero of=/swapfile bs=1M count=4096 # 推荐用 dd：fallocate 并非所有文件系统都支持；btrfs 上不能直接 fallocate，见第 19 章
sudo chmod 600 /swapfile # 权限应为 600，否则 swapon 告警（insecure permissions）
sudo mkswap /swapfile
sudo swapon /swapfile
swapon --show
free -h
```

要开机生效，在 `fstab` 里加一行（`<文件> none swap defaults 0 0`）。把整个分区当 swap 则先确认目标设备，再 `mkswap`、`swapon`：

```bash
swapon --show # 已有 swap 先看清，别重复启用同一块设备
lsblk -f # 找到打算用作 swap 的分区，记为 <swap-partition>（示例值 /dev/vda3，你的机器会不同）
sudo mkswap <swap-partition>
sudo swapon <swap-partition>
```

写 fstab 时用 UUID（`blkid <swap-partition>`）而不是设备名，设备顺序变动后仍能挂上。两点常识：休眠（hibernate）需要 swap 不小于内存，且 initramfs 启动参数要加 `resume=`（swap 文件还需 `resume_offset=`，见第 93 章）；zram 不能作休眠后端（内容在内存、断电即失）；swap 不是「越多越好」，数据库与容器场景应先查内存泄漏，再考虑调 `vm.swappiness`。

## LVM：把磁盘变成可伸缩的池

LVM 在物理磁盘与文件系统之间加了一层抽象，三层模型：

| 层 | 单位 | 命令 | 说明 |
| --- | ------ | ------------------ | --------------------------- |
| PV | 物理卷 | `pvcreate` / `pvs` | 把分区或整盘标记为 LVM 可用 |
| VG | 卷组 | `vgcreate` / `vgs` | 若干 PV 组成的存储池 |
| LV | 逻辑卷 | `lvcreate` / `lvs` | 从池里切出来的「虚拟分区」 |

典型流程会改写块设备，只能在可丢弃的磁盘或虚拟机快照里做。示例只使用一块新建的空盘 `/dev/vdc`；先检查整盘和所有分区，确认没有挂载点、需要保留的数据、文件系统签名或现有 PV。`pvcreate` 会写入 LVM 元数据，目标选错可能破坏已有数据；任何一项不确定都停止，不要继续：

```bash
lsblk -o NAME,SIZE,TYPE,FSTYPE,UUID,MOUNTPOINTS /dev/vdc # 连同分区一起检查
sudo wipefs --no-act /dev/vdc # 只读列出整盘签名；有签名时先查明原因
sudo pvs; sudo vgs; sudo lvs # 确认目标未属于现有 LVM
sudo pvcreate /dev/vdc # 不要把未逐一检查的设备追加到命令
sudo vgcreate vg0 /dev/vdc
sudo lvcreate -L 20G -n data vg0 # 切 20G
sudo mkfs.ext4 /dev/vg0/data
sudo lvextend -r -L +10G /dev/vg0/data # -r 顺带扩文件系统
```

`-r`（`--resizefs`）会在扩展 LV 后尝试同步扩展文件系统；它不替代对目标 LV、挂载点和文件系统类型的确认。在线扩容还要求该文件系统、内核和相应工具支持在线扩容；先用 `findmnt` 确认挂载来源与类型，再用 `df -h` 验证结果。ext4 和 XFS 都支持扩容，但 XFS 不能缩容。卷组有空闲空间时可直接扩展，不必重新分区；代价是多一层映射，救援时需额外激活（`vgchange -ay`）。

## 维护：TRIM、fsck 与 SMART

- **TRIM**：SSD 需要知道哪些块已废弃。`sudo fstrim -av` 手动执行，或启用 `fstrim.timer` 定期跑；也可在挂载选项加 `discard`（在线丢弃，性能开销略高）。
- **fsck**：文件系统一致性检查，只对未挂载设备运行；ext4 用 `e2fsck -f`，XFS 用 `xfs_repair`。
- **SMART**：硬盘健康预测。`smartctl -a /dev/vda` 看 `Reallocated_Sector_Ct`、`Pending_Sector_Ct` 等指标；需要 `smartmontools` 并启用 `smartd`（第 63 章的服务托管思路）。

LVM 扩容全链、`wipefs`/`partprobe`、`findmnt --verify`、btrfs 子卷与 zram 见第 19 章。

## 失败模式

- **`mkfs` 指错设备**：格式化只认设备名，不认「我以为它是那块空盘」；执行前 `lsblk -f` 看签名与挂载点，有数据的设备一律先备份。
- **fstab 写错导致起不来**：UUID 写错、类型写错、缺 `nofail`，开机挂载失败会进 emergency；改前备份，改后 `findmnt --verify`。
- **`mount -a` 验证方法错**：它只处理「尚未挂载」的条目，已挂载的不会重读；验证要先 `umount` 再 `mount -a`。
- **swapfile 权限/预分配不对**：权限不是 `600` 会告警；btrfs 上直接 `fallocate` 的 swapfile 会被 `swapon` 拒绝（需要无洞 + NoCOW）。
- **`pvcreate` 覆盖旧签名**：它会把设备开头的分区表/文件系统元数据清掉；指向有数据的盘等于毁数据。
- **`df` 与 `du` 对不上就以为丢数据**：已删除但被进程占用的文件、硬链接、文件系统保留块都会造成差异；用 `lsof +L1` 查被占用的大文件。
- **克隆后 UUID 冲突**：整盘 `dd` 克隆会带来相同 UUID，同时挂载两台会冲突；用 `uuidgen` + `tune2fs`/`xfs_admin` 重新生成。
- **把 `discard` 与 `fstrim.timer` 当成二选一**：两者都能让 SSD 知道空闲块，在线 `discard` 有持续开销，定期 `fstrim` 更平缓；同时开不是错，但要知道代价。

## 验证与回滚

| 操作 | 验证 | 回滚 |
| ---------------------- | ------------------------------------------------ | ------------------------------------------ |
| 分区/格式化 | `lsblk -f` 看类型、UUID、挂载点；先确认设备空闲 | 分区表可重建，**格式化不可逆**，只能靠备份 |
| 改 fstab | `findmnt --verify`；`umount` 后 `mount -a` 再 `findmnt` | 恢复 `fstab.bak`，或 emergency 下改回 |
| 启用 swap | `swapon --show`、`free -h` 看容量 | `swapoff` 后删除文件/注释 fstab |
| LVM 建卷 | `pvs`/`vgs`/`lvs` 三层核对 | `lvremove`/`vgremove`（会毁数据，先确认） |
| SSD 丢弃 | `fstrim -av` 的输出；`systemctl status fstrim.timer` | 关闭 timer 或移除 `discard` 选项 |

## 取舍边界

- **ext4 vs XFS vs btrfs**：ext4 稳、工具熟；XFS 适合大文件与高并发写，但不能缩小；btrfs 有子卷/快照/校验，代价是复杂度与部分场景的性能。选型按「是否需要快照/校验」而不是「哪个更新」。
- **swap 分区 vs swap 文件 vs zram**：分区最稳、不可灵活调整；文件灵活、受文件系统约束（btrfs 需特殊处理）；zram 快但占内存、不能休眠。桌面常用 zram，服务器常留磁盘 swap 兜底。
- **LVM vs 直接分区**：LVM 换来在线扩容、快照、跨盘卷组，代价是多一层映射与救援步骤；单盘、容量固定的场景直接分区更简单。
- **在线 `discard` vs 定期 `fstrim`**：前者实时但持续开销、可能泄露使用模式；后者批量、平缓。桌面与多数服务器选定期 `fstrim`。
- **容量留白**：文件系统保留块（ext4 默认 5%）与 SSD 预留空间不是浪费，是防碎片与延长寿命；把盘用到 100% 会让写入性能骤降。

## 小结

- `lsblk -f` 一次看全设备、分区、文件系统、UUID、挂载点；`df` 看文件系统用量、`du` 看目录用量，两者不一致有明确原因。
- GPT 取代 MBR；分区 → 格式化 → 挂载是三步独立操作：分区表可重写但旧布局不保证恢复，挂载可撤销，**格式化不可逆**，唯一安全网是备份。
- `/etc/fstab` 六字段：设备（写 UUID）、挂载点、类型、选项、dump、pass；`nofail` 与 `mount -a` 是保命细节。
- swap 文件三件套：`dd` + `chmod 600` + `mkswap`，再 `swapon` 并写 fstab（fallocate 仅在支持的文件系统上使用）。
- LVM 三层 PV/VG/LV；扩容用 `lvextend -r`，没有 `-r` 文件系统不会跟着长。
- 维护三件：`fstrim`、`fsck`（未挂载时）、`smartctl`。

## 练习

1. 只读侦察：运行 `lsblk -f`、`blkid`、`df -h`、`findmnt`，画出本机「设备→分区→文件系统→挂载点」的对应关系，并说明虚拟机的虚拟磁盘与物理磁盘有何差别。
2. 用量对账：对一个目录分别跑 `du -sh` 与 `df -h` 所在文件系统，解释两者统计对象的不同；再用 `lsof +L1` 查是否存在「已删除但被占用」的文件。
3. 分区实践（会改写块设备：只在可丢弃的磁盘或虚拟机快照里做）：给虚拟机加一块 5 GiB 虚拟磁盘，用 `fdisk` 建一个 GPT 分区并 `w` 写入，用 `lsblk` 确认；再把它删掉重建，观察分区表变化。
4. 格式化与挂载（会改写块设备：只在可丢弃的磁盘或虚拟机快照里做）：在新分区上 `mkfs.ext4`，`mkdir /mnt/lab18` 后挂载，写入文件并用 `findmnt` 确认；写出对应的 fstab 行（用 `blkid` 取 UUID，加 `nofail`），`mount -a` 验证无报错。
5. swap 文件（会改写块设备：只在可丢弃的磁盘或虚拟机快照里做）：创建一个 1 GiB swap 文件并启用，用 `swapon --show` 与 `free -h` 确认；写入 fstab 后先 `free -h` 确认内存余量，再 `swapoff -a && swapon -a` 验证配置正确——`swapoff` 会把换出页拉回内存，内存紧张时只 `swapoff /swapfile` 再 `swapon -a`。
6. LVM 扩容（会改写块设备：只在可丢弃的磁盘或虚拟机快照里做）：用两块虚拟盘建 `vg0` 与 10 GiB 逻辑卷，格式化挂载后写入测试文件；`lvextend -r -L +5G` 后用 `df -h` 确认文件系统确实变大，并解释不加 `-r` 会看到什么。
