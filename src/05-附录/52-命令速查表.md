# 第 56 章 命令速查表

本章按篇与工具分组收录常用命令，供日常查阅。表中只给最常用的形式，参数细节以 `man` 和 Wiki 为准。备注列会标出破坏性操作与常见误用。

> 本章目标：快速查到正确命令，并知道哪些命令执行前必须先确认对象。
> 对应 Wiki：[Core utilities](https://wiki.archlinux.org/title/Core_utilities)｜[Pacman](https://wiki.archlinux.org/title/Pacman)｜[Systemd](https://wiki.archlinux.org/title/Systemd)

## 第一篇 Linux 基础

| 目的       | 命令                                                     | 备注                        |
| ---------- | -------------------------------------------------------- | --------------------------- |
| 定位与查看 | `pwd`、`ls -la`、`ls -ld 目录`                           | `-d` 看目录本身而非内容     |
| 复制与移动 | `cp -a 源 目标`、`mv 源 目标`                            | `-a` 保留权限与时间戳       |
| 删除       | `rm -r 目录`、`rm -f 文件`                               | **危险**：先 `ls` 确认目标  |
| 查文件类型 | `file 文件`、`stat 文件`                                 | `stat` 看 inode、时间、权限 |
| 链接       | `ln -s 目标 链接名`、`ln 目标 硬链接`                    | 软链接可跨文件系统          |
| 查找       | `find 目录 -name '*.md'`、`find 目录 -type f -mtime -7`  | 先限定目录再组合条件        |
| 文本查看   | `head -n 20 文件`、`tail -f 文件`、`wc -l 文件`          | `tail -f` 跟日志            |
| 过滤与替换 | `grep -rn 模式 目录`、`sed -i 's/旧/新/g' 文件`          | `sed -i` **危险**：先备份   |
| 取列与排序 | `cut -d: -f1 文件`、`sort -u`、`uniq -c`                 | `uniq` 需要先排序           |
| 权限       | `chmod 644 文件`、`chmod u+x 文件`、`chown 用户:组 文件` | 不要盲目 `777`              |
| 身份       | `id`、`whoami`、`groups`                                 | 确认自己是谁、在哪些组      |
| 提权       | `sudo 命令`、`sudo -i`、`sudo -l`                        | `-l` 查被授予了什么         |

## 第二篇 Linux 进阶

| 目的     | 命令                                                | 备注                          |
| -------- | --------------------------------------------------- | ----------------------------- |
| 进程快照 | `ps aux`、`ps -eo pid,ppid,stat,cmd --sort=-pcpu`   | `%CPU` 是平均值               |
| 动态视图 | `top`（`P`/`M`/`1`/`k`）、`htop`                    | 先看负载与 CPU 核数           |
| 进程树   | `pstree -p`                                         | 看清父子关系                  |
| 作业控制 | `命令 &`、`jobs -l`、`fg %1`、`bg %1`、`disown %1`  | `Ctrl-Z` 是挂起               |
| 信号     | `kill -TERM PID`、`kill -9 PID`、`pkill -TERM 名字` | 先 `TERM` 后 `KILL`           |
| 优先级   | `nice -n 10 命令`、`renice -n 5 -p PID`             | 只有 root 能调低              |
| 脚本骨架 | `set -euo pipefail` + `trap 'rm -rf "$tmp"' EXIT`   | 生产脚本标配                  |
| 磁盘     | `lsblk -f`、`df -h`、`du -sh 目录`                  | `df` 与 `du` 口径不同         |
| 挂载     | `mount 设备 挂载点`、`findmnt`、`mount -a`          | 改完 fstab 先 `mount -a`      |
| 网络     | `ip -br addr`、`ip route`、`ss -tulpn`              | `0.0.0.0` 与 `127.0.0.1` 不同 |
| DNS      | `getent hosts 域名`、`dig +short 域名`              | `getent` 代表程序所见         |
| SSH      | `ssh-keygen -t ed25519`、`ssh-copy-id 用户@主机`    | `~/.ssh` 要 `700`             |

## 第三篇 pacman

| 目的                 | 命令                                                                   | 备注                                              |
| -------------------- | ---------------------------------------------------------------------- | ------------------------------------------------- |
| 完整升级             | `sudo pacman -Syu`                                                     | 日常唯一正确的升级方式                            |
| 换源后强制刷新并升级 | `sudo pacman -Syyu`                                                    | 仅在更换镜像源后使用                              |
| 安装包               | `sudo pacman -S --needed 包名`                                         | `--needed` 跳过已安装的包                         |
| 卸载包、依赖与配置   | `sudo pacman -Rns 包名`                                                | `n` 删除配置文件，**不可恢复**                    |
| 卸载包及无用依赖     | `sudo pacman -Rs 包名`                                                 | 保留配置文件                                      |
| 仓库搜索             | `pacman -Ss 关键字`                                                    | 同时匹配包名与描述                                |
| 已安装包搜索         | `pacman -Qs 关键字`                                                    | 只在本地数据库查找                                |
| 包详细信息           | `pacman -Qi 包名`                                                      | 看依赖、安装原因、安装时间                        |
| 包的文件列表         | `pacman -Ql 包名`                                                      | 确认文件归属与路径                                |
| 文件属于哪个包       | `pacman -Qo /usr/bin/bash`                                             | 按本地数据库查询；文件被删也能查                  |
| 显式安装的包         | `pacman -Qe`                                                           | 排查「为什么装了它」                                |
| 非官方来源的包       | `pacman -Qm`                                                           | AUR、本地 `makepkg` 结果                          |
| 孤立包               | `pacman -Qdt`                                                          | 无人依赖的依赖包                                  |
| 删除孤立包           | `sudo pacman -Rns $(pacman -Qdtq)`                                     | 先单独运行 `-Qdt` 预览                            |
| 清理包缓存           | `sudo paccache -r`                                                     | 每包保留 3 个版本，需 `pacman-contrib`            |
| 只保留 1 个版本      | `sudo paccache -rk1`                                                   | 释放空间更多                                      |
| 安装本地包           | `sudo pacman -U 包名.pkg.tar.zst`                                      | 注意依赖是否满足                                  |
| 降级到缓存版本       | `sudo pacman -U /var/cache/pacman/pkg/包名-旧版本-x86_64.pkg.tar.zst`  | 可能造成依赖不匹配                                |
| 校验包文件           | `pacman -Qkk 包名`                                                     | 不指定包名时校验全部                              |
| 更新密钥环           | `sudo pacman -Sy --needed archlinux-keyring`（随后 `sudo pacman -Su`） | 签名错误、常规 `-Syu` 被中止时使用（第 31、38 章） |
| 刷新文件数据库       | `sudo pacman -Fy`                                                      | 之后可用 `pacman -F 文件名`                       |
| 查找文件提供者       | `pacman -F /usr/bin/bash`                                              | 需先执行 `-Fy`                                    |

**铁律**：不要执行 `pacman -Sy 包名`。只同步数据库而不升级系统会造成部分升级，是 Arch 最常见的事故来源，详见 [第 29 章 pacman 的模型与铁律](../03-Arch-Linux/29-pacman-的模型与铁律.md)。唯一例外是密钥环引导：`sudo pacman -Sy --needed archlinux-keyring` 后**立刻** `sudo pacman -Su`，中间不安装其他包。

## 第三篇 systemd

| 目的               | 命令                                        | 备注                     |
| ------------------ | ------------------------------------------- | ------------------------ |
| 查看单元状态       | `systemctl status 单元名`                   | 失败时先看这里           |
| 立即启动           | `sudo systemctl start 单元名`               | 不影响开机自启           |
| 开机自启并立即启动 | `sudo systemctl enable --now 单元名`        | 最常用的组合             |
| 取消自启并停止     | `sudo systemctl disable --now 单元名`       | 与 `enable --now` 对称   |
| 重启服务           | `sudo systemctl restart 单元名`             | 会中断现有连接           |
| 禁止单元启动       | `sudo systemctl mask 单元名`                | 比 `disable` 更彻底      |
| 解除禁止           | `sudo systemctl unmask 单元名`              |                          |
| 列出失败单元       | `systemctl --failed`                        | 升级后必查               |
| 列出已启用单元     | `systemctl list-unit-files --state=enabled` | 排查自启项               |
| 重载单元文件       | `sudo systemctl daemon-reload`              | 改过 unit 文件后必须执行 |
| 查看定时器         | `systemctl list-timers`                     | 看下次触发时间           |
| 启动耗时           | `systemd-analyze blame`                     | 定位慢服务               |
| 关键启动链         | `systemd-analyze critical-chain`            | 看依赖顺序               |

`enable` 只设置开机自启，`start` 只影响当前运行。两者都不改变对方的状态，这是排障时最常见的误解。

## 第三篇 journalctl

| 目的             | 命令                                   | 备注                    |
| ---------------- | -------------------------------------- | ----------------------- |
| 本次启动全部日志 | `journalctl -b`                        | 默认按时间正序          |
| 上一次启动日志   | `journalctl -b -1`                     | 排查「上次为什么崩」      |
| 指定服务日志     | `journalctl -u 单元名 -b`              | 定位 failed unit 的主力 |
| 本次启动错误日志 | `journalctl -p err -b`                 | 只看 err 及以上级别     |
| 按时间筛选       | `journalctl --since "1 hour ago"`      | 也支持具体日期          |
| 实时跟踪         | `journalctl -f`                        | 类似 `tail -f`          |
| 内核日志         | `journalctl -k -b`                     | 硬件与驱动问题          |
| 查看日志占用     | `journalctl --disk-usage`              | 磁盘满时先看这里        |
| 清理到指定大小   | `sudo journalctl --vacuum-size=200M`   | 保留最近日志            |
| 清理旧日志       | `sudo journalctl --vacuum-time=2weeks` | 按时间清理              |

日志是否持久化到 `/var/log/journal` 取决于配置；重启后看不到上次日志时，先确认 journald 的存储设置。

## 第三篇 makepkg

| 目的             | 命令                                        | 备注                     |
| ---------------- | ------------------------------------------- | ------------------------ |
| 构建并安装       | `makepkg -si`                               | 自动装依赖并安装结果     |
| 只构建           | `makepkg`                                   | 产物在当前目录           |
| 强制重新构建     | `makepkg -f`                                | 强制重建并覆盖已有包文件 |
| 构建后清理       | `makepkg --clean`                           | 删除 `src/` 与 `pkg/`    |
| 生成 .SRCINFO    | `makepkg --printsrcinfo > .SRCINFO`         | AUR 提交必需             |
| 检查 PKGBUILD    | `namcap PKGBUILD`                           | 需安装 `namcap`          |
| 安装本地构建结果 | `sudo pacman -U 包名-版本-架构.pkg.tar.zst` | 与 `makepkg -i` 等价     |

执行 `makepkg` 前必须读 PKGBUILD。AUR 是用户提交内容，不经过官方审核，构建脚本会以你的用户身份运行。

## 第四篇 应用与服务

| 目的               | 命令                                                                                                              | 备注                                                               |
| ------------------ | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 托管应用           | `sudo systemctl enable --now 服务` + `journalctl -u 服务`                                                         | 单元写法见第 46 章                                                 |
| 单元覆盖           | `sudo systemctl edit 服务`、`systemctl cat 服务`、`systemd-analyze verify 单元`                                   | 改完 `daemon-reload`                                               |
| 用户级服务         | `systemctl --user enable --now 服务`、`loginctl enable-linger $USER`                                              | 退出登录后仍运行；不要加 sudo                                      |
| nginx 语法与重载   | `sudo nginx -t`、`sudo systemctl reload nginx`                                                                    | 改站点配置用 reload                                                |
| nginx 反代         | `proxy_pass http://127.0.0.1:8000;` + 四个 `proxy_set_header`                                                     | 见第 47 章                                                         |
| TLS                | `sudo certbot --nginx -d 域名`、`sudo systemctl enable --now certbot-renew.timer`、`sudo certbot renew --dry-run` | 启用 timer 后才自动续期（`systemctl list-timers \| grep certbot`） |
| Apache             | `sudo apachectl configtest`、`sudo systemctl reload httpd`                                                        | 站点根 `/srv/http`                                                 |
| Caddy              | `caddy validate --config /etc/caddy/Caddyfile`、`sudo systemctl reload caddy`                                     | 域名可达即自动签证书                                               |
| MariaDB 初始化     | `sudo mariadb-install-db --user=mysql --basedir=/usr --datadir=/var/lib/mysql`                                    | 只跑一次                                                           |
| MariaDB 登录与备份 | `sudo mariadb`、`sudo mariadb-dump --single-transaction app > app.sql`                                            | root 走 unix_socket                                                |
| PostgreSQL 初始化  | `sudo -u postgres initdb -D /var/lib/postgres/data --auth-local=peer --auth-host=scram-sha-256`                   | 只跑一次；缺 `--auth` 会得到 trust 免密实例（第 51 章）            |
| PostgreSQL 备份    | `sudo -u postgres pg_dump -Fc -f app.dump app`、`sudo -u postgres pg_restore -d app2 app.dump`                    | 角色需 `pg_dumpall --globals-only`                                 |
| 容器               | `docker run -d -p 127.0.0.1:8080:80 -v 卷:路径 镜像`                                                              | `docker` 组等价 root                                               |
| 容器排障           | `docker ps -a`、`docker logs -f 名`、`docker exec -it 名 sh`                                                      |                                                                    |
| rootless 容器      | `podman run`、Quadlet `.container`                                                                                | `podman generate systemd` 已停止开发（第 52 章）                   |
| 虚拟化能力检查     | `ls -l /dev/kvm`                                                                                                  | 无此设备则无硬件加速                                               |
| SSH 配置核对       | `sudo sshd -T`、`sudo systemctl reload sshd`                                                                      | 改完保留旧会话验证                                                 |
| 防火墙             | `nft -c -f /etc/nftables.conf`、`nft list ruleset`                                                                | 远程改前先 `-c` 检查                                               |
| 漏洞自查           | `arch-audit`、`arch-audit -u`                                                                                     | 对照安全公告                                                       |
| 音频               | `wpctl status`、`pavucontrol`                                                                                     | PipeWire 为用户级服务                                              |
| 图形渲染           | `glxinfo \| grep renderer`                                                                                        | 查看渲染路径（需 `mesa-utils`）                                    |
| AppArmor           | `sudo aa-status`                                                                                                  | 查看已加载 profile（第 53 章）                                     |
| 打印               | `lpstat -p -d`、`sudo lpadmin -p 名 -E -v ipp://... -m everywhere`                                                | 启用 `cups.socket`；`lpadmin` 通常需 root 或 CUPS SystemGroup 成员 |
| 电源               | `systemctl suspend`、`systemctl hibernate`                                                                        | 休眠需 swap ≥ 内存，且启动参数要加 resume=（swap 文件需 resume_offset=）；zram 不可作休眠后端                                                 |

## 磁盘、挂载与安装

| 目的                 | 命令                                         | 备注                       |
| -------------------- | -------------------------------------------- | -------------------------- |
| 查看块设备与文件系统 | `lsblk -f`                                   | 分区前必做                 |
| 查看设备详情         | `lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS` | 确认挂载关系               |
| 查看 UUID 与标签     | `sudo blkid`                                 | fstab 与 `root=` 使用      |
| 查看挂载树           | `findmnt`                                    | 比 `mount` 输出清晰        |
| 磁盘使用率           | `df -h`                                      | 排查空间不足               |
| 目录占用             | `du -sh 目录`                                | 逐层定位大目录             |
| 列出分区表           | `sudo fdisk -l`                              | 只读操作                   |
| 编辑分区表           | `sudo fdisk /dev/vda`                        | **危险**：写错设备会丢数据 |
| 格式化 ext4          | `sudo mkfs.ext4 /dev/vda2`                   | **危险**：清空该分区       |
| 格式化 ESP           | `sudo mkfs.fat -F32 /dev/vda1`               | **危险**：清空该分区       |
| 挂载根分区           | `sudo mount /dev/vda2 /mnt`                  | 先挂根                     |
| 挂载 ESP             | `sudo mount --mkdir /dev/vda1 /mnt/boot`     | 后挂 ESP                   |
| 递归卸载             | `sudo umount -R /mnt`                        | 卸载前先退出 chroot        |
| 生成 fstab           | `genfstab -U /mnt >> /mnt/etc/fstab`         | 只能执行一次               |
| 进入新系统           | `arch-chroot /mnt`                           | 需先挂好根与 ESP           |
| 复制并保留属性       | `cp -a 源 目标`                              | 保留权限与时间戳           |
| 同步目录             | `rsync -a 源/ 目标/`                         | 注意结尾斜杠含义           |
| 创建符号链接         | `ln -s 目标 链接名`                          | 先确认目标路径             |
| 修改权限             | `chmod 755 文件`                             | 不要盲目 `777`             |
| 修改属主             | `sudo chown 用户:组 文件`                    | 系统文件慎改               |

> **危险**：`fdisk`、`mkfs`、`dd` 一类命令直接操作块设备，没有回收站。执行前用 `lsblk` 确认设备名与容量，确认目标不是宿主磁盘或 U 盘。真机操作前先备份。

## WSL（Windows PowerShell）

| 目的             | 命令                                                                          | 备注                                                             |
| ---------------- | ----------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 查看 WSL 版本    | `wsl --version`                                                               | 确认支持 systemd                                                 |
| 列出发行版与状态 | `wsl -l -v`                                                                   | 看 WSL 1 还是 2                                                  |
| 关闭所有发行版   | `wsl --shutdown`                                                              | 修改 `wsl.conf` 后执行                                           |
| 终止指定发行版   | `wsl --terminate Arch`                                                        | 不删除数据                                                       |
| 设置默认发行版   | `wsl --set-default Arch`                                                      | 影响直接输入 `wsl` 的行为                                        |
| 导出备份         | `wsl --export Arch D:\backup\arch.tar`                                        | 先 `wsl --terminate Arch`；删除副本用 `wsl --unregister`（危险） |
| 从备份导入       | `wsl --import ArchRestore D:\wsl\arch-restore D:\backup\arch.tar`             | 目标目录会被写入；用新实例名避免同名                             |
| 导入并设默认     | `wsl --import ArchRestore D:\wsl\arch-restore D:\backup\arch.tar --version 2` | 明确使用 WSL 2                                                   |
| 更新 WSL         | `wsl --update`                                                                | 修复部分 systemd 问题                                            |
| 在指定目录启动   | `wsl -d Arch --cd ~`                                                          | 避免落到 `/mnt/c`                                                |

> **危险**：`wsl --import` 会向目标目录写入文件，导入到已有数据的目录可能覆盖内容；`wsl --export` 在发行版运行中执行可能得到不一致的备份。导出前先 `wsl --terminate Arch`，导入前确认目标目录为空。

## 实验依赖包清单

全书实验用到、但最小系统不含的包（按需安装）：`man-db`、`bash-completion`、`acl`、`htop`、`lsof`、`openbsd-netcat`、`bind`、`logrotate`、`base-devel`、`openssh`、`mesa-utils`、`strace`、`namcap`、`pavucontrol`、`rsync`、`alsa-utils`。第四篇另需：`nginx`、`certbot`、`certbot-nginx`、`mariadb`、`postgresql`、`docker`、`docker-compose`、`podman`、`libvirt`、`qemu-full`、`cups`、`fcitx5`、`fcitx5-chinese-addons`、`bluez`、`bluez-utils`。

## 小结

- 查命令先看参数作用，再执行；带 `sudo` 的命令要确认对象。
- pacman 的查询类命令（`-Q*`、`-F*`）是排障基础，破坏性命令集中在 `-Rns`、`-U`。
- systemd 的 `enable` 与 `start` 互相独立，`daemon-reload` 常被遗漏。
- journalctl 优先用 `-u` 和 `-p err` 缩小范围。
- 磁盘类命令执行前必须用 `lsblk` 确认设备。
- WSL 的导出/导入是低成本快照手段，但要在发行版停止时操作。

## 练习

1. 用本表查出 `/usr/bin/bash` 属于哪个包，并列出该包的全部文件。（环境：WSL，命令 `pacman -Qo`、`pacman -Ql`）
2. 分别用 `systemctl status` 和 `journalctl -u` 查看同一个服务的状态与日志。（环境：WSL）
3. 用 `lsblk -o` 自定义输出列，找出虚拟机磁盘的设备名与大小。（环境：VM）
4. 在虚拟机中执行一次 `fdisk -l`，指出哪个设备是 ESP。（环境：VM）
5. 用 `wsl --export` 导出一份备份，再导入到新目录验证可启动。（环境：Windows PowerShell）
6. 找出本表中三条最危险的命令，说明各自的确认步骤。（环境：阅读题）
