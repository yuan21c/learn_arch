# 第 104 章 常见坑与里程碑

学完 103 章之后，真正决定你能否独立维护一台 Arch 的，不是记住了多少命令，而是**踩坑前能不能预判、踩坑后能不能恢复**。这一章把全书反复出现的坑压成一张表，再把 104 章拆成六个可验收的里程碑，最后给三条不同的学习路线。

> 本章目标：能说出 30 个高频坑的根因与处置；能用可执行的自测判断自己是否真的掌握了某一篇；能按自己的目标选择后续方向，而不是盲目往下读。
> 对应 Wiki：[General troubleshooting](https://wiki.archlinux.org/title/General_troubleshooting)、[ArchWiki:About](https://wiki.archlinux.org/title/ArchWiki:About)

## 104.1 三十个常见坑

按「发生频率 × 恢复代价」排序。每条都指回讲它的章；处置列只给第一步，完整流程在对应章。

| # | 现象 | 根因 | 第一步处置 | 章 |
| -- | ------------------------------ | ------------------------------------------ | ------------------------------------------------------ | ---- |
| 1 | 升级后一半软件坏掉 | 执行了 `pacman -Sy 包名`，造成部分升级 | 不要再升单个包；按第 52 章整体 `-Syu`，必要时降级 | 41、52 |
| 2 | 提示签名无效 / 密钥环过期 | `archlinux-keyring` 太旧 | 先 `pacman -Sy --needed archlinux-keyring`，紧接着 `pacman -Su` | 43 |
| 3 | 镜像站 404 或极慢 | 镜像未同步或已下线 | `reflector` 重新排序，确认 `mirrorlist` 未被覆盖 | 39 |
| 4 | 新系统起不来，找不到根 | fstab 的 UUID 写错或没生成 | 用安装介质 chroot，`blkid` 核对后重写 fstab | 18、36 |
| 5 | fstab 里同一分区出现两次 | `genfstab` 执行了多次 | 删重复行，`findmnt --verify` 校验 | 36 |
| 6 | chroot 后 grub 找不到模块 | 没挂 `/boot` 或 ESP | 先挂 ESP 再 `arch-chroot` | 55、58 |
| 7 | 装完引导器直接进固件 | ESP 路径或 `--bootloader-id` 错 | 核对 `efibootmgr -v` 与 `/boot` 挂载 | 58、59 |
| 8 | 内核更新后开机卡在 initramfs | `HOOKS` 缺 `lvm2`/`encrypt`/`resume` | 救援模式重跑 `mkinitcpio -P`，补 hook | 58、60 |
| 9 | 开了 Secure Boot 后无法启动 | 引导程序或内核未签名 | 进固件关闭 SB，或按第 61 章签名 | 61 |
| 10 | 改了 unit 不生效 | 没 `daemon-reload` | `systemctl daemon-reload` 后重启单元 | 44 |
| 11 | 开机不自动起服务 | 只 `start` 没 `enable` | `systemctl enable 单元` | 44 |
| 12 | 服务一启动就退出 | 配置错或前台运行 | `journalctl -u 单元 -b` 看退出码 | 44、63 |
| 13 | `sudo` 提示不在 sudoers | 用户不在 `wheel` 组 | root 下 `usermod -aG wheel 用户` | 9、38 |
| 14 | SSH 改配置后连不上 | `sshd_config` 语法错或禁用了密码 | 保留一个已登录会话，`sshd -t` 先验证 | 26 |
| 15 | 启用防火墙后自己断网 | 默认拒绝且没放行已建立连接 | 先 `nft -c -f` 校验，保留本地 console | 25 |
| 16 | 改了 `/etc/resolv.conf` 又被覆盖 | 由 `systemd-resolved` 或网络管理器托管 | 改上游配置而不是结果文件 | 27 |
| 17 | LUKS 盘换机后打不开 | header 损坏且没有备份 | 从 header 备份恢复；没有备份只能重建 | 22 |
| 18 | RAID 重建后装错盘 | `/dev/sdX` 顺序漂移 | 用 `/dev/disk/by-id` 或 UUID | 21 |
| 19 | btrfs 显示有空间却写不进 | 元数据或 qgroup 配额满 | `btrfs filesystem usage`、`btrfs balance` | 19 |
| 20 | 休眠直接失败 | swap 小于内存或没配 `resume=` | 按第 93 章核对 swap 与 `resume_offset` | 93 |
| 21 | 合盖不睡 / 睡下不醒 | logind 策略被别的电源服务覆盖 | 检查 `logind.conf`，`power-profiles-daemon` 与 `tlp` 只留一个 | 93 |
| 22 | 装完显卡驱动黑屏 | 驱动与内核版本不匹配 | 救援模式卸驱动，改用内核自带模块 | 82 |
| 23 | Wayland 下截图/录屏失败 | 合成器未实现 portal 接口 | 装对应 portal 包，或临时切 X11 会话 | 84 |
| 24 | 输入法候选框不跟随 | Wayland `text-input` 支持不足 | 按合成器 Wiki 处理；XWayland 程序另测 | 94 |
| 25 | 两个候选框同时出现 | IBus 与 Fcitx5 同时在跑 | 只保留一个框架，删另一个自启项 | 94 |
| 26 | 中文显示成方框 | 缺中文字体或 locale | 装 `noto-fonts-cjk`，`localectl set-locale` | 87、101 |
| 27 | 蓝牙设备搜不到 | `rfkill` 软/硬阻断 | `rfkill list`；软阻断 `unblock`，硬阻断查开关 | 88 |
| 28 | 打印机队列一直卡住 | 后端不可达或队列被暂停 | `cupsenable`，看 `localhost:631` 错误日志 | 92 |
| 29 | 容器写宿主机目录权限错 | 容器内 UID 与宿主不一致 | 命名卷；Podman（rootless）用 `--userns=keep-id` 保持宿主 UID，Docker 无此参数，改用 `--user $(id -u):$(id -g)` 并保证目录属主匹配 | 72 |
| 30 | 备份从没验证过 | 只做备份不做恢复演练 | 每季度做一次完整恢复演练 | 40 |

`--userns=keep-id` 是 **Podman 的 rootless 用法**（约 4.3 起稳定），`podman run --help | grep userns` 可自查你的版本支持情况；Docker 没有这个值，照抄会直接报 `invalid userns mode`。

共同规律：**大部分坑不是命令错，而是顺序错或对象错**。顺序错（先升级单个包、先开防火墙后放行、先改配置后验证）靠流程避免；对象错（磁盘、分区、单元、用户）靠「执行前打印一遍对象」避免。

## 104.2 六个里程碑

每个里程碑都给「能做什么」与「怎么自测」。自测不通过就回到对应篇，不要继续往下读。

### 里程碑一：第一篇（第 1–12 章）——能在命令行里安全工作

- 能解释发行版、内核、用户空间的关系；能画出一次命令从输入到进程的路径。
- 能不用复制粘贴完成：查找文件、改权限、过滤文本、用管道组合两条命令。
- 自测：`find /etc -name '*.conf' | wc -l`、`grep -rn 'PermitRootLogin' /etc/ssh/`、`id`、`umask` 都能解释输出含义。

### 里程碑二：第二篇（第 13–32 章）——能定位进程、存储与网络问题

- 能用 `ps`/`top`/`strace` 判断 CPU、内存、I/O 三类负载；能读 `lsblk`、`df`、`findmnt`。
- 能区分 LVM、RAID、LUKS 各自解决什么问题；能用 `ip`、`ss`、`dig`、`tcpdump` 分层排查网络。
- 自测：给一台「能 ping 通但打不开网页」的机器，能在 10 分钟内定位到 DNS、路由、端口或应用层。

### 里程碑三：第三篇（第 33–62 章）——能独立安装、维护一台 Arch

- 能从零安装到可登录，包括分区、pacstrap、chroot、引导器、用户与 sudo。
- 能解释滚动发布的风险；能读 Arch News；能处理 `.pacnew`；能在救援环境 chroot 修复。
- 自测：在虚拟机里完成一次「装错引导器 → 用安装介质修复」的全流程，并写出步骤。

### 里程碑四：第四篇（第 63–80 章）——能跑起服务并守住边界

- 能写一个 systemd unit 并让它开机自启；能配 nginx + TLS；能备份与恢复数据库。
- 能解释容器与虚拟机的边界；能用 Podman/Docker 部署一个无状态服务；能列出主机加固的五个动作。
- 自测：给一个「服务重启后数据丢失」的场景，能判断是卷、权限还是数据库事务的问题。

### 里程碑五：第五篇（第 81–101 章）——能搭出可日常使用的桌面

- 能从最小图形环境走到完整桌面：驱动、合成器或 DE、显示管理器、字体、输入法、音频。
- 能解释 X11 与 Wayland 的差异；能按「半年内是否用到」决定深讲、精讲还是查索引。
- 自测：在虚拟机里装一个 Wayland 合成器，完成中文输入、音频播放、截图三件事；说出每步依赖的包。

### 里程碑六：第六篇（第 102–104 章）——能查、能判断、能继续走

- 能用第 102 章在 1 分钟内查到正确命令；能用第 103 章把任意主题定位到章。
- 能背出本章的十条高频坑并说出处置；能给自己选一条后续路线。
- 自测：不看目录，说出第 22、45、61、92 章各讲什么，并给出一个该章命令。

## 104.3 三条学习路线

同一本书，不同目标的人读法不同。三条路线都要求先完成里程碑一、二（第 1–32 章），再把第三篇的 pacman（41–43）与 systemd（44–45）作为**公共必修**（这也是 README 里「必须练熟」的全书主干），之后按重点章分叉。

| 路线 | 适合谁 | 公共必修 | 路线重点章（在必修之上增删） | 可以略读 | 终点能力 |
| ---------- | -------------------------- | ------------------------------------------------------ | ------------------------------------------------------ | ---------------------- | -------------------------------------- |
| 桌面日常 | 把 Arch 当主力桌面 | 1–32、41–45 | 35–39、52–55、81–101 | 47–51、67–75 | 能自己装机、配桌面、处理升级事故 |
| 服务器运维 | 管 VPS、家庭服务器、容器 | 1–32、41–45 | 35–39、63–75、76–80 | 81–101 | 能部署服务、做备份、加固与排障 |
| 安全与底层 | 想深入内核、启动链、加固 | 1–32、41–45 | 46、58–62、76–80，加 47–51 | 81–101 的大部分 | 能解释启动链与信任链、能审计主机 |

路线不是身份，可以换。换路线时先补该路线「重点章」里没读的部分，不必从头再来。

注意：「可以略读」只针对非终点能力相关的章；公共必修里的 1–32 与 41–45 不属于任何路线的「可以略读」，跳过它们会在备份、升级与服务托管处卡住。

## 104.4 完成本书之后

- **读上游文档**：`man`、`/usr/share/doc`、内核 `Documentation/`、systemd 的 man 页，比二手教程准。
- **跟 Arch News**：升级前看一次，能避免大部分「升级后要手动干预」的事故。
- **做恢复演练**：备份、快照、chroot 修复各演练一次；没演练过的恢复手段等于没有。
- **选一个方向深入**：内核与驱动、容器编排、网络安全、自动化与配置管理（Ansible/Nix），任选其一。
- **参与上游**：报一个真实 bug、写一段 Wiki、维护一个 AUR 包；这是从「会用」到「懂」的最快路径。

## 失败模式

| 现象 | 根因 | 处置 |
| -------------------------------- | ------------------------------------------ | ------------------------------------------------------ |
| 每个坑都靠搜索，修完不知道为什么好 | 只记命令不记模型 | 回到对应章的「原理」节，用自己的话复述一遍 |
| 读完就忘，自测通不过 | 跳过了练习与里程碑 | 按 104.2 的自测逐项做，不通过就回炉 |
| 总在同一个地方出事 | 流程缺一步（确认对象、备份、验证） | 把该步骤写进自己的检查清单，固定下来 |
| 越学越散，什么都想看 | 没有目标路线 | 先选 104.3 的一条路线，按重点章推进 |
| 修好一次又坏一次 | 没做根因分析，只处理了症状 | 记录「现象 → 根因 → 验证」，下次按同一路径排查 |
| 不敢动生产机 | 没做恢复演练 | 先在虚拟机演练，再按第 55 章的救援流程实操一次 |

## 验证与回滚

自测是本章的「验证」，回炉是「回滚」：

```bash
# 里程碑一：命令与文件
find /etc -name '*.conf' | wc -l
grep -rn 'PermitRootLogin' /etc/ssh/ 2>/dev/null
id; umask
# 里程碑二：存储与网络
lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS
ip -br addr; ip route; ss -tulpn
# 里程碑三：维护
systemctl --failed
sudo find /etc -name '*.pacnew'
cat /proc/cmdline
# 里程碑四：服务
systemctl list-units --type=service --state=running | head
sudo nginx -t 2>/dev/null; systemctl status --no-pager 服务名
# 里程碑五：桌面
echo "$XDG_SESSION_TYPE $XDG_CURRENT_DESKTOP"
wpctl status 2>/dev/null | head -20
# 里程碑六：查阅
grep -c '^- \[第' src/SUMMARY.md
```

每条命令都要能解释「输出里哪一行说明通过」。例如 `systemctl --failed` 为空才算通过；`cat /proc/cmdline` 要能指出 root= 与 resume= 是否存在；`wpctl status` 要能看到默认输出节点。

回滚：本章是自测与路线，不改变系统。若自测失败，回到对应篇重读并重做练习；不要用「再装一遍系统」掩盖没学会的环节。

## 取舍边界

- **广度 vs 深度**：104 章覆盖到「能日常使用」，不覆盖内核开发、驱动编写、大型集群。需要这些时走上游文档，而不是继续加章。
- **本书 vs Wiki**：本书给路径与判断，Wiki 给细节与版本差异。冲突时以 Wiki 与 `man` 为准，本书的结论会过时。
- **自测 vs 项目**：自测只能证明「知道」，项目才能证明「会」。里程碑通过后，尽快做一个真实项目（自己的服务器、桌面或容器服务）。
- **备份 vs 快照**：快照防误操作，备份防设备损坏；两者不能互相替代（第 40 章）。

## 小结

- 三十个坑的共同结构：顺序错或对象错；处置的第一步永远是取证与确认对象。
- 六个里程碑对应六篇，每个都有可执行自测；不通过就回炉，不往下读。
- 三条路线（桌面、服务器、安全底层）共享前两篇，之后按重点章分叉。
- 完成本书之后：读上游文档、跟 News、做恢复演练、选一个方向深入。
- 备份不等于快照，知道不等于会；项目与演练才是验收。

## 练习

1. 从 104.1 挑五个你实际遇到过的坑，写出当时的根因与现在的处置步骤。
2. 按 104.2 的六个里程碑逐项自测，把不通过的项目列成补课清单。
3. 选一条路线，画出从第 1 章到你目标章的阅读顺序，标出可以略读的章。
4. 在虚拟机里做一次「装错引导器 → 救援修复」的演练，记录每一步命令与验证方式。
5. 给你的机器写一份「恢复卡片」：备份位置、快照命令、chroot 步骤、固件启动项顺序。
6. 找出本书中你认为最可能过时的一节，说明理由，并给出你会在哪里核对最新信息。
