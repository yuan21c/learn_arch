# 第 80 章 密码学、隐私与密钥管理

前几章讨论「谁能进来、能改什么」；这一章讨论「数据本身怎么保护、密钥怎么活」。密码学用错比不用更危险：自己发明算法、把私钥放进 git、用 VPN 当匿名工具，都会带来虚假的安全感。本章只讲应用层：GPG、age、SSH 密钥、systemd-creds、systemd-homed、FreeIPA，以及 Tor/VPN/代理的隐私边界；算法细节以标准文档为准。

> 本章目标：能区分对称/非对称、哈希、KDF、AEAD 的用途并说出「不要自己造算法」的原因；会用 age 与 GPG 完成加密、签名、验证；会生成与检查 SSH 密钥，并给 `authorized_keys` 加限制；知道 systemd-creds、systemd-homed、密码管理器、FreeIPA 各自管理哪类秘密；能说清 Tor、VPN、代理在「隐私/匿名」上的差异与共同局限；能识别「私钥无口令」「密钥进仓库」「把 VPN 当匿名」三类问题。
> 对应 Wiki：[GnuPG](https://wiki.archlinux.org/title/GnuPG)、[Age](https://wiki.archlinux.org/title/Age)、[OpenSSH](https://wiki.archlinux.org/title/OpenSSH)、[Systemd-creds](https://wiki.archlinux.org/title/Systemd-creds)、[Systemd-homed](https://wiki.archlinux.org/title/Systemd-homed)、[FreeIPA](https://wiki.archlinux.org/title/FreeIPA)、[Tor](https://wiki.archlinux.org/title/Tor)

## 五种原语，五种用途

| 原语 | 解决什么 | 常见实现 | 典型误用 |
| ------------- | ------------------------------ | ------------------------------ | ------------------------------ |
| 对称加密 | 用同一密钥加解密大量数据 | AES-GCM、ChaCha20-Poly1305 | 自己拼 CBC、复用 nonce |
| 非对称加密/签名 | 公钥分发、身份与不可否认 | RSA、Ed25519、ECDSA | 把「加密」和「签名」混用 |
| 哈希 | 完整性、指纹、口令存储的输入 | SHA-256、SHA-3、BLAKE2 | 用 MD5/SHA-1 做安全用途 |
| KDF | 从口令派生密钥、抗暴力破解 | Argon2id、scrypt、PBKDF2 | 直接用口令当密钥 |
| AEAD | 同时保证机密性与完整性 | GCM、ChaCha20-Poly1305 | 先加密再自行拼接 MAC |

三条底线：**不要自己设计算法或模式；不要复用 nonce/IV；不要用口令直接当密钥**。应用层优先选「已经封装好这些细节」的工具（age、GPG、WireGuard），而不是手写 `openssl enc`。

## age：简单的文件加密

age 的定位是「现代、无历史包袱的文件加密」，适合备份、配置、单文件传输：

```bash
sudo pacman -S age
mkdir -p /tmp/crypto-lab && cd /tmp/crypto-lab
age-keygen -o key.txt
PUB=$(grep -o 'age1[0-9a-z]*' key.txt | head -1)
printf 'secret\n' > plain.txt
age -r "$PUB" -o secret.age plain.txt
age -d -i key.txt -o plain.out secret.age
diff plain.txt plain.out && echo "roundtrip OK"
```

- `age-keygen` 生成身份文件，公钥在注释行；私钥文件权限应是 `600`。
- `-r` 指定接收者公钥，`-d -i` 用身份文件解密；多人场景可以给多个 `-r`。
- 口令加密用 `age -p`，它会走 scrypt/Argon2 类 KDF；适合「没有公钥基础设施」的一次性场景。
- age 没有 Web of Trust，也**不验证发送者身份**：要认证来源，得另配签名（如 SSH 签名或 GPG）。

## GPG：签名、加密与信任网

GPG 功能多，先用最小闭环：生成、签名、验证。

```bash
mkdir -p /tmp/gpg-lab && chmod 700 /tmp/gpg-lab
export GNUPGHOME=/tmp/gpg-lab
gpg --batch --passphrase '' --quick-generate-key 'Lab <lab@example>' ed25519 sign 1d
gpg --list-keys
printf 'data\n' > msg.txt
gpg --armor --detach-sign -o msg.asc msg.txt
gpg --verify msg.asc msg.txt
```

- 用临时 `GNUPGHOME` 演练，不碰你的真实钥匙串；生产密钥应设口令、设到期、生成吊销证书并离线保存。
- `--quick-generate-key` 的参数依次是 UID、算法、用途、有效期；日常签名用 Ed25519，兼容老系统时可能需要 RSA。
- **不要随意把公钥上传到公共 keyserver**：上传会暴露身份与社交图，且很难撤回；用带身份验证的分发渠道。
- **私钥备份要加密**：导出后用 age/GPG 再加密，离线保存；不要把私钥、吊销证书和口令放在同一处。

## SSH 密钥与授权限制

```bash
ssh-keygen -t ed25519 -C lab -f /tmp/crypto-lab/id_lab -N ''
ssh-keygen -lf /tmp/crypto-lab/id_lab.pub
```

- Ed25519 是当前推荐的默认类型；`-N ''` 只适合实验，真实私钥要口令。
- 指纹用 `ssh-keygen -lf` 核对，不要凭「文件名像」判断。
- `~/.ssh/authorized_keys` 可以加限制：`from="10.0.0.0/24",command="/usr/local/bin/backup",no-port-forwarding,no-agent-forwarding,no-pty ssh-ed25519 AAAA…`。一把钥匙只做一件事，比「全权限钥匙」安全。
- SSH 还支持用密钥签名文件（`ssh-keygen -Y sign` / `-Y verify`），适合已经信任 SSH 密钥的团队，省去再建一套 GPG 信任网。

## 服务秘密与身份管理

- **systemd-creds**：给服务加密凭据，密文可以放在 `LoadCredentialEncrypted=` 引用的文件里；加密密钥来自宿主（可结合 TPM）。
  ```bash
  sudo systemd-creds encrypt --name=db-password /tmp/plain.txt /tmp/db.cred
  sudo systemd-creds decrypt --name=db-password /tmp/db.cred -
  ```
  普通用户直接运行可能报 `io.systemd.InteractiveAuthenticationRequired`（需要向宿主密钥环认证），所以示例用 `sudo` 演练；生产环境里服务由 systemd 启动时，`LoadCredentialEncrypted=` **才会**解密并把明文放到 `$CREDENTIALS_DIRECTORY`，无需手工 `decrypt`。**注意 `LoadCredential=` 不会解密——它只读取明文文件**；要加载密文必须写 `LoadCredentialEncrypted=<名字>:<密文路径>`。`--name=` 把凭据绑定到名字，**加解密都要给同一个 `--name=`**，换名会失败。**绑定宿主/TPM 的密文在重装或换机后解不开**，必须保留恢复路径。

  ```ini
  # unit 中的写法：名字与 systemd-creds 的 --name 必须一致
  LoadCredentialEncrypted=db-password:/etc/db.pass.cred
  # 程序从 $CREDENTIALS_DIRECTORY/db-password 读取明文
  ```
- **systemd-homed**：把用户家目录做成可移植、加密的映像，登录时解锁；`homectl create`、`homectl list`。底层涉及加密卷，存储细节见第 22 章，本章只讲用户视角：忘记恢复口令就真的进不去。
- **密码管理器**：KeePassXC（本地数据库 + 主口令/硬件密钥）、`pass`（GPG + git）。适合个人账号；团队共享要走带审计的方案，别把数据库丢进共享盘。
- **FreeIPA**：集中身份（Kerberos/LDAP/DNS/PKI），适合多机统一账号；Arch 上服务端通常用容器或专门发行版，客户端 `freeipa-client` 在 AUR。它把「身份」变成基础设施，复杂度也随之上升。

## 隐私：Tor、VPN、代理的边界

| 工具 | 隐藏什么 | 不隐藏什么 | 主要风险 |
| ------------- | ------------------------------ | ------------------------------ | ------------------------------ |
| Tor | 出口 IP、路径（对本地网络/ISP） | 登录身份、浏览器指纹、出口节点可见的明文 | 慢；登录即去匿名；关联攻击 |
| VPN | 本地网络/ISP 看到的真实出口 | 对 VPN 提供商的流量与元数据 | 信任转移；DNS 泄漏；供应商日志 |
| 代理 | 应用层出口 | 传输层元数据、指纹 | 配置泄漏；并非加密 |
| DNS over HTTPS/TLS | 本地 DNS 查询内容 | 目标站点、流量特征 | 仍可被流量分析 |

- **VPN 不是匿名工具**：它把「谁能看到你的流量」从本地网络换成了 VPN 提供商；对目标站点，你仍是同一个出口。要匿名，Tor 更接近，但必须避免登录个人账号、关闭 WebRTC/指纹泄漏。
- **Tor 也不等于安全**：出口节点的明文可被观察；HTTPS 能保护内容，但元数据仍在。`torsocks` 只代理单进程，配置错的应用会绕过。
- **内容过滤/家长控制**常靠 DNS 过滤或代理实现；它挡的是「解析到被禁域名」，挡不住 DoH/VPN 绕过，也不是安全边界。
- **隐私的第一原则是少暴露**：能不填的资料不填，能本地处理的不到云端；工具只是放大器，不是替代品。

## 失败模式

- **私钥无口令**：笔记本丢失即密钥泄露；真实私钥一律设口令，必要时用硬件令牌。
- **私钥进了 git**：`git log` 永远留着；发现后要吊销并轮换，而不是只删文件。
- **GPG 密钥过期/无吊销证书**：到期后签名失效，出事时无法撤回；生成时就要设到期与吊销证书。
- **公共 keyserver 泄露身份**：上传公钥会暴露邮箱与签名关系；用受控分发。
- **低熵口令 + 快 KDF**：口令可被离线爆破；用 Argon2id/scrypt 参数按硬件调，而不是默认值一把梭。
- **age 私钥权限过宽**：`key.txt` 可被同机其他用户读；`chmod 600` 并放在加密盘。
- **`authorized_keys` 全权限**：一把钥匙能转发、能开 shell、能连所有主机；按用途加 `from=`/`command=`/`no-pty`。
- **systemd-creds 绑定宿主后重装**：密文解不开；保留原始秘密的离线恢复副本。
- **homed 忘记恢复口令**：家目录映像无法解锁；恢复密钥要离线保存。
- **VPN 当匿名**：登录同一账号、DNS 泄漏、浏览器指纹，仍可被关联。
- **Tor 里登录个人账号**：一次登录就把整条链路去匿名化。
- **密钥备份没加密**：备份盘丢失等于全部秘密泄露。

## 验证与回滚

加密与签名的验证是「解回来、验通过、指纹对」：

```bash
age -d -i /tmp/crypto-lab/key.txt -o /tmp/crypto-lab/plain.out /tmp/crypto-lab/secret.age
diff /tmp/crypto-lab/plain.txt /tmp/crypto-lab/plain.out
GNUPGHOME=/tmp/gpg-lab gpg --verify /tmp/gpg-lab/msg.asc /tmp/gpg-lab/msg.txt
ssh-keygen -lf /tmp/crypto-lab/id_lab.pub
systemd-creds --help >/dev/null && echo "systemd-creds 可用"
homectl list 2>/dev/null || echo "未启用 homed"
wg show 2>/dev/null || echo "未启用 WireGuard"
```

回滚与轮换：

- **SSH 密钥泄露**：从所有 `authorized_keys` 删除对应行，生成新钥匙，检查 `sshd -T` 与登录日志；旧钥匙的 `known_hosts` 条目不影响。
- **GPG 私钥泄露**：用预先保存的吊销证书发布吊销，生成新密钥并重新签名；没有吊销证书就只能等到期。
- **age 私钥泄露**：用新身份重新加密文件，旧密文视为已泄露；没有「撤销」机制。
- **systemd-creds**：用原秘密重新加密并更新 unit；保留离线副本，防止宿主/TPM 变化导致解不开。
- **homed**：用恢复口令/恢复密钥解锁；没有恢复路径只能从备份恢复数据。
- **VPN/Tor 配置**：保留旧配置，改坏时 `wg-quick down` 或停 `tor`，先恢复直连再排查。

## 取舍边界

- **GPG vs age**：需要签名、信任网、邮件加密、成熟生态 → GPG；只要简单文件加密、现代默认 → age。两者可以并用：age 加密数据，SSH/GPG 签名分发。
- **口令 vs 公钥 vs 硬件令牌**：口令方便但易被钓鱼/复用；公钥免口令但私钥要保护；硬件令牌（FIDO2/YubiKey）抗钓鱼但需要购买与备份。
- **密码管理器 vs systemd-creds**：个人账号用密码管理器；服务凭据用 systemd-creds + `LoadCredentialEncrypted=`；不要把两者混成一个库。
- **systemd-homed vs 传统家目录 + 加密卷**：要可移植、集中管理的加密家目录 → homed；要成熟可控的块级加密 → 传统方案（第 22 章）。
- **FreeIPA vs 独立账号**：多机统一身份、Kerberos 单点登录 → FreeIPA；一两台机器 → 本地账号 + SSH 密钥，别为规模上复杂度。
- **VPN vs Tor**：只想换出口、信任提供商 → VPN；要对抗本地网络与提供商关联 → Tor；两者组合也有流量关联与配置风险。
- **密钥轮换周期**：按暴露面与合规要求定；轮换太频繁会增加运维错误，太慢会扩大泄露窗口。
- **加密范围**：传输层（TLS/SSH）、存储层（加密卷）、应用层（字段级）各有边界；先明确「防谁」，再选层。

## 小结

- 五种原语各有用途；不自己造算法、不复用 nonce、不把口令当密钥。
- age 简单、无信任网；GPG 功能全、信任网复杂；两者都要保护私钥与备份。
- SSH 密钥按用途加限制；指纹用 `ssh-keygen -lf` 核对。
- systemd-creds 管服务凭据，homed 管家目录，密码管理器管个人账号，FreeIPA 管集中身份。
- Tor 比 VPN 更接近匿名，但登录、指纹与出口仍会暴露；VPN 只是转移信任。
- 密钥生命周期包括生成、分发、存储、轮换、吊销、备份与恢复；缺一环就可能全盘皆输。

## 练习

1. age 闭环：按正文生成身份、加密、解密、`diff`；再给两个公钥加密同一文件，验证两人都能解。
2. GPG 演练：在临时 `GNUPGHOME` 生成 1 天期密钥、签名并验证；导出吊销证书，说明离线保存的原因。
3. SSH 限制：生成一把实验钥匙，在 `authorized_keys` 加 `from=`/`no-pty`，说明哪些场景会因此失败。
4. systemd-creds：用 `encrypt`/`decrypt` 演练一条凭据，换 `--name=` 再解密，观察失败；说明宿主绑定与恢复副本的关系。
5. 隐私对比：分别用 VPN、Tor、代理访问同一站点（或阅读文档推演），列出「谁能看到什么」，标出三种去匿名化路径。
6. 轮换演练：模拟一把 SSH 钥匙泄露，写出「删除授权 → 生成新钥 → 验证登录 → 查日志」的完整步骤。
7. 备份策略：为一组 GPG/age/SSH 密钥设计离线备份与恢复流程，说明为什么不能和口令放在一起。
