# 第 75 章 虚拟化平台与沙箱

第 74 章讲的是「手工搭一台虚拟机」；这一章讲「用现成平台管虚拟机」，以及一类介于容器与 VM 之间的隔离——Waydroid、Whonix 这类「带特定目的的系统环境」。平台型工具（VirtualBox、VMware、Xen）省事但把控制权交给厂商；沙箱型工具（firejail、bubblewrap）轻量但不是虚拟化。选之前先问：你要的是完整系统、桌面应用隔离，还是某个特定运行时？

> 本章目标：能区分 Type-1/Type-2 虚拟化平台与容器型沙箱；会用 `VBoxManage` 创建/查看/删除域并管理快照；知道 VirtualBox 内核模块（DKMS）与内核升级的关系；能说出 VMware、Xen、Hyper-V、Parallels 的定位与代价；知道 Waydroid 的 binder 前提与 Whonix 的双 VM 结构；能识别「内核升级后 vboxdrv 失效」「Waydroid 缺 binder」「把沙箱当 VM」三类问题。
> 对应 Wiki：[VirtualBox](https://wiki.archlinux.org/title/VirtualBox)、[VMware](https://wiki.archlinux.org/title/VMware)、[Xen](https://wiki.archlinux.org/title/Xen)、[Waydroid](https://wiki.archlinux.org/title/Waydroid)、[Whonix](https://wiki.archlinux.org/title/Whonix)

## 平台与沙箱的地图

| 工具 | 类型 | 隔离基础 | 适合 | 主要代价 |
| ------------- | ---------- | -------------------------- | ------------------------------ | ------------------------------ |
| VirtualBox | Type-2 | 宿主内核模块 + 用户态 | 桌面实验、跨系统兼容 | 模块随内核升级失效；3D 有限 |
| VMware | Type-2 | 厂商内核模块 | 商业桌面虚拟化、成熟工具链 | 许可与模块编译；闭源 |
| KVM/libvirt | Type-1 式 | 宿主内核 KVM | 服务器、直通、自动化 | 需自行搭管理（第 74 章） |
| Xen | Type-1 | 独立 hypervisor | 服务器、强隔离 | dom0 配置复杂、生态较小 |
| Hyper-V | Type-1 | 另一系统的 hypervisor | 企业虚拟化 | 与 Linux 宿主共存需嵌套 |
| Parallels | Type-2 | 厂商内核模块 | 桌面虚拟化 | 平台绑定、闭源 |
| Waydroid | 容器型 | LXC + binder | 在 Linux 桌面上跑 Android 应用 | 需要 binder 与 Wayland |
| Whonix | VM 组合 | 两个 VM + Tor | 强匿名浏览 | 资源开销、网络配置严格 |

Type-1 直接跑在硬件上，Type-2 跑在宿主操作系统上。**Type-2 的「省事」来自把硬件细节交给厂商模块；代价是内核升级后要重编译模块**。

## VirtualBox：命令行与快照

```bash
sudo pacman -S virtualbox virtualbox-host-dkms
sudo gpasswd -a "$USER" vboxusers
VBoxManage --version
VBoxManage list hostinfo
lsmod | grep -E 'vboxdrv|vboxnet'
```

创建、查看、删除一个不启动的域（全部在用户目录，可回滚）：

```bash
VBoxManage createvm --name lab --ostype Linux26_64 --register
VBoxManage showvminfo lab
VBoxManage unregistervm lab --delete
```

`showvminfo` 看配置、控制器、网卡与快照；`unregistervm --delete` 会连同虚拟磁盘一起删，执行前先 `VBoxManage list hdds` 确认没有别的域共享这块盘。常用管理项：

```bash
VBoxManage list vms
VBoxManage list runningvms
VBoxManage snapshot lab take snap1
VBoxManage snapshot lab list
VBoxManage snapshot lab restore snap1
```

`virtualbox-host-dkms` 是关键：内核一升级，`vboxdrv` 要重新编译。若 `lsmod` 里没有它，先 `sudo dkms autoinstall`，再 `sudo modprobe vboxdrv`；开了 Secure Boot 时，未签名的第三方模块会被拒绝加载（第 61 章的签名链同样适用）。

## VMware、Xen 与远程管理

- **VMware**：Workstation/Player 属 Type-2（相关包在 AUR），装完后需要编译 `vmware-host-modules` 并启动 `vmware-networks`、`vmware-usbarbitrator` 等服务；内核升级后同样要重编译。许可是商业条款，个人/商业使用范围要先确认。
- **Xen**：Type-1，宿主机跑在 dom0，`xl list` 看 domU，`xl info` 看 hypervisor 与资源。Xen 的隔离强，但 dom0 内核、网络后端与工具栈都要单独维护，生态与资料少于 KVM。
- **Hyper-V/Parallels**：分别绑定另一类宿主平台；Linux 作为客体时需要集成服务，作为宿主时通常要开嵌套虚拟化才能再跑 KVM。**跨平台方案要先确认「谁在谁上面」**，否则性能与直通都无从谈起。
- **远程管理**：PhpVirtualBox 给 VirtualBox 套 Web UI；RemoteBox 通过 SOAP 远程操作 VirtualBox；VMware vCLI 面向 vSphere 管理。三者都扩大了口子——面板必须加认证、限制来源，最好只走内网或 SSH 隧道（第 76 章）。

## Waydroid 与 Whonix：目的型沙箱

**Waydroid** 用 LXC 跑一个 Android 系统容器，和宿主共享内核，因此依赖内核的 binder 支持：

```bash
sudo pacman -S waydroid
sudo modinfo binder_linux || echo "缺 binder 模块"
sudo waydroid init
waydroid session start
waydroid status
waydroid show-full-ui
```

它需要 Wayland 会话；`binder_linux` 不在内核里时要装对应的 DKMS/模块包并加载。Waydroid 的隔离来自命名空间与 LXC，不是硬件虚拟化——**它能跑 Android 应用，但不能当作安全边界去运行不可信代码**。

**Whonix** 由两个 VM 组成：Gateway 负责把流量强制走 Tor，Workstation 只连 Gateway 的内部网络。启动顺序必须先 Gateway 后 Workstation，网络要设成 internal/private；任一配置错，Workstation 可能直接暴露真实出口。它适合「强匿名浏览」这一单一目的，不适合日常开发；资源开销也是两台 VM 的量级。

## 失败模式

- **内核升级后 VirtualBox 起不来**：`vboxdrv` 未随新内核重编译；`dkms status` 看状态，`dkms autoinstall` 修复。
- **`modprobe vboxdrv` 报签名/权限错误**：Secure Boot 拒绝未签名模块；要么签名，要么在受控环境关闭 Secure Boot（第 58/59 章）。
- **VMware 服务起不来**：内核模块未编译、`vmware-networks` 未启用，或与别的虚拟化模块冲突。
- **Xen 的 domU 网络不通**：桥接/后端配置错误；`xl network-list` 与 `ip link` 对照，别只看 domU 内部。
- **Waydroid 卡在 `initializing`**：缺 binder、没有 Wayland 会话、或内核版本不匹配；先 `modinfo binder_linux` 与 `echo $XDG_SESSION_TYPE`。
- **Whonix 泄漏真实出口**：Workstation 网卡接到了 NAT 而不是 internal，或 Gateway 未先启动；用 `curl` 检查出口前先确认 VM 网络类型。
- **把沙箱当 VM**：firejail/bubblewrap 共享宿主内核（第 71 章），不能防内核漏洞；需要强隔离时用 VM。
- **快照当备份**：VirtualBox 快照依赖原磁盘链，主机磁盘损坏时一起没；快照只解决回退。
- **面板暴露公网**：PhpVirtualBox/RemoteBox 无认证或弱口令，等于把宿主控制权交出去。
- **许可证误判**：VirtualBox Extension Pack、VMware 商业版都有许可边界；先读条款再用于生产。

## 验证与回滚

平台型工具的验证先看「模块、版本、域状态」：

```bash
VBoxManage --version
lsmod | grep -E 'vboxdrv|vboxnetflt|vboxnetadp'
VBoxManage list vms
VBoxManage showvminfo lab --details | head -30
xl info 2>/dev/null || echo "无 Xen"
waydroid status 2>/dev/null || echo "无 Waydroid"
```

回滚动作：

- **VirtualBox 域**：`VBoxManage snapshot lab restore snap1` 回退状态；彻底清理用 `unregistervm --delete`，但先确认磁盘不被其他域共享。
- **模块问题**：`sudo dkms autoinstall` + `sudo modprobe vboxdrv`；仍失败就看 `dkms status` 与内核版本，别反复重启。
- **Waydroid**：`waydroid session stop`，需要清数据时 `waydroid reset`（会清应用数据，先确认）。
- **Whonix**：按「先关 Workstation、再关 Gateway」的顺序停机；网络配置改坏时恢复到 internal 网络快照，再重新验证出口。

本机验收只做只读检查与「创建/查看/删除不启动的 VirtualBox 域」；安装平台、加载模块、启动 Waydroid/Whonix 都会改动宿主，**未实测**。

## 取舍边界

- **VirtualBox vs VMware vs KVM**：桌面实验、跨系统兼容、免费 → VirtualBox；商业支持与成熟工具链 → VMware；服务器、直通、自动化 → KVM/libvirt（第 74 章）。
- **Type-1 vs Type-2**：要接近原生性能与强隔离 → Type-1（Xen/KVM）；要桌面即装即用 → Type-2。Type-2 的便利建立在厂商模块与内核版本匹配上。
- **Waydroid vs Android 模拟器**：要原生速度、与桌面集成 → Waydroid；要完整模拟各种设备/版本 → 专用模拟器（资源更重）。
- **Whonix vs Tails/VPN**：要长期匿名工作环境 → Whonix；一次性匿名会话 → Tails；只是换出口 IP → VPN（但 VPN 不等于匿名）。
- **沙箱 vs VM**：单进程/桌面应用隔离 → firejail/bubblewrap；不可信代码、内核风险 → VM。
- **快照 vs 备份**：快照用于「升级前回退」，备份用于「磁盘/主机损坏恢复」；两者都要有，不能只留快照。
- **远程面板 vs 本地管理**：面板提升效率但扩大攻击面；能本地/SSH 管理就不要把面板开到公网。

## 小结

- Type-2 平台（VirtualBox/VMware）靠宿主内核模块，内核升级后要重编译；这是最常见的「昨天还能用」故障。
- `VBoxManage` 能完成创建、查看、快照、删除；`unregistervm --delete` 会连磁盘一起删，先确认共享关系。
- Xen 是 Type-1，隔离强但维护成本高；Hyper-V/Parallels 绑定各自宿主平台。
- Waydroid 是 LXC 容器，依赖 binder 与 Wayland，不是强安全边界。
- Whonix 是 Gateway + Workstation 双 VM，网络配置错就可能泄漏真实出口。
- 沙箱、容器、VM 按隔离强度递增；快照不能替代备份；远程面板必须加认证与来源限制。

## 练习

1. 平台检查：跑 `VBoxManage --version`、`lsmod | grep vbox`、`xl info`、`waydroid status`（不存在的命令记录为「未安装」），整理本机可用的平台。
2. 域生命周期：用 `VBoxManage createvm --register` 建一个不启动的域，`showvminfo` 查看，再 `unregistervm --delete`；说明删除前要检查什么。
3. 模块故障推演：假设内核从 6.x 升到 7.x 后 `vboxdrv` 加载失败，写出 `dkms status` → `dkms autoinstall` → `modprobe` 的排查链。
4. Waydroid 前提：检查 `modinfo binder_linux` 与 `$XDG_SESSION_TYPE`，说明缺任一条件时 Waydroid 会卡在哪一步（不实际启动）。
5. Whonix 网络：画出 Gateway/Workstation 的网络连接，标出哪一步配错会导致真实出口泄漏；给出验证出口的命令。
6. 选型结论：为「桌面跑一个跨系统应用」「服务器跑多台隔离环境」「在 Linux 上跑 Android 应用」各选一个平台，写两条代价。
