# 第 35 章 安装准备与分区

安装需要固件、分区表与真实块设备，这些在虚拟机和真机上都具备。本章从虚拟机选型开始，完成 ISO 校验、磁盘布局设计与实际分区，为第 36 章的 `pacstrap` 准备好挂载点。

> 本章目标：能独立选择并配置一台 UEFI 虚拟机，校验 Arch ISO，规划 ESP 与 root 分区并完成格式化、挂载。
> 对应 Wiki：[Installation guide](https://wiki.archlinux.org/title/Installation_guide)｜[Partitioning](https://wiki.archlinux.org/title/Partitioning)

> 本书假设你的 Arch 已经装好。本章保留完整流程作为**参考资料**：想重装、想在真机上安装，或想理解安装器到底做了什么时再读。本章的分区、格式化与挂载都是破坏性操作，**未实测**；练习只在空虚拟盘或 `/tmp` 镜像文件上做。

## 为什么先用虚拟机

安装流程涉及分区、格式化、写引导项，真机上一次失误就可能清空整块磁盘。虚拟机提供了三样真机不便提供的东西：UEFI 固件、可随意重来的虚拟磁盘、能观察引导过程的重启。显卡直通、无线网卡、指纹、休眠无法在虚拟机验证，这些留到真机阶段。

| 方案 | 优点 | 限制 | 适合 |
| ---------- | ----------------------------------------- | ------------------------- | ---------------- |
| VirtualBox | 图形界面完整，快照、共享文件夹方便，跨平台 | 性能一般，UEFI 需手动启用 | 需要频繁快照回滚 |
| QEMU | 命令行可控，能指定 OVMF、virtio、磁盘格式 | 需自己写参数，学习曲线陡 | 想理解虚拟化细节 |

两种方案选其一即可，不必同时折腾；具体界面与限制以各项目当前文档为准。

| 项目 | 建议值 | 说明 |
| ----------- | ----------------------- | ------------------------------------------------------ |
| 固件 | UEFI（OVMF 或固件自带） | 本章按 UEFI + GPT 讲解 |
| Secure Boot | 关闭 | 官方 ISO 未做 Secure Boot 签名，开启后通常无法直接启动 |
| CPU | 2 个虚拟核心 | 编译内核或 AUR 包时更多核心更好 |
| 内存 | 2–4 GiB | 低于 2 GiB 时 `pacstrap` 容易因内存不足失败 |
| 磁盘 | 20 GiB，动态分配 | 学习安装足够，装桌面后需更大 |
| 网络 | NAT | 默认即可访问镜像站 |

VirtualBox 的 UEFI 开关在「设置 → 系统 → 主板 → 启用 EFI」；QEMU 需额外准备 OVMF 固件。具体界面以各软件当前文档为准。

## 获取并校验 ISO

ISO 从官方下载页获取：<https://archlinux.org/download/>。优先用 torrent 或 HTTPS 镜像，不要从第三方网盘或博客附件下载。下载后必须核对 SHA256 并验证 GPG 签名：前者确认文件未损坏，后者确认文件确实由 Arch 发布者签名。只做 SHA256 只能防传输错误，不能防镜像站被替换。

```bash
cd ~/Downloads
sha256sum archlinux-*.iso
gpg --keyserver keyserver.ubuntu.com --recv-keys 发布密钥指纹
gpg --verify archlinux-*.iso.sig archlinux-*.iso
```

签名文件 `.sig` 与 ISO 在同一页面提供。命令中的「发布密钥指纹」要替换成下载页或 Wiki 公布的实际指纹，不要原样执行。输出 `Good signature` 才算通过；`WARNING: This key is not certified` 只表示没有本地信任链，但必须确认指纹与官方公布的一致。文件名与版本号以实际下载为准。

## 设计磁盘布局

UEFI 系统至少需要两个分区：FAT32 的 EFI 系统分区（ESP）存放引导器和内核，另一个 Linux 根分区。GPT 是 UEFI 下的默认分区表。

| 挂载点 | 大小 | 分区类型 | 文件系统 | 说明 |
| -------- | ------------- | ---------------- | ------------- | ------------------------ |
| `/boot` | 512 MiB–1 GiB | EFI System | FAT32 | ESP，GRUB 与内核都放这里 |
| `/` | 剩余空间 | Linux filesystem | ext4 或 btrfs | 根文件系统 |
| `[SWAP]` | 可选 | Linux swap | swap | 也可安装后用 swapfile |

ESP 只放引导相关文件，不要塞普通数据。512 MiB 对单内核足够；保留多个内核、使用统一内核镜像（UKI）或多份 initramfs 时给 1 GiB 更稳妥。

| 方式 | 优点 | 缺点 | 适用 |
| --------- | ------------------------ | ------------------------------------------------------------------------------------------------ | ------------------ |
| swap 分区 | 独立于文件系统，行为简单 | 大小固定，调整需重新分区 | 内存固定、需要休眠 |
| swapfile | 随时创建、删除、调整 | btrfs 上需 NoCOW（无洞、不压缩），可用 `btrfs filesystem mkswapfile`；含 swapfile 的子卷不能快照 | 虚拟机、临时实验 |
| zram | 压缩内存，不占磁盘 | 不能用于休眠 | 内存较大、磁盘较小 |

虚拟机阶段建议先不建 swap，安装完成后再加 swapfile 或启用 zram，把分区步骤压到最少。

| 维度 | ext4 | btrfs |
| -------- | -------------------- | -------------------------- |
| 成熟度 | 长期稳定，工具链简单 | 功能多，但需理解子卷与维护 |
| 快照 | 不支持 | 支持，可配合 snapper |
| 压缩 | 不支持 | 支持透明压缩 |
| 修复 | `fsck` 直观 | 需 `btrfs check`，操作谨慎 |
| swapfile | 直接支持 | 需 NoCOW、无压缩、不被快照 |
| 建议 | 第一次安装首选 | 明确需要快照时再选 |

本书示例使用 ext4。btrfs 的子卷布局、挂载选项和快照策略差异较大，以 [Btrfs](https://wiki.archlinux.org/title/Btrfs) 为准。

## 确认磁盘并分区

进入 Live 环境后，第一件事不是分区，而是确认哪块磁盘属于虚拟机。用 `lsblk` 与 `blkid` 交叉确认设备名、容量、文件系统：

```bash
lsblk -f
lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS
sudo blkid
sudo fdisk -l
```

虚拟机磁盘常见为 `/dev/vda`、`/dev/sda` 或 `/dev/nvme0n1`；Live ISO 所在的 U 盘也可能是 `/dev/sda`。再用 `lsblk -d -o NAME,SIZE,MODEL` 核对型号与大小。

> **危险**：`fdisk`、`mkfs` 直接作用于块设备，写错设备会不可恢复地清空数据。执行前必须用 `lsblk` 确认设备名与容量，确保虚拟机中没有需要保留的磁盘；真机操作前先备份。

以下示例假设目标磁盘是 `/dev/vda`，请按实际输出替换。用 `fdisk` 创建 GPT、512 MiB ESP 和占满剩余空间的根分区：

```bash
sudo fdisk /dev/vda
```

```text
Command (m for help): g
Command (m for help): n
Partition number (1-128, default 1): 1
First sector: 回车
Last sector: +512M
Command (m for help): t
Partition number (1): 1
Partition type or alias: 1
Command (m for help): n
Partition number (2-128, default 2): 2
First sector: 回车
Last sector: 回车，使用剩余空间
Command (m for help): p
Command (m for help): w
```

`g` 新建 GPT，`n` 新建分区，`t` 设置类型（GPT 中类型 `1` 是 EFI System），`p` 复核，`w` 写入。写入前看到的分区表就是最终结果，务必检查大小与类型。

格式化并挂载：先根分区，再 ESP。`--mkdir` 会在挂载前创建 `/mnt/boot`，顺序不能反。

```bash
sudo mkfs.fat -F32 /dev/vda1
sudo mkfs.ext4 -L archroot /dev/vda2
sudo mount /dev/vda2 /mnt
sudo mount --mkdir /dev/vda1 /mnt/boot
```

不要对整块磁盘执行 `mkfs`，也不要格式化已挂载的分区。`-L archroot` 只是给根分区一个标签，便于识别。最后验证：

```bash
findmnt /mnt
findmnt /mnt/boot
lsblk -f
```

输出中 `/mnt` 应为 ext4，`/mnt/boot` 应为 vfat，设备名与刚创建的分区一致。如果 `/mnt/boot` 没有独立挂载，说明 ESP 挂载失败，继续安装会导致引导器写不进 ESP。

fstab 六字段、UUID 与挂载选项的通用概念见第 18 章（`/etc/fstab` 与挂载），本章侧重 Arch 安装的实际动手路径：挂载点、UUID 与 `genfstab -U` 见第 36 章。

btrfs 子卷与 NoCOW 的细节见第 19 章，UKI（统一内核镜像）见第 58 章。

## 失败模式

- **设备名认错**：Live 环境里 U 盘与虚拟盘都可能显示为 `/dev/sda`。仅凭 `fdisk -l` 的排列顺序判断，容易把 ISO 所在盘当成目标盘；先用 `lsblk -d -o NAME,SIZE,MODEL` 对型号与容量。
- **只校验 SHA256**：能发现下载损坏，不能发现镜像站被替换；GPG 签名与官方公布的指纹必须同时核对。
- **ESP 没有真正挂载**：`/mnt/boot` 未独立挂载时仍是根分区上的普通目录，内核被写进根分区，引导器却找不到 ESP。判据是 `findmnt /mnt/boot`，不是目录是否为空。
- **对整盘执行 `mkfs`**：`mkfs.ext4 /dev/vda` 会清掉分区表；格式化对象必须是分区，如 `/dev/vda2`。
- **`fdisk` 写入前不看 `p`**：`w` 一按就落盘，大小、类型、顺序错了只能重来。
- **在已有数据的盘上练习**：分区与格式化没有撤销；练习只在空虚拟盘或一次性镜像上做。

## 验证与回滚

> 分区、格式化与挂载属于破坏性操作，本章**未实测**。下列演练在 `/tmp` 的稀疏镜像文件上完成，不碰真实块设备。

```bash
cd /tmp
truncate -s 2G part-drill.img # 稀疏文件，逻辑 2G，实际占用很小
fdisk part-drill.img # 在镜像上练手，不碰 /dev/vda
# 按键顺序：g → n(1, +512M) → t(1) → n(2, 回车) → p → w
fdisk -l part-drill.img # 复核：两个分区、大小与类型正确
losetup -fP part-drill.img # 可选：映射为 /dev/loopXpN，需要 root
lsblk -f # 观察镜像分区的 FSTYPE
losetup -d /dev/loopX # 演练结束先解绑
rm part-drill.img # 删除整个镜像 = 回滚
```

真实安装前先给虚拟机打快照；`mkfs` 之后没有「撤销」，只能重装或从备份恢复。装完基础系统回到本章复核 `findmnt /mnt` 与 `findmnt /mnt/boot`，两个独立挂载都在，才进第 36 章。

## 取舍边界

- **虚拟机 vs 真机**：学习与重装用虚拟机；显卡、无线、休眠、固件细节必须真机验证。
- **ESP 挂 `/boot` vs `/efi`**：单系统把 ESP 直接挂 `/boot` 最省事；需要独立 `/boot` 或加密时拆开，但引导器参数必须跟着改。
- **ext4 vs btrfs**：第一次安装选 ext4，工具链直观；明确需要快照与压缩再选 btrfs，并接受子卷与维护成本。
- **swap 分区 vs swapfile vs zram**：休眠需要持久 swap；临时实验用 swapfile；内存大、磁盘小用 zram，但不能休眠。
- **GPT vs MBR**：UEFI 用 GPT；只有老固件或特殊兼容需求才考虑 MBR。

## 小结

- 虚拟机提供 UEFI、可重建的磁盘和真实重启，是学习安装的最低风险环境。
- ISO 必须同时校验 SHA256 和 GPG 签名，签名验证依赖官方公布的密钥指纹。
- UEFI 布局至少需要 ESP 和根分区；ESP 挂到 `/boot` 是最省心的方案。
- swap 可以延后到安装完成，用 swapfile 或 zram 补上。
- 分区前用 `lsblk` 确认设备，`fdisk` 写入前用 `p` 复核，挂载后必须用 `findmnt` 验证。

## 练习

1. 创建一块 20 GiB 虚拟磁盘，用 UEFI 启动 Live ISO，记录 `lsblk -f` 的完整输出（需要 Live ISO 环境；预期：能看到你新建的空磁盘）。
2. 用 `fdisk` 创建 512 MiB-1 GiB ESP 和剩余空间的根分区，写出每一步的按键顺序（需要 Live ISO 环境；预期：`lsblk -f` 显示 ESP 为 `vfat`）。
3. 分别用 `mkfs.ext4` 与 `mkfs.btrfs`（btrfs 可再建 `@`/`@home` 子卷，见第 19 章）格式化根分区，比较 `lsblk -f` 的 `FSTYPE` 列（需要 Live ISO 环境；预期：两行分别为 ext4/btrfs）。
4. 用 `blkid` 记录两个分区的 UUID 和 PARTUUID，说明 `genfstab -U` 会使用哪一个（需要 Live ISO 环境；预期：两个 UUID 可与 `lsblk -f` 对上）。
