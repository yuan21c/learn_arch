# 第 42 章 安装、卸载与查询

pacman 的操作分为三组：`-S` 管安装，`-R` 管卸载，`-Q` 管查询。每组后面跟的单个字母都会改变行为，尤其是 `-R` 系列，多一个 `n` 或少一个 `s`，结果完全不同。本章把常用组合拆开讲清楚，并给每条命令配上可对照的输出。

> 本章目标：熟练完成安装与卸载，能根据场景选择 `-R`、`-Rs`、`-Rns`、`-Rdd`，并用 `-Q` 与 `-F` 系列定位包和文件。
> 对应 Wiki：[Pacman](https://wiki.archlinux.org/title/Pacman)

> 本章的安装与卸载命令**未实测**；可复现的安全练习以 `-Q`、`-Ql`、`-Qo`、`-F` 等只读查询为主。确需演练卸载，请先在一次性虚拟机的快照中做。

## 安装

`-S` 从同步数据库安装，不会自动刷新数据库。找不到包时不要用 `-Sy`，而应完整升级。

```bash
sudo pacman -S --needed htop git
# Packages (2) htop-3.4.1-1 git-2.51.0-1 （依赖已满足时才是 2；未预装依赖会更多）
# Total Download Size: 8.21 MiB
# :: Proceed with installation? [Y/n]
```

`--needed` 会跳过已是最新版本的包，适合写进脚本。多个包名用空格分隔；版本过旧时 pacman 会提示升级，而不是静默重装。以下输出中的版本号是示例，你的系统以当前仓库为准。

```bash
pacman -Ss htop
# extra/htop 3.4.1-1
# Interactive process viewer
```

`-Ss` 搜索仓库（支持正则），输出第一行是「仓库/包名 版本」，缩进行是描述。需要完整元数据时用 `-Si`。

### 组安装

```bash
pacman -Sg xorg # 只列出组成员，不安装
sudo pacman -S xorg # 安装整组
sudo pacman -Si base-devel # 元包：正常输出（-Sg 则会报 not found）
```

组名不是包名，`pacman -Sg <组名>` 只对真实包组有效；`base-devel` 自 2023-02 起已是元包，应把它当包看待。安装组会把成员记为显式安装；只想装组里的一个包时，直接写包名。

## 卸载

| 命令 | 删除包 | 删除孤儿依赖 | 删除配置文件 | 检查依赖 |
| ------------- | ------ | ------------ | ------------ | -------- |
| `pacman -R` | 是 | 否 | 否 | 是 |
| `pacman -Rs` | 是 | 是 | 否 | 是 |
| `pacman -Rns` | 是 | 是 | 是 | 是 |
| `pacman -Rdd` | 是 | 否 | 否 | 否 |

```bash
sudo pacman -Rns htop
# Packages (1) htop-3.4.1-1
# Total Removed Size: 0.45 MiB
# :: Do you want to remove these packages? [Y/n]
```

- `-R`：只删指定包，依赖留给 `-Qdt` 处理。
- `-Rs`：递归删除「因这个包被装、且现在无人需要」的依赖。显式安装的包不会被顺带删除。
- `-Rns`：在 `-Rs` 基础上加 `-n`，不保留配置文件。pacman 只处理包内标记为 backup 的文件；你在 `/etc` 里新建的同名文件不受管理，修改过的配置也不再存成 `.pacsave`。
- `-Rdd`：两个 `d` 跳过依赖检查，包括「其他包依赖它」的检查。

> **危险**：`-Rdd` 会跳过依赖检查，可能留下启动即报错的系统。只在明确知道某个依赖已损坏、且准备好修复方案时使用。

卸载前用 `pacman -Qi 包名` 看「Required By」，确认没有别的包还依赖它。

## 查询

| 目的 | 命令 | 说明 |
| ------------ | ------------------- | ----------------------- |
| 所有已安装包 | `pacman -Q` | 含版本 |
| 显式安装 | `pacman -Qe` | 用户主动要求 |
| 依赖安装 | `pacman -Qd` | 为别的包而装 |
| 外来包 | `pacman -Qm` | AUR、本地包，不在同步库 |
| 孤立包 | `pacman -Qdt` | 依赖安装且无人需要 |
| 文件归属 | `pacman -Qo 路径` | 哪个包拥有它 |
| 包的文件 | `pacman -Ql 包名` | 完整文件列表 |
| 包信息 | `pacman -Qi 包名` | 版本、依赖、安装原因 |
| 本地搜索 | `pacman -Qs 关键字` | 在已安装包中搜 |
| 仓库搜索 | `pacman -Ss 关键字` | 在同步库中搜 |
| 可升级 | `pacman -Qu` | 对比同步库版本 |

```bash
pacman -Q | wc -l # 214（你的系统不同）
pacman -Qe | grep '^base ' # base 3-2（显式安装）
pacman -Qs '^pacman$' # local/pacman 7.1.0-1（本地搜索）
pacman -Qm
# paru 2.0.1-1（示例；没有外来包时无输出）
pacman -Qdt
# 无输出表示没有孤立包
pacman -Qo /usr/bin/bash
# /usr/bin/bash is owned by bash 5.3.20-1
pacman -Ql bash | head -n 2
# bash /etc/
# bash /etc/bash.bash_logout
pacman -Qi bash | grep -E '^(Name|Version)'
# Name : bash
# Version : 5.3.20-1
```

`-Qo` 对不属于任何包的文件会输出 `error: No package owns 路径`，通常说明文件是手动放入的。`-Qi` 是排障时最常用的命令：先看「Depends On」和「Required By」，再决定能不能删。

## 文件数据库

`-Q` 只查已安装包的文件。要查「仓库里哪个包提供某个文件」，需要单独的文件数据库。

```bash
sudo pacman -Fy # 下载各仓库的文件数据库
pacman -F /usr/bin/bash
# core/bash 5.3.20-1
# usr/bin/bash

pacman -Fl bash | head -n 2
# bash usr/
# bash usr/bin/
```

`-Fy` 需要 root，且只在 `-F` 提示数据库缺失时执行。文件数据库与同步数据库独立刷新，`pacman -Syu` 不会自动更新它。`-F` 给完整路径时精确匹配；只给文件名时按路径末尾匹配，以 `man pacman` 为准。

## 包状态

```bash
sudo pacman -D --asdeps libfoo # 改标为依赖
sudo pacman -D --asexplicit libfoo # 改标为显式

pacman -Qkk bash
# bash: 148 total files, 0 altered files
```

`-D` 只改本地数据库的安装原因，不动文件。手动编译安装了一个库、又希望孤立包清理能识别它时，标成 `asdeps` 更合理。

`-Qkk` 校验包内文件的存在性与属性（权限、大小、符号链接目标等）。输出 `0 altered files` 表示一致；有缺失或改动时会列出具体路径。升级后出现大量 `altered`，优先怀疑手动改过 `/usr` 或磁盘问题。

## 速查表

| 场景 | 命令 |
| ------------------ | ------------------------------ |
| 安装且不重复装 | `sudo pacman -S --needed 包名` |
| 卸载并清依赖与配置 | `sudo pacman -Rns 包名` |
| 查看谁依赖它 | `pacman -Qi 包名` |
| 找孤立包 | `pacman -Qdt` |
| 找文件归属 | `pacman -Qo 路径` |
| 找仓库中的文件 | `pacman -F 路径` |

## 失败模式

- **用 `-Rdd` 强行绕过依赖**：其他包仍依赖它时，删除会留下启动即报错的系统；只在确认依赖已损坏且备好修复方案时使用。
- **把 `-Rns` 当默认卸载**：`-n` 不保留配置文件，修改过的配置不会存成 `.pacsave`；需要留配置时用 `-R` 或 `-Rs`。
- **只看包名不看 Required By**：卸载前没有检查反向依赖，删掉后被依赖的程序在下次启动时才失败。
- **把 `-Qo` 与 `-F` 混用**：前者查已安装文件归属，后者查仓库文件归属；`-F` 的数据库不会随 `-Syu` 自动更新。
- **长期不跑 `-Fy` 却依赖 `-F`**：文件数据库过期，查不到新包的文件；只在提示缺失时执行一次 `-Fy`。
- **安装组后不检查安装原因**：组内所有成员都被标为显式，`-Qdt` 永远找不到它们；需要时用 `-D --asdeps` 调整。
- **`--needed` 理解错**：它是「已是最新才跳过」，旧版本仍会升级；不是「装过就不动」。

## 验证与回滚

只读查询即可验证包状态，不影响系统：

```bash
pacman -Qi bash | grep -E 'Version|Install Reason|Required By|Depends On'
pacman -Ql bash | head -n 5
pacman -Qo /usr/bin/bash
pacman -Qkk bash
pacman -Qm
pacman -Qdt
```

判读：`Required By` 非空说明还有包依赖它；`-Qo` 报 `No package owns` 说明文件是手工放置；`-Qkk` 的 `altered files` 非 0 要区分配置改动与程序被覆盖。卸载后的回滚：重新安装同名包即可恢复 `/usr` 文件；被 `-n` 删除的配置只能从备份或 `.pacsave`（若存在）恢复；误删依赖导致系统异常时，从 Live 环境重装关键包（**未实测**）。安装/卸载演练建议在快照中做，并把 `pacman -Qi` 输出留在记录里。

## 取舍边界

- **`-R` vs `-Rs` vs `-Rns`**：只删包用 `-R`；清孤儿依赖用 `-Rs`；确定不要配置才用 `-Rns`。
- **`--needed` vs 强制重装**：日常与脚本用 `--needed`；修复被改动的包文件时才重装（`pacman -S 包名`）。
- **`-Qo` vs `-F`**：排障「这个文件从哪来」用 `-Qo`；找「哪个包提供这个文件」用 `-F`。
- **`-Qdt` 自动清理 vs 人工判断**：自动清理快，但可能删掉暂时不用、日后还要的库；先列表再决定。
- **组安装 vs 单包安装**：需要整组能力才装组；只为一个工具装整组会把大量不需要的包标为显式。

## 小结

- `-S` 用现有同步数据库安装；找不到包时用 `-Syu`，不要 `-Sy`。
- `--needed` 让安装幂等，适合脚本；组安装会装全组并标为显式。
- `-R` 只删包，`-Rs` 清孤儿依赖，`-Rns` 再清配置，`-Rdd` 跳过依赖检查。
- `-Qe`、`-Qm`、`-Qdt` 分别对应显式、外来、孤立包，是维护系统的三把尺子。
- `-Qo` 查已安装文件归属，`-F` 查仓库文件归属，两者数据库不同。

## 练习

1. 用 `--needed` 重复安装同一个包两次，观察第二次的输出。
2. 安装一个带依赖的包，用 `-R` 卸载，再用 `-Qdt` 找残留依赖；然后**重装该包**，改用 `-Rns` 重复实验并对比 `-Rs`。
3. 用 `-Qo` 查 `/usr/bin/pacman`，再用 `-Ql` 列出 pacman 包的全部文件并统计数量。
4. 先执行 `sudo pacman -Fy`，再用 `-F` 查找 `pacman` 可执行文件来自哪个包。
