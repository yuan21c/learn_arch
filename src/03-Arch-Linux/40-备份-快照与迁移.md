# 第 40 章 备份、快照与迁移

维护系统时有三类不同的「退路」：快照让整机回到某个时刻，备份让配置与数据离开这台机器，迁移让一套系统换到新硬件或新磁盘。三者目标不同、失效方式也不同，混为一谈会在真正需要恢复时才发现拿不出可用的副本。

> 本章目标：能区分快照、文件级备份与整盘镜像的边界；列出 Arch 上必须备份与不必备份的路径；完成一次可验证的 `tar` 备份与恢复演练；理解 btrfs 快照、虚拟机快照的限制；能按「重装 + 恢复配置」或「整盘复制 + 重建引导」两条路径规划迁移。
> 对应 Wiki：[System backup](https://wiki.archlinux.org/title/System_backup)｜[Synchronization and backup programs](https://wiki.archlinux.org/title/Synchronization_and_backup_programs)｜[Rsync](https://wiki.archlinux.org/title/Rsync)

## 三种手段的边界

| 手段 | 解决的问题 | 数据放在哪 | 典型失效场景 |
| -------------- | -------------------------- | ---------------------- | -------------------------------------- |
| 快照 | 整机或子卷回退到某时刻 | 与原数据同一存储 | 磁盘损坏、存储池丢失、快照被清理 |
| 文件级备份 | 配置与数据可恢复、可迁移 | 另一块磁盘或远端 | 策略漏目录、备份未演练、介质同时损坏 |
| 整盘镜像 | 块级复制，保留分区与文件系统 | 另一块磁盘 | 镜像过期、无法增量、恢复目标容量不足 |
| 配置清单 | 在新机器上重建同样软件 | 纯文本，体积极小 | 只有包名没有配置与数据 |

最重要的一条：**快照不是备份**。快照与原数据共享底层存储，删除原卷、磁盘故障或宿主目录被删时，快照会一起消失。快照适合「改坏了马上回退」，备份适合「机器没了还能重建」。

## 备份什么

备份范围按「能否重新获得」划分，而不是按目录大小划分：

| 路径或对象 | 内容 | 处理方式 |
| -------------------------- | ---------------------------- | ------------------------------------------ |
| `/etc` | 系统与软件配置 | 必备份；恢复时逐文件比对，不整目录覆盖 |
| `/home`、`/root`、`/srv` | 用户数据与站点数据 | 必备份；注意权限与属主 |
| `/var/lib/pacman/local` | 已安装包数据库 | 必备份；用于对照重装结果 |
| `/boot` | 内核、initramfs、引导器配置 | 必备份；迁移时还要重建引导 |
| 数据库数据 | PostgreSQL、MariaDB、SQLite 等 | 用应用层导出，不直接拷运行中的文件 |
| `/etc/systemd/system` | 自建 unit 与 drop-in | 随 `/etc` 备份；重装后重新 `enable` |
| 包清单 | `pacman -Qqe`、`pacman -Qqm` | 文本保存，重装时批量恢复 |

不必备份：`/usr`（由包重建）、`/var/cache/pacman/pkg`（可重新下载）、`/proc`、`/sys`、`/dev`、`/run`、`/tmp`。把伪文件系统打进归档既无用又容易报错。

运行中的数据库直接拷贝可能得到撕裂的文件：先停服务，或用 `pg_dumpall`、`mariadb-dump`、`sqlite3 库文件 ".backup 副本"` 一类的一致性导出。

## 文件级备份：tar 与 rsync

`tar` 适合一次性归档，保留权限、ACL 与扩展属性：

```bash
sudo tar --acls --xattrs --numeric-owner --one-file-system \
 -C / -cpf /run/media/backup/arch-$(date +%F).tar \
 etc home root srv var/lib/pacman/local
sudo tar --acls --xattrs --numeric-owner \
 -C /boot -cpf /run/media/backup/boot-$(date +%F).tar .
```

`--one-file-system` 阻止归档跨入其他挂载点，因此 `/boot`（通常是独立 ESP）要单独归档，否则会被静默跳过；`--numeric-owner` 保留数字 UID/GID，恢复时不依赖目标机的用户名；`-C /` 让归档内是相对路径，恢复时可选择解到 `/` 或临时目录。先列目录再恢复：

```bash
tar -tvf /run/media/backup/arch-2026-11-04.tar | head
tar -tf /run/media/backup/arch-2026-11-04.tar | wc -l
```

`rsync` 适合反复增量同步到另一块磁盘或远端：

```bash
sudo rsync -aHAX --numeric-ids --info=progress2 \
 --exclude=/proc --exclude=/sys --exclude=/dev --exclude=/run \
 --exclude=/tmp --exclude=/var/cache/pacman/pkg \
 / /run/media/backup/rootfs/
```

第一次不要加 `--delete`；确认目标目录正确、清单符合预期后，再把它用于「让目标与源一致」。`--delete` 删的是目标端多余文件，目标写错时损失不可逆。

需要加密、去重、多代快照时，用 restic 或 borg。它们把备份组织成可校验的仓库，支持 `check` 与按时间点恢复；学习成本高于 `tar`，但长期多机备份更可靠。具体命令以各项目文档为准。

## btrfs 快照

btrfs 的快照是子卷级别的写时复制，创建几乎瞬时、初始不占空间：

```bash
sudo btrfs subvolume snapshot -r / /.snapshots/root-$(date +%F-%H%M)
sudo btrfs subvolume list /
```

`-r` 创建只读快照，防止后续写入污染回退点。快照只覆盖同一个文件系统：`/boot` 若是独立 ESP（FAT32），不在快照范围内；`/home` 若是独立子卷，也要单独快照。用 snapper 可以管理保留策略与自动清理，但它同样不把数据送出本机。

回滚 btrfs 快照通常要改默认子卷或从 Live 环境替换子卷，属于破坏性操作，本章**未实测**；操作前先把当前子卷另存为快照，确认新默认子卷能启动后再清理旧数据。

## 虚拟机快照

改分区、换引导器、批量改配置之前，先关机或暂停再打快照。运行中打快照可能得到不一致的磁盘状态。回滚会把磁盘恢复到快照时刻，之后写入的数据全部丢失；从挂起或快照恢复后系统时间可能漂移，先 `sudo timedatectl set-ntp true` 对时。

虚拟机快照依然是「同一存储上的回退点」，宿主磁盘损坏时同样会丢；重要的数据仍要定期导出到宿主机之外的介质。

## 迁移：换机器或换盘

两条路径，优先选第一条：

**路径 A：重装 + 恢复配置（推荐，干净）**

1. 旧机记录清单：`pacman -Qqe > pkglist.txt`，`pacman -Qqm > foreign.txt`，并备份 `/etc`、`/home`、`/srv` 与数据库导出。
2. 新机按第 35–39 章装到能启动、能联网。
3. 用清单重装官方包：`sudo pacman -S --needed - < pkglist.txt`；外来包按第 49 章逐个重建，不要直接拷贝 `/usr`。
4. 恢复 `/etc` 时逐文件比对：新机已有的默认配置可能比旧机更适合新硬件；用 `diff` 看差异，再决定合并。
5. 重建用户与组、恢复 `/home` 属主、重新 `systemctl enable` 自建 unit。
6. 验证启动、网络、服务、数据四层，再切换生产流量。

**路径 B：整盘复制 + 重建引导（未实测）**

把新盘分区、格式化、挂载到 `/mnt`，用 `rsync -aHAX` 复制旧系统，再 `genfstab -U /mnt >> /mnt/etc/fstab`、`arch-chroot /mnt`、`mkinitcpio -P`，最后按第 36 章重装 GRUB 或 systemd-boot。新盘 UUID 变化会让旧 fstab 与引导 entry 失效，必须用新盘的 `blkid` 重新生成；克隆机还要重新生成 machine-id 与 SSH 主机密钥，避免两台机器身份相同。

## 失败模式

- **把快照当备份**：快照与源共享存储，磁盘故障时一起丢失；只防「改坏」，不防「机器没了」。
- **备份与源在同一块磁盘**：最常见的「以为有备份」；至少一份要离开本机。
- **归档里打进 `/proc`、`/sys`**：伪文件无法恢复，恢复时还会报错；用 `--one-file-system` 与排除项。
- **直接拷运行中的数据库**：得到撕裂副本，恢复后可能无法打开；用应用层导出或先停服务。
- **`rsync --delete` 目标写错**：目标端被清空或误删源数据；第一次必须 `--dry-run` 并核对路径。
- **恢复时整目录覆盖 `/etc`**：把新机适配的配置覆盖成旧机配置，网络、显示、引导随之失效；逐文件合并。
- **迁移漏掉外来包**：`pacman -Qqe` 只含官方包，AUR/本地包在 `-Qqm` 里，漏了就要重新找构建方式。
- **迁移漏掉引导与 initramfs**：复制完文件不等于能启动；新盘要重装引导器并重建 initramfs。
- **从未演练恢复**：备份文件存在、校验和正确，仍可能在恢复时因权限、路径或依赖失败；演练才算备份完成。

## 验证与回滚

备份的验证分三层：归档可读、内容完整、能恢复。前两层用列目录与计数，第三层必须真的解包一次。

```bash
mkdir -p /tmp/bk40/src/sub
echo v1 > /tmp/bk40/src/sub/a.txt
tar -C /tmp/bk40 -cpf /tmp/bk40/snap.tar src
mv /tmp/bk40/src /tmp/bk40/src.orig
tar -C /tmp/bk40 -xpf /tmp/bk40/snap.tar
diff -r /tmp/bk40/src /tmp/bk40/src.orig
```

`diff` 无输出表示恢复结果与原始树逐字节一致；有差异会列出文件与行。这个演练完全在 `/tmp`，不碰系统文件，可反复执行。真实恢复要先解到临时目录、核对后再覆盖；覆盖前给当前状态再打一次快照或备份，避免「用旧备份毁掉新数据」。

回滚策略按层级：虚拟机整机回滚用快照；btrfs 用只读快照与子卷切换（**未实测**）；文件级恢复保留至少两代，发现最新一代损坏时退回上一代；迁移失败时保留旧机原状直到新机验证通过。

## 取舍边界

- **快照 vs 备份**：快照换回退速度，备份换生存能力；重要数据两者都要。
- **`tar` vs `rsync` vs restic**：一次性归档用 `tar`；反复镜像用 `rsync`；需要加密、去重、多代保留用 restic/borg。
- **全量 vs 增量**：全量恢复简单但占空间；增量省空间但依赖链更长，任何一环损坏都可能影响后续。
- **本地 vs 异地 vs 云**：本地快但同灾；异地能防火灾水灾但成本高；云方便但受网络、账号与隐私约束。3-2-1 原则（3 份副本、2 种介质、1 份异地）是常见下限。
- **重装迁移 vs 整盘复制**：重装干净、可顺手升级硬件适配，但耗时；整盘复制快，却把旧问题一起带走，且 UUID、引导、密钥都要处理。
- **加密 vs 速度**：备份介质可能丢失，含隐私数据时应加密；加密会增加恢复步骤，密钥管理本身也要有备份。

## 小结

- 快照、备份、镜像解决不同问题；快照不是备份，必须有一份离开本机。
- 备份范围按「能否重新获得」划分：`/etc`、`/home`、`/srv`、包数据库、数据库导出、包清单。
- `tar` 用 `--one-file-system`、`--numeric-owner` 保留边界与属主；`rsync` 第一次不加 `--delete`。
- btrfs 快照是子卷级、同文件系统内；`/boot` 与独立子卷要单独处理。
- 迁移优先「重装 + 恢复配置」，整盘复制必须重建引导、处理 UUID 与机器身份。
- 没演练过的备份只能算希望；恢复演练在 `/tmp` 就能完成第一层验证。

## 练习

1. 列出你机器上「必须备份」的五个路径，并说明每一项为什么不能靠重装恢复（只读规划，不执行备份）。
2. 用 `tar -tf` 与 `tar -tvf` 检查一个已有归档，记录文件数与前三项权限；指出归档里是否混入了 `/proc`、`/sys` 一类路径。
3. 完成本章「验证与回滚」的 `/tmp` 演练，记录 `diff` 的退出码；再故意改一个字节，观察 `diff` 输出。
4. 写出你机器的 `pkglist.txt` 与 `foreign.txt`（`pacman -Qqe`、`pacman -Qqm` 重定向到 `/tmp`），统计行数并解释两者差别（只读）。
5. 在虚拟机中打一次快照，改坏一个无关配置后回滚，记录回滚后 `timedatectl` 的状态（需在虚拟机中完成）。
6. 设计一份迁移清单：从旧机到新机，按顺序写出「记录、备份、安装、恢复、重建引导、验证」六步，并标出哪一步最容易漏。
