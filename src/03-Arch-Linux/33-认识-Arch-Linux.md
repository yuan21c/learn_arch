# 第 33 章 认识 Arch Linux

篇一第 1 章已经讲过 Linux 的内核、发行版与桌面各自是什么，也对比过几种发行版的定位——本章不重复那些定义。这里只回答一个问题：**为什么这本书选 Arch 作为主线，它和别的发行版到底差在哪、代价是什么。** 建立正确的预期，比记住几条 pacman 命令更重要。

> 本章目标：说清 Arch 的五个关键词与「最小基础系统」的实际含义；分清官方仓库（core/extra/multilib）与 AUR 的本质差别；理解滚动更新把哪些责任转移给了你，以及为什么不能部分升级；知道哪些能力在普通会话里就能练、哪些必须进入 Live 环境或真机。
> 对应 Wiki：[Arch Linux](https://wiki.archlinux.org/title/Arch_Linux)、[Arch compared to other distributions](https://wiki.archlinux.org/title/Arch_compared_to_other_distributions)

## 定位：五个关键词

Arch 是一个独立开发的 x86-64 发行版，不基于 Debian、Fedora 或任何其他发行版。它的自我描述集中在五个词上：

| 关键词 | 含义 | 对你的实际影响 |
| --- | --- | --- |
| 滚动更新 | 没有大版本号，装一次后持续升级 | 系统状态取决于你最后一次升级 |
| KISS | Keep It Simple, Stupid，简单优先 | 不做过度设计与「智能」默认值 |
| 极简基础系统 | 默认只装能启动、能联网、能装包的最小集合 | 桌面、驱动、服务都要你自己选 |
| 用户中心 | 系统怎么配由用户决定 | 出了问题也要你自己定位 |
| Wiki 驱动 | 官方文档是最完整的一手资料 | 遇到问题的第一站是 Wiki，不是论坛 |

「用户中心」不是口号，它意味着**决策权与责任一起交给你**。Arch 不替你选桌面，不预装办公套件，也不强制你用 NetworkManager；它提供零件和文档，组装由你完成。

「极简」有多极简？看显式安装的包：

```bash
pacman -Qe | head -20 # 显式安装的包（不含依赖）
pacman -Qe | wc -l # 数量：通常远少于 Ubuntu 桌面版
```

这个数字就是你的系统「你自己选了多少东西」的度量。第 41 章会解释 `-Qe` 与依赖安装的区别。

## 两种软件来源：官方仓库与 AUR

| 名称 | 内容 | 维护者 | 形式 |
| --- | --- | --- | --- |
| core | 启动、联网、构建、系统管理必需的包 | Arch 开发者 | 预编译二进制 |
| extra | core 之外的大部分软件 | Arch 打包者 | 预编译二进制 |
| multilib | 在 x86-64 上运行 32 位程序所需的库与软件 | Arch 打包者 | 预编译二进制 |
| AUR | 用户提交的构建配方 | 社区用户，**非官方** | `PKGBUILD` 源码脚本 |

本质区别只有一条：**官方仓库给的是签过名的二进制包，AUR 给的是「怎么构建」的脚本**。前者 `pacman -S` 直接装；后者要你自己 `makepkg`，或者用 AUR 助手代劳。

```bash
pacman -Ss firefox # 搜官方仓库
pacman -Qm # 列出非官方来源的已安装包（AUR 或本地构建）
```

三条必须记住的判断：

- AUR 内容**未经官方审核**，安全性由提交者与使用者负责；装机前要读 `PKGBUILD`（第 48–49 章）。
- 先搜官方仓库，搜不到再去 AUR；能装官方包就不要走 AUR。
- AUR 不是「另一个软件源」，它没有二进制仓库、没有签名、没有 SLA。

## 滚动更新：一份责任转移清单

滚动发行不是「永远最新所以更好」。它把几件事从发行版转移到了你身上：

- **升级时机由你定**：没有「Arch 2026.10」这种大版本，系统状态取决于你最后一次升级。
- **升级是持续的小步**：每次 `pacman -Syu` 都可能是跨版本迁移，要读输出、看 News。
- **旧状态不受保护**：官方不保证任意旧状态都能平滑升到最新，长期不升级会积累需要人工介入的变更。
- **必须整系统升级**：不能只升一个包（原因见篇二第 29 章的 ABI 讨论与第 41 章的铁律）。

```bash
pacman -Qu # 只查看可升级的包，不实际升级
sudo pacman -Syu # 完整升级：先同步数据库，再升级全部
```

> **危险**：不要用 `pacman -Sy 包名` 只刷新数据库就装单个包。这会造成部分升级——新包依赖的新库版本已经进库，而旧包还连着旧库，结果是「装完就崩」。这是 Arch 最常见的事故来源，详见第 41 章。

升级前该做什么、`.pacnew` 怎么处理、需要人工干预的更新长什么样，第 52 章会给出固定流程。

## 适合谁：读者画像

这本书假设你**已经会 `ls`、`cp`、`mv`、`vim`，能在 Linux 里完成日常开发工作，但对系统本身（进程、权限、包、启动）只有模糊印象**。在这个前提下，Arch 有三个明确的收益：

- 你被迫理解每一层：装了桌面就要知道显示服务器，配了服务就要知道 unit。
- 系统里没有你不知道来路的东西——包是你选的，配置是你写的。
- Wiki 的质量极高，遇到问题的文档密度远超多数发行版。

也有三类人会被它拖累：希望装完就能用、不愿意碰配置文件的人；无法接受升级偶尔需要手动干预的人；把 AUR 当官方源、不读构建脚本的人。

三个常见误解值得先破除：

- 「Arch 就是难」——安装与配置的**决策量**大，但命令本身不复杂；难在判断，不在打字。
- 「滚动更新等于不稳定」——稳定性更多取决于是否完整升级、是否读 News、是否乱加第三方源。
- 「AUR 是官方仓库」——它是用户内容平台，官方明确不提供支持。

## 虚拟机与真机的分工

本书的主练习环境是虚拟机里的 Arch，因为打开成本最低、出错可回滚；真机负责虚拟机覆盖不到的部分。

两层的分工是：包管理、systemd、打包、排障在虚拟机里就能练熟；引导、内核、磁盘与加密需要真实固件与块设备，放在真机或支持嵌套虚拟化的环境。从 ISO 到首次启动的完整路径见第 35–39 章，具体故障处置见第 53 章。

## 失败模式

- **把 Arch 当成「装好就能用」的发行版**：`base` 只提供能启动、能联网、能装包的最小集合；桌面、驱动、打印、音频都要自己选。预期错位会导致「怎么什么都没有」的误判。
- **把 AUR 当官方仓库**：AUR 没有二进制包、没有官方签名、没有支持承诺；`pacman -Ss` 搜不到它，`pacman -Qm` 才会列出。装上之后升级失败，官方不承担修复责任。
- **只升级「出问题的那一个包」**：`pacman -Sy 包名` 制造部分升级。新库与旧使用者混在一起，症状常推迟到重启或下次登录才出现。
- **以为「滚动更新」等于「永远最新所以稳定」**：稳定性取决于是否完整升级、是否读 Arch News、是否加入来路不明的仓库，与「最新」本身无关。
- **把「极简」理解成「功能少」**：极简指默认不替你做选择，不是能力缺失；需要的能力仍然要自己装，选择权和维护责任一起给你。
- **在没有快照或备份的机器上折腾**：Arch 默认没有系统级回滚点，改坏引导或本地数据库后，恢复成本远高于固定版本发行版。

## 验证与回滚

以下命令只读，可在任意 Arch 会话执行：

```bash
pacman -Qe | wc -l # 显式安装的包数量
pacman -Q | wc -l # 全部已安装包数量
pacman -Qm # 外来包：AUR 或本地构建
pacman -Qu # 可升级包，只查询不改动
head -3 /etc/os-release
```

判读：`-Qe` 与 `-Q` 的差额是「为依赖而装」的部分；`-Qm` 非空说明系统里已有非官方来源，升级前必须先确认这些包由谁维护、能否重建。回滚按层级选择：虚拟机快照回整机；`/etc` 用 `.bak` 或 `.pacnew` 合并；单个包用缓存或 ALA 降级（第 43 章）。整系统没有「一键回到上一版」，这正是选择 Arch 时接受的成本。

## 取舍边界

- **Arch vs 固定版本发行版**：要较新软件、愿意读 News 并承担偶发手动干预，选 Arch；要「装上多年不动」，选 Debian stable 一类。
- **官方仓库 vs AUR**：官方仓库有的绝不走 AUR；AUR 只在前者没有、且你愿意读 `PKGBUILD` 时使用。
- **极简 vs 便利**：极简减少未知组件，也把组装成本转给你；不想维护桌面栈的人不该把「极简」当卖点。
- **学习价值 vs 时间成本**：Arch 适合作为理解 Linux 的主线，不适合作为唯一的生产环境；生产环境优先可预测性与回滚能力。

## 小结

- Arch 的五个关键词：滚动更新、KISS、极简、用户中心、Wiki 驱动；核心是决策权与责任一起给你。
- 官方仓库（core/extra/multilib）提供签名二进制包，AUR 只提供 `PKGBUILD`，不接受官方支持；`multilib` 默认在 `pacman.conf` 中被注释，需手动启用并随系统 `-Syu`。
- 滚动更新把升级时机与迁移责任交给用户；必须整系统升级，`pacman -Sy 包名` 是禁忌。
- 这本书的读者画像是「会基本命令、不懂系统」；Arch 的价值在于每一层都要你亲手理解。
- 虚拟机练用户空间与日常维护，真机补引导、分区、内核与硬件。

## 练习

1. 清点你的系统：`pacman -Qe | wc -l` 与 `pacman -Q | wc -l` 各是多少？两者差额说明什么？
2. 仓库与 AUR 对照：挑一个软件，分别在 `pacman -Ss <名字>` 与 AUR 网站搜一次，比较返回的形式（二进制包 vs `PKGBUILD`）。
3. 只读升级检查：运行 `pacman -Qu` 记录可升级数量；再运行 `pacman -Qm` 看有没有外来包，说明这两条命令各自回答什么问题。
4. 读一期 Arch News：找一期标注需要手动干预的新闻，用自己的话写出「升级前要做什么」。
5. 边界判断：列四件事——装 nginx、改 GRUB 引导项、给分区做 LUKS 加密、编译内核模块——分别说明该在普通会话、Live 环境还是真机上做，并给出理由。
