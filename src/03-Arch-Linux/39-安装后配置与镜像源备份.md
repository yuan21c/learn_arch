# 第 39 章 安装后配置与镜像源备份

能登录不等于可用。locale、时区、主机名决定系统行为是否符合预期；镜像源与 pacman 选项决定日常维护的体验；备份决定你能否在改坏之后回到上一步。三件事都应在动手改系统之前完成，而备份是你做任何大改之前的最后一道保险。

> 本章目标：完成 locale、时区、主机名与 hosts 配置；配置可靠的镜像源与 pacman 选项；掌握微码加载与基础工具补装；会用虚拟机快照与 `tar`/`rsync` 两种方式备份并完成一次恢复演练；知道下一步该学什么。
> 对应 Wiki：[General recommendations](https://wiki.archlinux.org/title/General_recommendations)｜[Mirrors](https://wiki.archlinux.org/title/Mirrors)｜[System maintenance](https://wiki.archlinux.org/title/System_maintenance)

> 本章命令默认用 `sudo` 执行；普通用户与 sudo 授权见第 38 章。

## 基础配置

先编辑 `/etc/locale.gen`，取消 `en_US.UTF-8 UTF-8` 与 `zh_CN.UTF-8 UTF-8` 两行的注释，再生成 locale：

```bash
sudo vim /etc/locale.gen
sudo locale-gen
echo "LANG=en_US.UTF-8" | sudo tee /etc/locale.conf
```

`locale-gen` 生成 locale 数据，`/etc/locale.conf` 决定登录后的语言环境。不要把 `LC_ALL` 写进 `locale.conf`：它会覆盖所有 `LC_*` 设置，导致排序和日期格式异常；中文 locale 还需要中文字体，留到桌面环境补（第 81 章）。

时区与硬件时钟：

```bash
sudo ln -sf /usr/share/zoneinfo/Asia/Shanghai /etc/localtime
sudo hwclock --systohc
```

`/etc/localtime` 是指向时区数据库的符号链接，`hwclock --systohc` 把当前系统时间写入硬件时钟，Arch 默认按 UTC 解释。虚拟机与真机都适用；多系统共用一块 RTC 时才需要额外考虑时钟语义，本书不展开。

主机名与本地解析：

```bash
sudo hostnamectl set-hostname arch-lab
```

同时检查 `/etc/hosts`，保证本机能解析自己的主机名：

```text
127.0.0.1 localhost
::1 localhost
127.0.1.1 arch-lab.localdomain arch-lab
```

主机名只影响标识与提示符，不影响网络连通；解析失败时先看这里，而不是先怀疑 DNS。

## 备份 mirrorlist

任何修改之前先留原文件：

```bash
sudo cp /etc/pacman.d/mirrorlist /etc/pacman.d/mirrorlist.bak
```

`mirrorlist` 是纯文本，一行一个 `Server = ...`。注释行以 `#` 开头，pacman 按从上到下的顺序尝试。

## 用 reflector 生成镜像列表

```bash
sudo reflector --country China --age 12 --protocol https --sort rate \
 --save /etc/pacman.d/mirrorlist
```

`--age 12` 只选 12 小时内同步过的镜像，`--protocol https` 限定协议，`--sort rate` 按测速结果排序，`--save` 覆盖写入。参数会随版本变化，以 `man reflector` 和 Wiki 为准；`--country` 可按网络环境调整。

更换镜像源后刷新数据库：

```bash
sudo pacman -Syy # 先强制刷新索引
sudo pacman -Syu # 再完整升级
```

换源后建议 `pacman -Syyu` 一次（强制重下索引并完成完整升级）；平时 `-Syu` 足够。

## pacman.conf 常用选项

```bash
sudo cp /etc/pacman.conf /etc/pacman.conf.bak
sudo vim /etc/pacman.conf
```

推荐打开：

```ini
Color
ILoveCandy
ParallelDownloads = 5
```

| 选项 | 作用 | 风险 |
| ------------------- | ---------------- | ---------------------------- |
| `Color` | 彩色输出 | 无 |
| `ILoveCandy` | 进度条变成吃豆人 | 无 |
| `ParallelDownloads` | 并行下载 | 过高可能被镜像限速 |
| `IgnorePkg` | 升级时跳过指定包 | 长期部分升级，不建议随意使用 |
| `CleanMethod` | 决定 `-Sc` 保留策略（默认 `KeepInstalled`：保留已安装包的缓存） | 改为 `KeepAll` 会让缓存只增不减 |
| `[multilib]` | 32 位库仓库，默认被注释 | 启用后必须随系统一起 `-Syu`，否则造成部分升级 |
| `SigLevel` | 包签名校验级别（默认 `Required DatabaseOptional`） | 调低会削弱完整性校验，不要为省事改成 `Never` |

`IgnorePkg` 的风险：被跳过的包不会随系统升级，依赖它的包可能因 ABI 变化而损坏。除非你清楚后果且有明确的短期理由，否则不要启用。

`CleanMethod` 默认值是 `KeepInstalled`，所以 `pacman -Sc` 不会删除已安装包的旧版本；要压缩缓存体积应改用 `paccache`（第 43 章）。

## 包缓存

pacman 下载的包保存在 `/var/cache/pacman/pkg/`。保留缓存的意义是升级出问题时可以从本地回滚，代价是占用磁盘。

```bash
# 每个包保留最近 3 个版本
sudo paccache -r

# 只预览，不删除
sudo paccache -d
```

`paccache` 来自 `pacman-contrib`，未安装时先 `sudo pacman -S pacman-contrib`。

> **危险**：`paccache -r` 会删除旧包。确认你不再需要某些历史版本后再执行，尤其是刚升级或准备回滚时。

## 微码与基础工具

按 CPU 厂商安装微码，二者只装其一：

```bash
sudo pacman -S intel-ucode # Intel
sudo pacman -S amd-ucode # AMD
```

微码必须在启动早期加载，两种方式**选一种**：默认 `HOOKS` 已含 `microcode`，此时直接 `sudo mkinitcpio -P` 重建即可，不要再往 entry 里加微码 `initrd`；只有走独立 initrd 方案时，systemd-boot 才需要把 `initrd /intel-ucode.img` 排在 `initramfs-linux.img` 之前，GRUB 的 `grub-mkconfig` 会自行检测并插入。虚拟机中微码效果有限，但配置方法必须掌握。

第 36 章的 pacstrap 示例不含编辑器。补装常用工具：

```bash
sudo pacman -S --needed vim man-db bash-completion
```

| 包 | 用途 |
| ----------------- | -------------------------- |
| `vim` | 编辑配置，可换成其他编辑器 |
| `man-db` | `man` 手册页 |
| `bash-completion` | 命令与路径补全 |

`base-devel`、`git`、`sudo`、`reflector`、`pacman-contrib` 已在第 37 章装入，这里不重复。构建 AUR 包需要完整工具链时，`base-devel` 已经覆盖（第 48 章）。

## 备份：快照与文件级备份

备份分两层：**快照**解决「整机回退」，**文件级备份**解决「配置与数据可迁移」。两者不能互相替代。

### 虚拟机快照

改系统之前先打快照，出问题直接回滚，这是学习环境里成本最低的安全网。VirtualBox 在「机器 → 快照」中创建；QEMU/libvirt 用 `virsh snapshot-create-as <域名> <快照名>`。快照要关机或至少暂停后再打，运行中打快照可能得到不一致的磁盘状态。

两条边界必须记住：

- **快照不是备份**：它与原磁盘在同一存储上，磁盘损坏或宿主目录被删时一起丢失。
- **回滚有代价**：回滚后磁盘状态回到快照时刻，这段时间的数据全部丢失；系统时间也可能与外部不一致，回滚后先 `timedatectl set-ntp true` 重新对时。

### 文件级备份

需要能把系统带到另一台机器、或长期保留时，用 `tar` 或 `rsync`。备份的关键目录是 `/etc`（全部配置）、`/home`、`/root`、`/var/lib/pacman/local`（已安装包数据库）与 `/boot`（内核与引导器）：

```bash
sudo mkdir -p /var/backups # Arch 默认不建这个目录，不先建会报 No such file or directory
sudo tar -C / -czf /var/backups/arch-$(date +%F).tar.gz \
 --exclude=proc --exclude=sys --exclude=dev --exclude=run \
 --exclude=var/cache/pacman/pkg \
 etc home root var/lib/pacman/local boot
```

`-C /` 让归档内路径相对于根目录，恢复时可以原样解到 `/`。排除项是虚拟文件系统与可重新下载的包缓存；不加排除会把 `/proc`、`/sys` 里的伪文件打进归档，既无用又可能报错。

`rsync` 适合反复增量同步到另一块磁盘或远端主机：

```bash
sudo rsync -aHAX --numeric-ids --one-file-system --delete \
 --exclude=/proc --exclude=/sys --exclude=/dev --exclude=/run \
 / /mnt/backup/rootfs/
# --one-file-system 会跳过独立分区的 /boot（尤其是单独挂载的 ESP）：必须单独备份
sudo rsync -aHAX --numeric-ids --delete /boot/ /mnt/backup/boot/
```

`-a` 保留权限与时间，`-H` 保留硬链接，`-A`/`-X` 保留 ACL 与扩展属性，`--numeric-ids` 避免 UID/GID 映射错位，`--one-file-system` 阻止跨文件系统扩散。**`--one-file-system` 的代价是漏掉所有独立挂载点**：`/boot`（内核与 initramfs）、单独的 ESP、外挂数据盘都不会进第一份备份——内核与引导器缺失时系统起不来，所以 `/boot` 要像上面那样单独同步一遍。`/mnt/backup` 必须是另一块磁盘上的挂载点——备份到同一块磁盘等于没有备份。

> **危险**：`--delete` 会删除目标端多余的文件。第一次运行前先用 `--dry-run` 看清单，确认目标目录是对的。

### 恢复演练

没验证过的备份等于没有备份。按下面顺序做一次文件级演练：

```bash
# 1. 造一个测试文件
echo "before-backup" | sudo tee /root/drill.txt

# 2. 只打包演练需要的路径，节省时间
sudo tar -C / -czf /tmp/drill.tar.gz root/drill.txt etc/fstab

# 3. 模拟事故：删掉测试文件
sudo rm /root/drill.txt

# 4. 先解到临时目录检查，不直接覆盖系统
sudo mkdir -p /tmp/drill-restore
sudo tar -C /tmp/drill-restore -xzf /tmp/drill.tar.gz
sudo cat /tmp/drill-restore/root/drill.txt
```

第 4 步读到 `before-backup`，说明归档可用。确认后再决定是否解回原位；把归档直接解到 `/` 会覆盖同名系统文件，操作前先打快照。

整机恢复的顺序是**先 `/boot`、再根文件系统、最后重建引导**：先把 `/boot`（或 `rsync` 出来的 `boot/`）解回原位，再解 `/etc`、`/home` 等，然后 `arch-chroot` 进去跑 `mkinitcpio -P`，最后重新安装或重建引导项（`grub-install`/`bootctl install` 等，见第 36、58 章）。少了 `/boot` 这一步，恢复完的系统会因为找不到内核而直接进固件界面。

虚拟机还可以做一次整机演练：打快照 → 故意改坏一个配置 → 回滚 → 验证系统恢复。这类演练在真机上成本很高，虚拟机里可以反复做。

## 备份策略

| 策略 | 做法 |
| ---------- | ------------------------------------------------- |
| 大改前快照 | 改 pacman 配置、批量删包、折腾 AUR、升级内核前先打 |
| 定期打包 | 每周或每次大改后做一次 `tar`/`rsync` |
| 保留多份 | 至少保留最近两次，避免备份本身损坏 |
| 异地保存 | 复制到另一块磁盘、另一台机器或云端 |
| 定期演练 | 真正解包一次并验证内容 |

## 失败模式

- **把 `LC_ALL` 写进 `/etc/locale.conf`**：它会覆盖所有 `LC_*`，造成排序、日期、数字格式异常；只写 `LANG`。
- **不备份就 `reflector --save`**：原镜像列表被覆盖，新列表不可用或排序异常时没有退路。
- **长期启用 `IgnorePkg`**：被跳过的包持续部分升级，最终以 ABI 冲突或启动失败暴露。
- **`tar` 直接解到 `/`**：会覆盖同名系统文件；先解到临时目录核对，再决定是否原位恢复。
- **`rsync --delete` 目标写错**：目标端多余文件被删除，甚至可能删到源；第一次必须 `--dry-run`。
- **备份放在同一块磁盘**：磁盘损坏时备份与源一起丢失；快照同理，它不是备份。
- **没演练过的备份**：文件存在不等于能恢复，恢复流程里的权限、路径、依赖都可能在真事故时才发现问题。

## 验证与回滚

```bash
locale # 当前 LANG 与 LC_* 是否一致
timedatectl # 时区与 NTP 同步状态
hostnamectl # 主机名
pacman-conf Color ParallelDownloads # 确认 pacman.conf 生效
tar -tzf /var/backups/arch-YYYY-MM-DD.tar.gz | head # 归档可读
```

归档先列目录再恢复；恢复演练解到 `/tmp/drill-restore`，用 `diff -r` 对照原文件。回滚：mirrorlist 与 `pacman.conf` 都有 `.bak`；快照回整机；单包回滚用缓存/ALA（第 43 章）；备份本身至少保留两份，避免备份损坏时无备份可用。文件级演练命令已在本章「恢复演练」一节给出，可完整复现。

## 取舍边界

- **reflector vs 手写 mirrorlist**：reflector 省事但依赖网络与测速；手写可控但需要定期维护。生产机可固定少量可信镜像。
- **快照 vs 文件级备份**：快照用于大改前回退，备份用于跨机器恢复；两者都要，不能替代。
- **`tar` vs `rsync`**：一次性归档用 `tar`；反复增量同步用 `rsync`；需要加密去重再加 restic/borg。
- **保留缓存 vs 磁盘空间**：缓存是降级来源，至少保留最近一个可用版本；空间紧张时先清已卸载包。
- **微码 hook vs 独立 initrd**：默认 hook 简单；需要精细控制加载顺序时才用独立 initrd，二选一，不要重复。

## 小结

- locale、时区、主机名、hosts 是安装后的最小配置集；`LC_ALL` 不要写进 `locale.conf`。
- 改 mirrorlist 前先备份，用 reflector 生成后 `pacman -Syyu`。
- `Color`、`ILoveCandy` 无风险，`IgnorePkg` 会制造部分升级。
- 包缓存在 `/var/cache/pacman/pkg`，可用 `paccache` 管理。
- 微码必须在 initramfs 之前加载，默认 `microcode` hook 与独立 initrd 二选一。
- 快照是整机回退点、不是备份；`tar`/`rsync` 做文件级备份，两者都要有，且必须演练。
- 内核、LUKS、btrfs、桌面、容器属于进阶内容，本书只给方向，以 Wiki 为准。

## 练习

1. 完成 locale、时区、主机名与 hosts 配置，用 `locale`、`timedatectl`、`hostnamectl` 验证（预期：LANG 生效、时区为 Asia/Shanghai、主机名与 hosts 一致）。
2. 备份 mirrorlist，用 reflector 生成新列表，比较前后镜像数量与排序（预期：数量变化且 `pacman -Syyu` 无报错）。
3. 打开 `Color` 和 `ParallelDownloads`，用 `pacman-conf` 验证生效（预期：输出包含两项配置值）。
4. 用 `du -sh /var/cache/pacman/pkg` 查看缓存大小，再用 `sudo paccache -d` 预览可清理的版本（预期：预览列出待删包，不实际删除）。
5. 验证微码已进 initramfs：`sudo lsinitcpio /boot/initramfs-linux.img | grep microcode`（预期：输出含 `kernel/x86/microcode/` 路径）。微码文件形如 `GenuineIntel.bin`，不含 `ucode` 字样；只想看 early 段时用 `lsinitcpio --early`（该选项行为随 mkinitcpio 版本变化，42.x 默认同时列 early 与 main）。再说明走独立 initrd 方案时，systemd-boot 的 entry 里微码 `initrd` 应写在哪一行、GRUB 又由谁插入。
6. 完成一次「打包 → 删除测试文件 → 解到临时目录 → 验证内容」的文件级恢复演练（预期：`/tmp/drill-restore/root/drill.txt` 内容为 `before-backup`）。
7. 做一次整机演练：打快照 → 改坏 `/etc/fstab` 中一处非关键注释 → 回滚 → 验证系统正常启动（**会回滚整机**：必须先有虚拟机快照或可丢弃环境；预期：回滚后系统可登录，`findmnt /` 正常）。
8. 写一份个人备份策略，说明触发条件、保存位置和保留份数。
