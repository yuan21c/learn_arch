# 第 3 章 文件与目录操作进阶

`ls`、`cp`、`mv` 大家都会敲，但「会敲」和「不出事故」之间隔着选项与概念：`cp` 少一个 `-r` 只是报错，`rm` 少一个判断就是灾难。本章把常用的文件操作命令讲到能预判行为的程度，并引入两个关键概念——文件类型与链接，它们是理解第五章文件系统的钥匙。

> 本章目标：熟练使用 `mkdir/touch/stat`、`cp/mv/rm` 的关键选项并预判其行为；会用 `file` 与 `ls -l` 判断真实文件类型；能解释硬链接与符号链接的差别；能用 `find` 按名称、类型、时间定位文件。
> 对应 Wiki：[Core utilities](https://wiki.archlinux.org/title/Core_utilities)

## 创建与元数据：mkdir、touch、stat

`mkdir` 建目录；`-p` 一次建出多层路径，且目标已存在时不报错，是脚本里的标配：

```bash
mkdir -p /tmp/lab/2026/10     # 连同父目录一起创建
mkdir /tmp/lab/2026/10         # 父目录已存在时重复执行会报错
```

`touch` 对不存在的文件就创建（内容为空），对已存在的文件则刷新修改时间——它不「碰」内容。文件名含空格时必须加引号：`touch "my file.txt"`。

`stat` 显示一个文件的全部元数据，比 `ls -l` 更完整。实跑一行（环境：WSL，/tmp 演练）：

```bash
stat -c '%n type=%F size=%s inode=%i links=%h' /tmp/lab/a.txt
# /tmp/lab/a.txt type=regular file size=6 inode=4444 links=1
```

记住四个字段：`size` 是字节数，`inode` 是文件在文件系统里的编号（本章链接一节马上要用），`links` 是硬链接计数，时间戳分三类——`atime` 访问、`mtime` 内容修改、`ctime` 状态变更（权限、属主、内容都会动它）。

## 复制与移动：cp 与 mv

| 选项 | 作用                   | 备注                                                  |
| ---- | ---------------------- | ----------------------------------------------------- |
| `-r` | 递归复制目录及其内容   | 复制目录不加它必报错                                  |
| `-a` | 归档模式               | 等价 `-dR --preserve=all`：保留权限、属主、时间、链接 |
| `-i` | 覆盖前询问             | 交互使用建议常开                                      |
| `-n` | 已存在则不覆盖         | 脚本里比 `-i` 可靠（`-i` 会等输入）                   |
| `-p` | 保留权限、属主与时间戳 | 备份场景常用                                          |
| `-v` | 显示每一步做了什么     | 排查用                                                |

`mv` 没有 `-r`，因为移动整个目录不需要递归。同文件系统内 `mv` 只是改目录项，瞬间完成；跨文件系统（比如拷到 `/mnt` 下的 Windows 盘）实际是先复制再删除。两者的默认行为都是**静默覆盖已存在的同名文件**，交互使用先加 `-i`，脚本里用 `-n`：

```bash
cp -r /tmp/lab/dirA /tmp/lab/dirB     # 实跑：目录被完整复制
mv /tmp/lab/dirB /tmp/lab/dirC        # 实跑：重命名
```

## 删除：rm

`rm` 只删文件；删目录要 `-r`（recursive）。三个常用选项的组合决定它有多「冲动」：

- `-i`：每个目标都先询问；`-f`：强制，不询问、不存在也不报错。
- 目录树删除的常规写法是 `rm -r 目标`，拿不准就 `rm -ri` 逐个确认。
- CLI 删除**不进回收站**，没有 Ctrl-Z 可撤。

> **危险**：`rm -rf` 不会二次确认。经典事故是变量为空时 `rm -rf "$DIR/"` 展开成删根，以及把路径敲错一位（`/var/log` 写成 `/var/lg` 无妨，写成 `/var/` 就没了）。执行前先 `ls 目标路径` 核对；一切练习只在 `/tmp` 演练目录里做。

## 文件类型与 file

扩展名只是命名习惯，内核并不看它：`notes.txt` 和 `notes.dat` 对系统没区别，`.sh` 不会因此可执行。真正决定「怎么处理这个文件」的是类型，判断靠两处：

- `ls -l` 的首字符：`-` 普通文件、`d` 目录、`l` 符号链接、`c` 字符设备、`b` 块设备、`s` 套接字、`p` 管道。
- `file` 命令读文件开头的魔数（magic bytes）给出结论，实跑结果（环境：WSL）：

```text
$ file note.txt link.txt /dev/null
note.txt: ASCII text
link.txt: symbolic link to a.txt
/dev/null: character special (1/3)
```

`file` 报告符号链接时不会跟过去，报普通文件内容时会读数据。配合 `ls -ld /bin` 输出的 `lrwxrwxrwx ... /bin -> usr/bin`，就能确认 `/bin` 本身是链接、指向的目录里才是程序。

## 链接：硬链接与符号链接

文件系统里，目录项（文件名）只是指向 inode 的标签，数据与元数据都挂在 inode 上。链接就是给 inode 增加标签的方式，两种链接的区别是「标签指向什么」：

|            | 硬链接 `ln 目标 名字`  | 符号链接 `ln -s 目标 名字`         |
| ---------- | ---------------------- | ---------------------------------- |
| 本质       | 与原名指向同一 inode   | 独立的小文件，内容是目标路径字符串 |
| inode      | 相同（`ls -i` 可见）   | 自己的编号                         |
| 链接数     | 每加一个 +1            | 恒为 1                             |
| 跨文件系统 | 不允许                 | 允许                               |
| 指向目录   | 普通情况下不允许       | 允许                               |
| 目标消失后 | 数据仍可经其它名字访问 | 变成断链，访问报错                 |

实跑验证（环境：WSL，/tmp 演练）——建软链后 `stat` 显示它 `type=symbolic link`、`size=5`（恰好是 `a.txt` 的长度）；删掉原文件后，硬链接仍能 `cat` 出全部内容，软链接则悬空：

```bash
ln a.txt hard.txt          # 硬链接：ls -i 与 a.txt 同号，links=2
ln -s a.txt soft.txt       # 软链接：ls -l 显示 soft.txt -> a.txt
rm a.txt
cat hard.txt               # 数据仍在
cat soft.txt               # 报错：No such file or directory（断链）
```

日常里软链接是快捷方式与版本切换（`libfoo.so` → `libfoo.so.1.2`），硬链接是「同一份数据多个名字」（备份工具用它做增量引用）。符号链接可以指向目录，这让「把一个目录挂在另一个位置」成为可能——也是第五章挂载概念的近亲。

## find 定位

`find` 按表达式遍历目录树，语法是 `find 起始路径 条件 动作`，条件之间默认「与」关系：

| 条件                              | 含义                                          |
| --------------------------------- | --------------------------------------------- |
| `-name '*.txt'`                   | 名称匹配（区分大小写，通配符加引号交给 find） |
| `-iname '*.txt'`                  | 名称匹配，忽略大小写                          |
| `-type f` / `-type d` / `-type l` | 普通文件 / 目录 / 符号链接                    |
| `-mtime -7`                       | 7 天内修改过（`+7` 则是超过 7 天）            |
| `-size +10M`                      | 大小超过 10 MB                                |
| `-maxdepth 2`                     | 最多向下两层（放在其它条件前面）              |

动作默认 `-print`（逐行输出）；`-exec 命令 {} \;` 对每个结果执行命令，`{}` 是结果占位符，`\;` 是结束符。实跑（环境：WSL，/tmp 演练）：

```bash
find /tmp/lab -name '*.txt' -exec wc -l {} \;   # 对每个匹配文件统计行数
find /tmp/lab -maxdepth 1 -type f               # 只列第一层的普通文件
```

`*.txt` 必须加引号：不加的话 shell 会先在**当前目录**展开它，把碰巧匹配的文件名塞给 find，行为完全走样。

## 小结

- `mkdir -p`、`touch`、`stat` 覆盖创建与元数据；`stat` 的 `inode` 与 `links` 是理解链接的入口。
- `cp` 复制目录必须 `-r`，`cp -a` 归档保真；`mv` 跨设备时是复制加删除；两者默认静默覆盖。
- `rm -rf` 无确认、无回收站；危险命令的演练场只能是 `/tmp`。
- 扩展名不决定类型；`ls -l` 首字符看类别，`file` 读魔数看内容。
- 硬链接共享 inode、链接数相加；符号链接是存路径的独立文件，会断链。
- `find` 用「路径 + 条件 + 动作」定位文件，glob 加引号交给 find 自己匹配。

## 练习

1. 布置演练场并读元数据（环境：WSL）：

   ```bash
   mkdir -p /tmp/lab3/sub && cd /tmp/lab3
   touch sub/a.txt && echo hi > sub/a.txt
   stat -c '%n type=%F size=%s inode=%i links=%h' sub/a.txt
   ```

2. 在 `/tmp/lab3` 里依次执行 `ln sub/a.txt sub/hard.txt`、`ln -s a.txt sub/soft.txt`，用 `ls -li sub` 对比 inode 与链接数；删除 `sub/a.txt` 后分别 `cat` 两个链接并解释结果（环境：WSL）。
3. 用 `ls -ld /bin` 与 `file /bin/ls` 判断 `/bin` 与 `ls` 各是什么类型，再用 `ls -l` 首字符规则复核（环境：WSL）。
4. 用 `cp -r`、`mv -n` 在 `/tmp/lab3` 内复制并改名一个目录；故意重名执行一次 `mv`，观察默认覆盖行为（环境：WSL）。
5. 用 `find /tmp/lab3 -type f -name '*.txt'` 与 `-maxdepth` 组合，找出两层以内所有文本文件（环境：WSL）。
